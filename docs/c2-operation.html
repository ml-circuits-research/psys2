C2 operation

Status: implemented planned (vision only) Pipeline, loaders and episode trace implemented; snapshot pinning, overlays and streaming are vision only.

Specs: spec 06 Dialog, server, webchat

Vision: vision §1, vision §7

Purpose

C2 is operation: users talk to the assistant and get answers. It runs accepted formalizers, interpreters and action connectors. It has no LLM endpoint and no access to the coding agent, and it cannot change accepted worlds; it writes episodes and session state only (vision §1). Answers distinguish a supported result, alternative readings, a contradiction, missing evidence, an unsupported operation and budget exhaustion, so "I do not know" never wrongly implies that missing data is the only cause.

The dialog pipeline (spec 06)

const engine = await createEngine({ loader })   // loads all worlds via the loader
const session = engine.createSession({ language: 'auto' })
const reply = await session.send(text)
// reply = { text, lang, translation, segments, wires, answers, statuses, trace }
  1. Language. Detect; if not English, translate (spec 05; Translation). The original is kept as the source record referenced by core.source.
  2. Formalize with the rule formalizer over all loaded worlds (Rule formalizer). Emitted wires go to session memory.
  3. Solve. Every core.question and core.request is resolved by the interpreter (Interpreter).
  4. Render each result with world templates; statements get acknowledgements; unparsed sentences get I did not understand "<sentence>". plus up to two example sentences from the closest world (router score).
  5. Back-translate the reply if the user wrote in another language.
  6. Return the reply and a trace (segments, router scores, matched patterns, wires, operations called, statuses), which is the episode record (vision §7).

engine.worlds() lists loaded worlds; session.memory() returns the session wires as SOP Lang.

Example

> Tom has 5 apples. Ana gives him 3 apples. How many apples does Tom have?
Tom has 8 apples.
> How many apples does Mia have?
I don't know yet. How many are there?

Loaders

  • Node: src/loaders/fs-loader.mjs reads worlds/*/ and imports ops.mjs with dynamic import().
  • Browser: src/loaders/bundle-loader.mjs reads a bundle built by scripts/build-webchat.mjs (one worlds/<id>/bundle.json per world with its file texts, loaded when the world is needed; worlds/index.json is the small routing index with the word index, spec 06 "Lazy loading") and imports each world's ops.mjs from its copied path.

The same modules run in both because browser-safe modules take a loader rather than importing node:* (AGENTS.md). See the webchat demo.

Target C2 (vision §7)

planned (vision only)

  • A request pins a deployment snapshot at start and never changes versions midway; sessions remain pinned or migrate by a tested conversion.
  • Working memory is a temporary overlay over pinned imports; query caching includes complete context and snapshot hashes; budgets limit candidates, branches, recursion, retrieved facts and time.
  • Longer reports collect typed findings with evidence, applicability, severity and unresolved questions.
  • Each episode records input and access policy, source hashes, selected and rejected worlds, encoder versions, candidate circuits and scores, context branches, operations, results, timing, resource use and later feedback, subject to retention policy.
  • Streaming sessions, temporary document overlays and batch reports (milestone 5): file analysis never modifies accepted worlds without a separate learning job.

SituationBehaviour
Language not recognized or negation/question word untranslatableReported; no translation without the meaning-bearing word (spec 05)
Sentence not formalizedI did not understand ... with up to two examples
Ambiguity between worldsReported, not chosen silently
Operation error or budgetStatus error or budget shown, never a false answer
