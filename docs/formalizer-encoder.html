Encoder formalizer

Status: planned (vision only)

Specs: none (vision only)

Vision: vision §5, vision §6, vision §17

Purpose

The encoder strategy is the vision's primary formalizer: a pinned ModernBERT-base backbone with a per-world LoRA adapter and task heads that turn text into candidate circuits. It is not implemented; this page records the target design so the rule strategy and fixtures can be built to feed and check it. Statements here are targets, not claims of achieved performance.

Backbone and profile

The initial backbone is ModernBERT-base (about 149 million parameters, advertised context 8192 tokens; vision reference [1]). The checkpoint is not already a SOP Lang formalizer: PSys2 must train task heads and adapters and measure them. The initial language profile is English; each extra language needs its own encoder profile, data and evaluation. Within an accepted deployment snapshot the backbone is frozen. A world adapter is never loaded against a different backbone or tokenizer.

Pipeline, step by step

  1. Type and mention detection. Candidate mentions scored against type descriptions from candidate legends; alternatives, scores and spans retained; several instances of one type in a sentence must be distinguished; multi-token mentions supported.
  2. Key extraction. A key question conditioned on the particular mention and its context predicts a span, several spans when permitted, or no answer. This is how "A has mass 2 kg and B has mass 3 kg" binds each mass to the right body.
  3. Reference resolution. A scorer links mentions to entities in the segment, session and permitted knowledge scope. Retrieval narrows candidates and is not evidence of identity; the model can abstain or keep several hypotheses.
  4. Relations and scope. Structured heads predict conditions, negation, modality, attribution, conjunction, alternatives and temporal relations; deterministic assembly builds the circuit and checks scope consistency. A valid circuit with lost scope is still a formalization failure.
  5. Question mapping. User questions become typed query plans (entity selection, requested keys, aggregation, comparison, existence, constraints, explanation, action request); one question can yield several answer wires.

All normalized facts link to source spans or an explicit deterministic derivation. No decoder LLM fills missing values; unresolved scope, identity or arguments produce a structured uncertainty or learning request. The formalizer returns candidates (spans, typed mentions, key assignments, references, scope graph, task scores, rejected hypotheses, model hashes), not an unqualified circuit.

Per-world data and training (vision §6)

  • Training record: stable example id, source or generator lineage, source-group id, text, language, active legend versions, expected mentions and keys, reference links, scope graph, expected query or outcome, negative labels, validation results, split.
  • Label status: generator-backed, mechanically checked, independently corroborated, teacher-only. Teacher-only cannot be upgraded by majority vote. The rule strategy adds rule-derived (ADR-001).
  • Splits: sources and problem families are partitioned before annotation expansion; paraphrases, numeric variants and generated siblings stay with their parent. Protected acceptance sets belong to the evaluation service; the agent receives only aggregate diagnostics, and disclosed cases are retired and replaced.
  • Checks: span boundaries, typing, reference integrity, scope, units, contradictions, answerability, applicability of operations. Round-trip stability is a diagnostic, not a certificate; agent code plus agent labels can be circular.
  • Training: LoRA adapters plus task heads on the local GPU. Rank, layers, precision and batch size are benchmarked on development data; adapter size is measured, not promised. Command, code revision, seeds, data hashes, hardware, framework versions and artifact hashes are recorded.
  • Jobs: GPU memory and time limits, checkpoints, cancellation, resumability; separate quotas for training and inference; an out-of-memory error reduces batch or sequence budget by a declared policy and is logged; long examples cannot be silently dropped.
  • Retraining mixes new examples with pinned replay data; development performance selects candidates, protected evaluation controls release; quantized exports are evaluated separately; shared-backbone updates are coordinated releases that re-evaluate all dependent adapters. Licences and training-use restrictions are kept in manifests.

Relation to the rule strategy

Both strategies obey the same output contract. A world may declare both; the encoder is preferred where accepted (ADR-001). Rule-formalized output can be exported as rule-derived training records, and rule patterns provide a check on encoder output (Rule formalizer). Rule patterns do not count as C1 evidence.

Targets

Role-conditioned extraction F1 at least 90%, scope and reference accuracy at least 95% each on the world's protected set, at least 95% structurally valid first-pass circuits (see Evaluation).

Failure modes and contingencies

Capacity or language coverage too low, key-query passes too expensive, unreliable nested scope: see the contingency table in Roadmap. Generative LLM formalization and an LLM fallback in C2 are excluded; reintroducing them needs a new architectural decision.
