Rule formalizer

Status: implemented

Specs: spec 03 Rule formalizer, ADR-001

Vision: vision §5, vision §6, vision §7

Purpose

A light formalization strategy built from patterns and heuristics, declared per world with formalization=rules. It runs on any CPU and in the browser, needs no model, and is used to bootstrap worlds quickly, to generate and check training data for the encoder strategy, for tests, and wherever speed matters more than coverage of linguistic nuance. It is deterministic and never invents values: every slot value is a span of the (normalized) input or an atom fixed by the pattern. Input is English; other languages are translated first (Translation).

Vision and specs differ

Vision v1 §5 makes encoder-based formalization the only formalizer. ADR-001 (accepted 2026-11-07) amends vision §1, §5 and §16 by adding this rule strategy beside the encoder, under the same output contract: wires with source spans, typed against legends, validated before use, no generated values. Its coverage is limited by its patterns; unparsed input is reported, never guessed.

Interface

formalize(text, { worlds, session, source }) -> {
  segments: [{ text, span:[start,end], isQuestion, worlds:[{id, score}],
               match: { patternId, worldId, slots } | null,
               wires: Wire[], unparsed: boolean }],
  wires: Wire[]          // all emitted wires, in order
}

Implementation: src/formalizer/rules/ (browser-safe). CLI: node src/cli.mjs formalize "<text>".

Step 1: normalization and segmentation

  1. Split into sentences on . ! ? (not inside numbers like 3.5), keeping offsets; ? marks a question. A sentence starting with how what who where when which why is are does do can did is also a question.
  2. Tokenize into words, numbers and 's, keeping original casing (names) and a lowercase form for matching.
  3. Expand contractions: doesn't to does not, I'm to I am, what's to what is, can't to can not.
  4. Number words to digits: zero to twenty, tens, hundred, thousand, combinations (twenty-one, one hundred and five), half to 0.5, a dozen to 12.
  5. Drop fillers anywhere (please ok okay well um, sentence-initial so) and sentence-initial and, then, after that.
InputAfter normalization
Tom doesn't have two apples.Tom does not have 2 apples
Well, please give me a dozen pears!give me 12 pears (fillers dropped)
And then Ana buys three more.Ana buys 3 more
It costs 3.5 dollars.one sentence: the dot in 3.5 is not a boundary

Step 2: patterns

@pat.arith.has core.pattern
    match="{who:agent} [has|have|had|got] {n:number} {item:noun}"
    emit="@{_} kids.arith.holding owner={who} count={n} item={item}"
    kind=statement
    priority=10
    example="Tom has 5 apples."

Match syntax

Token level, anchored to the whole sentence without its final punctuation.

ElementMeaning
wordliteral token (case-insensitive)
[a|b|c]exactly one alternative; may be multi-word with _ ([how_many|how_much])
[a|b]?optional alternative
{name:class}capture one item of the class
{name:class?}optional capture
...skip 0 to 4 arbitrary tokens (lazy)

Slot classes

ClassAcceptsCaptured value
numberone numeric tokenatom (5, 2.5, -3)
wordany single tokenatom (lowercase)
words1 to 6 tokens, lazystring (original text)
nouna single word or a multi-word lexicon nounatom: singular lemma, _ joins multi-word (ice_cream)
<lexicon id> e.g. lex.kids.animals.namesa word or multi-word entry whose singular lemma is in that lexiconatom: the lexicon entry
agentcapitalized token not a known lowercase word, a name from any class=name lexicon, or a pronounreference to an agent entity ($e.tom)
unittoken in any class=unit lexicon or the quantity unit tableatom

Singular lemma: irregular plurals from plural= entries first; then ies to y, ves to f, (ch|sh|x|ss)es drop es, s dropped (not after ss). The lemma is used for lexicon matching and in emitted atoms.

Optional elements and lazy skips use a backtracking matcher; for one pattern the first full match in left-to-right, prefer-consume order wins.

Emit templates

  • {slot} gives the slot value (atom, or $id for agents); inside a string ("{slot}") the original text, JSON-escaped.
  • {_}, {_1}, {_2} are fresh wire ids unique per session (w17, w18).
  • An optional slot that was not captured removes the whole key={slot} entry.

The engine adds to every emitted wire: core.via=$<patternId>, core.source="<source>#<start>-<end>", core.seq=<n> (strictly increasing per session; orders events) and core.in=$<worldId>.

Pattern kinds

KindEmits
statementfacts or events into session memory
questiona core.question (Interpreter)
requesta core.request (action or task)
chatconversational acts (greetings, thanks): a core.request action=<op> handled by a world operation

Pattern examples

The first is from the spec; the others are illustrative patterns in the same syntax, showing each feature (they are not claimed to exist in a shipped world).

Statement with optional capture

@pat.arith.has.opt core.pattern
    match="{who:agent} [has|have|had|got] {n:number} {item:noun}"
    emit="@{_} kids.arith.holding owner={who} count={n} item={item}"
    kind=statement
    priority=10

Tom has 5 apples. -> one holding wire.

Event with two agents and a pronoun

@pat.arith.gives core.pattern
    match="{giver:agent} [gives|gave] {taker:agent} {n:number} {item:noun}"
    emit="@{_} kids.arith.giving from={giver} to={taker} count={n} item={item}"
    kind=statement
    priority=10

Ana gives him 3 apples. -> him resolves to the most recent male-or-unknown agent.

Optional alternative

@pat.arith.buys core.pattern
    match="{who:agent} [buys|bought] {n:number} {item:noun} [for]? {price:number?}"
    emit="@{_} kids.arith.buying buyer={who} count={n} item={item} price={price}"
    kind=statement
    priority=8

Ann buys 2 pears. -> the price entry is removed from the wire because that slot was not captured.

Question with multi-word alternative

@pat.arith.howmany core.pattern
    match="[how_many|how_much] {item:noun} [does|do] {who:agent} have"
    emit="@{_} core.question type=kids.arith.holding seek=count where.owner={who} where.item={item}"
    kind=question
    priority=10

How many apples does Tom have? -> core.question; the noun slot lemmatizes apples to apple.

Lazy skip

@pat.arith.left core.pattern
    match="how_many {item:noun} ... [left|remain]"
    emit="@{_} core.question type=kids.arith.holding seek=count where.item={item}"
    kind=question
    priority=5

How many apples are left? -> "are" is consumed by the 0 to 4 token skip. Fewer skips rank higher.

Free text capture

@pat.misc.note core.pattern
    match="remember that {text:words}"
    emit="@{_} core.note text={text}"
    kind=statement
    priority=1

Remember that Tom likes red. -> text keeps the original string, JSON-escaped.

Chat act

@pat.chat.thanks core.pattern
    match="[thanks|thank_you]"
    emit="@{_} core.request action=chat.thanks"
    kind=chat
    priority=1

Thanks! -> a request resolved by a world operation with semantics=action.

Worked example

Input (one message):

Tom has 5 apples. Ana gives him 3 apples. How many apples does Tom have?

Segments: three sentences, the last a question. Entities: @e.tom core.agent name="Tom" gender=m and @e.ana ... gender=f are created on first mention. Illustrative emitted wires (ids and exact keys depend on the world):

@w1 kids.arith.holding owner=$e.tom count=5 item=apple
    core.via=$pat.arith.has core.source="msg1#0-16" core.seq=1 core.in=$world.kids.arith
@w2 kids.arith.giving from=$e.ana to=$e.tom count=3 item=apple
    core.via=$pat.arith.gives core.source="msg1#17-40" core.seq=2 core.in=$world.kids.arith
@w3 core.question type=kids.arith.holding seek=count where.owner=$e.tom where.item=apple
    core.via=$pat.arith.howmany core.source="msg1#41-71" core.seq=3 core.in=$world.kids.arith

The interpreter then answers 8 (Interpreter).

Step 3: entities and reference

  • An agent slot creates (first mention) or reuses @e.<lowercase name> core.agent name="Tom" in session memory, with gender=m|f if a name lexicon says so.
  • he him his go to the most recent agent with gender m or unknown; she her to f or unknown; they them to the most recent agent; I me my to e.user; you to e.assistant.
  • An unresolvable pronoun makes the pattern fail for that sentence. No guessing.
  • Mentions are tracked in order of appearance; questions also update recency.

Step 4: choosing a reading

  1. Try every pattern of every loaded world.
  2. Rank full matches by priority (higher first), then number of literal tokens matched, then fewer .../words captures, then router score of the world.
  3. If nothing matches the whole sentence, split into clauses at , and then but (one level) and match each; a failing clause is reported as unparsed.
  4. Equal-rank matches from different worlds that emit different wires are kept as alternatives; the dialog layer reports the ambiguity instead of choosing silently (vision §7).

Training-data export

Because each wire carries core.source offsets and slot spans, the strategy can export encoder training records (text, mentions, key spans, references, label status rule-derived) as JSONL with scripts/export-training.mjs for training/. ADR-001 makes rule-derived distinct from generator-backed, mechanically checked, independently corroborated and teacher-only (vision §6). See Encoder formalizer.

Phrase macros, shapes and shared phrasing

Phrasing that many patterns share is written once. New phrasing goes into lang.common or a shape, never inline in a pattern (AGENTS.md, ADR-007).

Macros (core.phrase)

A core.phrase wire in lexicon.sop (phrase.<id>, alternatives alt=..., _ joins words) names a list of literal alternatives. In a match string [$lang.lead.polite] is the group of that phrase, [$id]? the optional form and [$id|extra_word] a union with literals. Expansion happens in compilePattern into an ordinary alternative group, so the matcher, core.pattern and the emit templates are unchanged; alternatives are tried in phrase order (longest first). matchTokens counts macro words in literals and also reports frameLiterals; frame=false marks content-word phrases that never count as frame. A pattern may only use phrases of its own world or of a world it imports; checkPattern rejects unknown or non-imported ids. scripts/migrate-macros.mjs <world> [--write] rewrites a world's patterns mechanically.

lang.common and ctx.lang

worlds/lang.common (status=fixture, no patterns) holds the shared phrase groups (lang.lead.*, lang.tail.filler, lang.shape.*, lang.yes, lang.no, lang.unsure, lang.cancel, lang.filler, lang.connective, degree, size and position groups) and the shared lexicons (lex.lang.colour, ordinal, size, degree, direction, position, unit). It is imported through kids.common, so every world sees it. Lexicons gain extends= and exclude=, resolved at load. The interpreter exposes the same vocabulary to world code as ctx.lang (yesNo, unsure, cancel, stripLead, stripFiller, stripConnective, ordinal, colour, size, position, degree, splitAdverb), so worlds do not keep their own yes/no or filler regexes (spec 04).

Shapes (core.shape) and expand-patterns

A core.shape wire in patterns.sop declares one operation; the loader expands it into the ordinary patterns of its request forms (pat.<id>.<form>, with form and shape fields), after macros and lexicon extends= are resolved. Generated patterns go through checkPattern; problems are world load errors. node scripts/expand-patterns.mjs <world> [--shape <id>] [--stats] prints exactly what is generated, as SOP. The short form has priority minus 2 and is dropped at routing tier 5.

Shape keys (spec 03 section 2b):

Pattern routing keys

Optional keys on core.pattern read by the router: tabOnly=true (considered only while its world owns the active tab), tabFollow=true (a bare coordinate such as "b1": dropped from tier 5 when no literal word accompanies it, so only the active tab, game or a recent world reads it), tabPriority=<n>, yieldsTo=<world>, and needsState=<path> (the pattern counts only while that path of its world's state is non-empty, or its world owns the active tab; for example a bare "next" needs playing or an open search).

Canonical examples (RD6)

Examples double as training data, so many are fragments or typos. What users are shown (help, "what can I say here?", "did you mean") is only the canonical subset: canonical="Some sentence." lines on a pattern or shape. scripts/mark-canonical.mjs picks up to two clean sentences per operation (--strip, then --write); tests/canonical-examples.test.mjs checks the quality gate and that each canonical sentence is understood by its own world.
