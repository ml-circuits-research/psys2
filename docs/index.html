Overview

Status: implemented planned (vision only)

Specs: ADR-001

Vision: vision §1

PSys2 (PragmaticSystem2) is an assistant that builds, uses and improves explicit computational worlds. Natural language is formalized into SOP Lang wires; deterministic interpreters answer questions and execute authorized tasks. No generative language model is used in operation (C2): LLMs are used only by coding agents while authoring and improving worlds (C1, C3). The vision targets autonomous construction of a library of at least 100 worlds on a machine with a local GPU; CPU execution is a supported, separately measured profile.

Status: implemented planned (vision only) The repository currently implements the C2 side with hand-built fixture worlds, a rule-based formalizer and a browser demo; the encoder, C1, C3, release machinery and sandbox are vision only. See the table below and ADR-001.

The five core terms

TermMeaning
WireOne typed, identified record in SOP Lang: @id type key=value .... A circuit is a set of wires linked by $id references (SOP Lang v1)
LegendA versioned vocabulary of types and keys, with an English question per key (Legends)
WorldA versioned package: legend, knowledge, operations, templates, tests and (in the vision) model, training data and history (Worlds)
OperationA declared, typed computation or action with explicit inputs and outputs, implemented by a deterministic strategy (Interpreter)
ContextThe scope in which a fact holds: session or document, world release, assumptions, time (Context and consistency)

Others you will meet: formalizer (text to wires), router (text to candidate worlds), episode (the trace of one request), release and snapshot (immutable, hash-identified), journal (append-only history).

The three modes

ModeInputs and permitted workPublication authorityPage
C1 constructionSource documents, world requests, budgets; the agent designs legends, code, training data, tests; local GPU fine-tuningCandidate release only; independent gate publishesC1 construction
C2 operationUser messages, session documents, explicit capabilities; formalization, reasoning, reporting, authorized executionNone: no change to accepted worlds; writes episodes and session stateC2 operation

Vision versus specs

The vision is the target architecture; the specs are the contracts of what is being implemented now. ADR-001 amends the vision by adding rule-based formalization and hand-built fixture worlds. Other differences are marked on the relevant pages in highlighted boxes labelled "Vision and specs differ". Language rule: everything is English; other languages are translated at the boundary (Translation).
