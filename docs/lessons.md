## The learning curve and the frozen held-out set (worker-log "Learning curve and frozen held-out set")
- **Rule (AGENTS-style, for everyone):** a real message (a new owner export, a new ledger row that came from a person) is frozen into `training/eval/heldout-real/` AT ARRIVAL with `node scripts/freeze-heldout.mjs --add <file> --source <name>` (arrival date and hash recorded, append-only), before anyone reads it to fix something. After that it is measured only: never copied into a world, pattern, lexicon, test, corpus case, training file or task, and no rule is written or changed to make one of its messages work. `--check` reports a leak (a frozen text found in the repository) and exits 3; a message that was used anyway is moved to `used.jsonl` with `--retire` and stops counting. This is the one set where the data principle "overlap is acceptable" does NOT apply: the whole point of the set is that nothing overlaps.
- The set starts EMPTY. Every real message that exists today (the three owner logs, the real-phrases files, the ledger) is already a case, a test or a fixed row, so none is unseen; seeding from them would have measured memory. `--add` refuses a text already in `training/eval/*.jsonl|txt`. Its first line of data arrives with the next owner export. The share right is judged by hand (`--score` writes the replies, `--judge` records the verdict), by the reviewer, not by the worker who fixed things.
- What the curve shows today: 3 points (2026-11-13, 11-14, now), 33 > 37 > 38 general mechanisms (schema worlds + acts + verb groups). Schema-alone world 31/60 flat (the four worlds added after the first point were not the seating world and it was not re-judged, so flat is "not measured", not "did not generalise"); meaning-kept paraphrases 12/85 (14.1%), one value only because the set was one mixed set of 146 before the re-judging. The slope is therefore 0 pp per mechanism where it can be computed, and a gap elsewhere; the honest reading is that the curve has no evidence yet either way.
- **[LIB]** A mechanism count must be a number a script can take at any commit (here: schema worlds + acts + verb groups); a landing that says "added wires" without a count cannot be plotted. A better x (rules added that are used by more than one world, from the reuse report) should replace it once the library reports it per commit.
- Method: a measure that did not exist at an earlier landing is a gap in the history, not a zero and not a back-estimate; the note of the point says why. A set that is re-judged (paraphrases: same / changed) breaks the line at the re-judging.

## Order in time, one noun-phrase resolver, referent as evidence (worker-log "Order in time, one resolver, referent evidence")
- Generalised: a question that puts two moments in order ("is Monday before Friday", "does spring come after winter", "is 3 o'clock after 5pm", a day against a month) is recognised once from the temporal preposition facts (`en.timeComparison` over `en.timeRelation` and the `lang.en.timeword` names) at the dialogue level, for every tab and both reasoners; until a world has an order in time the answer says it cannot compare yet, never "4 days" (cases h21-h23 right: 2 of 5 -> 4 of 5 temporal; the open one, "is March during the summer", needs the season facts of k.time). Two noun-phrase resolvers (the acts executor, art.draw `resolveNP`) now call ONE host function (`src/lang/np-resolve.mjs`: choice, part of a set, relative clause, "the other one"), 52 lines of duplicated logic removed from the two worlds; test-world all (both reasoners), the owner logs a / b / c, the lang holes and the coverage grid (1,689 cells) are identical row by row. A referent held by a world the user worked in lately is evidence for that world ("remove milk" on the drawing board while the list holds milk goes to the list; spec 20 rule 5), by the same whole-word lookup as rule 2, with no phrase listed; the six invariants stay green.
- Did not generalise: the two domains still look up a PLAIN phrase in their own way (kind, number, name, attribute value in the acts; kind, colour, size, place, ordinal in the drawing: 1,000 lines of parser), so "one resolver" is the shared reading plus an adapter of five functions, not one parser; the library's `resolve(phrase) -> ids + tier` (handover/lang.en/std-grammar.md section 8) is what would remove the adapters. "delete bread" on the drawing board is still guessed by best effort as "delete my bread list" (a list named bread, which exists only by the verb's other sense): the referent evidence drops the board's refusal but cannot say WHICH frame of the other world the words fill; that is `std.fill` (delegation with tiers), not another rule here.
- **[KNOW]** `k.time` has `n` on weekdays, months and seasons and `after` on seasons, but no `before / after` relation derivable by one rule, no clock hours, no parts of the day, no cyclic successor; `timeComparison` reads the names from `lang.en.timeword` facts only until it does, and `plan.timeline` cannot sort things with a temporal aspect (nothing to sort by) until it is published. `w.lang.en` is not in the catalog yet (its second worker is importing the hand-over), so `src/lang/en.mjs` still loads the hand-over (`createLangEn(source)` takes the catalog's wires when they exist).
- **[LIB]** `std.grammar` `resolve` (above); and an evidence rule for the world of a referent belongs in `std.focus` / `std.fill` (the world whose things hold the words is a candidate of the delegation, ranked by the tier "scene").
- Method: the evidence rule was written against the mechanism first (what is the tab's own state, who holds the words) and found that two guesses were wrong on the way (tab worlds: the tasks world has no tab; every world's state: the reader's sample story holds "bread"); a world is evidence only if the user has worked in it.

## data.charts switch: a data world became schema + acts (worker-log "data.charts switch")
- Generalised: one grammar read 267 of the 277 old rows with 163 lines of schema and 29 new generic forms (`worlds/acts/forms.data.mjs`: an enum after a determiner, a switch, a text value, a number said for a thing, an amount or a factor, "go to the next one", an order, data first); the hand patterns went from 365 to 163, the hand lexicon from 1,750 to 1,100 lines, `matrix.sop` / `fns.mjs` / the 40-line `interceptInput` of regexes are gone. The same forms read "hide the legend", "call it Fruit" and "pears 7" in any world that has a switch, a text and a number.
- Did not generalise: the families that are not acts (sources from other worlds, statistics, pictures and files) keep 163 hand patterns and had to be given a HIGHER priority than the generic forms, otherwise "chart the prices of the toys" is a `make` and "copy the chart data" a `copy`; the verb alone cannot say "delete the chart" from "clear the chart" (one form for both, the domain hook cannot see the verb). The ledger has the 10 rows by cause (reset, un-verbs, "drop", an anaphora of the open tab, the dialogue's "instead", no-chart declines).
- **[LIB]** Priority between a specific frame of a world and a generic act form needs a rule, not numbers: "a frame that names the world's own words beats the act forms" (today each extra pattern got +20 by hand). The same module should own "what is X" for a named thing of the open view, so that a bar of the open chart wins against a catalog word (`focus` from the decline hook did it for the open tab only).
- **[LIB]** A slot grammar fact found the hard way: an optional lexicon slot before a required slot does not match (`{value:L}? {noun:N}`), a lexicon word that ends in s is lemmatised away (`sideways` must also be listed as `sideway`), `words` takes at most 4 tokens unless `words(14)`; the library's form compiler should reject or fix these when the schema is generated.
- **[KNOW]** `k.actions` lacks verbs of remove ("drop") and of reset; `k.attributes` should say that a switch attribute has a verb and its un-verb (stack / unstack, show / hide), and the default of an attribute ("reset the colours"); a view that takes a set (`many`, `counts`) is still 26 hand lines because `acts.view` cannot declare it.

## LANG-EN first slice: noun phrases, coordination / ellipsis, anaphora read from English facts (worker-log "LANG-EN first slice")
- Generalised: the closed classes of English were written again in seven modules (5 lists of determiners, 5 of pronouns, 4 of prepositions, 2 of ordinals, 2 of singularisation); as facts with a view per old list, one 214-line module (`src/lang/en.mjs`) replaced them and 187 lines of code in 12 files (the algorithms moved, so the code did not shrink; the gain is one place for every word list); test-world (34 worlds, both reasoners), owner logs a / b / c, the robustness sets and the coverage grid are identical row by row, which is what "knowledge moved, behaviour did not" should look like.
- Did not generalise: the views differ by accident (`dialogue` has `many few several`, `routing` has `new`, `acts` lacks `his her its their`), so the facts could not be unified without moving numbers; the algorithms (split a coordination, shared argument, one-anaphora) are still code, only their word lists and limits are facts; negation of an act, relative clauses, "the other one" and "some of the tables" are in no module at all.
- **[LIB]** `std.grammar` should ship the facts-lookup functions first (views, inflect, fragment, agent), then the three algorithms with these cases, then a chart parser measured against the generated patterns; a `grammar.diff(viewA, viewB)` makes unifying a measured decision. The proposal is `handover/lang.en/std-grammar.md`.
- **[KNOW]** `w.lang.en` is `handover/lang.en` (schema, 11 shards: 176 argument frames, 79 phrase groups of lang.common, rules with `status=hole` for the English nothing reads); `lang.common` mixes grammar with world-specific lead-ins (`i_want_to_make_the`), which belong to the worlds that asked for them.
- Method: when a list is copied into facts, keep one named view per old copy and diff the whole gate; a differential test of the old and new function over 2,116 words found the lemmatizer equal before any suite ran.

## LANG-EN slice 2: clause cutter and argument frames as facts, then the holes one by one (worker-log "LANG-EN slice 2")
- Generalised: the clause splitter, the card-driven cutter, frame leads, correction markers, bare answers and question words now read `src/lang/en.mjs` (`handover/lang.en/shards/clauses.sop`, each old list a named view); the 238 argument frames of the acts (the old `FORMS`, `FORMS_MORE`, `FORMS_DATA`: the first extraction had 176, the 62 `acts.data` forms were missing) are facts in `frames-acts.sop` and the schema worlds generate their patterns from them, with the code arrays deleted (280 lines of form tables gone from three files). Both moves passed the strict gate: test-world (both reasoners), owner logs, rules-C robustness (1,848 rows) and the coverage grid (1,689 cells) identical row by row, generated files of the 7 schema worlds byte-identical.
- Method that made the move safe: rebuild the old structure from the facts and deep-equal it with the code arrays BEFORE deleting them (238 of 238 equal, which also exposed what the first extraction had lost: the 62 `acts.data` forms and the reader forms' `tabOnly` / `tabPriority`); then delete.
- Holes, with cases (`training/eval/lang-holes.jsonl`, 31 cases, `node scripts/eval-lang-holes.mjs`, recorded in the case corpus as source `holes`): right 10 -> 27 of 31 (new reading in `en.nounPhrase`: relative clause with "be" 0 -> 5 of 5, "some of / two of" 0 -> 4 of 4, "the other one" 2 -> 4 of 4, "or" 0 -> 3 of 3, negated request 0 -> 3 of 3 (a 4th case, a leading "never", stays open); controls 6 of 6 before and after). Not closed: temporal prepositions (2 of 5; the facts and `en.timeRelation` exist, but no world has an order of its things in time to consume them: "is Monday before Friday" is still answered as a distance), and a leading "never" (kids.tasks reads it as a statement about a task).
- What the holes showed: four of them were not missing English but WRONG ACTIONS: "make table 1 or table 3 red" changed table 3 (the last of the list), "remove table 1 or table 2" removed table 2, "make two of the tables..." added tables, "do not draw a sun" drew a sun (the form swallowed "do not" into a free capture), "remove some of the houses" removed all of them. Reading what a sentence does not say (a choice, a part of a set, a negation) is a safety property before it is a coverage one; each of these now asks or declines and changes nothing.
- Did not generalise: the NP readings plug into two resolvers (the acts executor `resolve`, art.draw `resolveNP`) because art.draw has its own noun-phrase parser (1,000 lines) and the forms' determiner words ("some", "the") are eaten by the pattern before the role capture, so the reading also has to accept "of the tables" and "other table" (the facts list those residual forms). One chart parser over the facts (`std.grammar`) would read the phrase once.
- Negation of a request is a dialogue-level decision, and the check "does a world own this negation" is the span of the reading's free captures: "Dont loop it" is the music world's loop off (a pattern that consumed the words, 399 tests expect it) and must stay; "Do not draw a sun" was read by a catch-all whose free capture held "Do not draw a". The first version intercepted both (one new test failure in media.music); the measured fix, not a list of exceptions, is the rule.
- **[LIB]** `std.grammar` should read these four facts (`relpron`, `partitive`, `other`, `choice`) and the negation lead as rules of its chart, with "the reading asked instead of guessed" as a result kind (`ask` with candidates) so every world gets it; today it is code in two resolvers.
- **[KNOW]** `w.lang.en` needs an order-in-time relation (before / after / during with the line it is measured on: days, months, seasons, the clock) in `k.time`; then `timeRelation` has a consumer and the five temporal cases close.

## Recurring lessons across landings
- A fix is accepted when it names a cause group and reports the group's count before and after; most "bugs" in the ledger are one group seen many times (boundary 1,656 of 2,504 failing cases: translation and typing, not the pipeline).
- A pair of worlds that cooperate is worth more than a feature inside one world: T1 shows 11 of 15 world pairs working with no per-pair code.
- What each landing deleted is the real measure: lines of hand-written language, general lines still in PSys2, knowledge items still in worlds. The table makes it visible; the accuracy sets only guard.

## 2026-11-14 acts bridge: domain effects through sopworld 0.29.0
- **The first switch costs more in the contract than in the code.** Moving the host's acts onto `std.schema.effect` took one 80-line module (`worlds/acts/effects.mjs`) and 12 lines in `acts.mjs`; the work was finding what the library checks before an effect (required arguments per act: placeholders), what it swallows (a throw in an effect is an `error` refusal; budget stops and bugs must be rethrown by the host) and what it needs to undo (the library calls `undo()` only inside a sentence, so the host gives one snapshot for the whole sentence).
- **All or nothing is a behaviour change worth having.** The bridge left the earlier parts of "draw a moon, a star and a ghost" done when the ghost was refused (one undo step, a wrong picture and a reply about a failure). With the library sentence nothing is kept and the reply says "I changed nothing". No test, owner log or corpus case depended on the old behaviour (0 right-to-wrong).
- **Measured, same numbers:** art.draw 564/596 ops and 561/600 matrix, diagram.sketch 756/771 both, ui.avatar 18/18 both, data.charts 258/267 ops and 267/277 matrix, plan.seating 7/7, plan.timeline 4/4: identical to before. Owner logs 45 / 10 / 14 identical, corpus 0 right-to-wrong. Cost: about 8% on a world's test run (the difference reads the `referents` signatures twice per act), a few ms per sentence of several steps (`structuredClone` of the session state).
- **Replies stay the host's.** Templates need a reply that can be made from a diff. The four domain worlds say what they did in their engines' words, so the library's `actReply` has nothing to fill; the step that unlocks it is a world whose engine returns what it did as data (a diff with the user's words), not a sentence. Until then replies are a bridge, listed in specs/21 section 10.
- **State off the wires makes the reserved-names question disappear;** it returns the day a world's things become wires, which is also the day the generic executor and its reply code can go.
## Smoke invariants after the art.draw switch (worker-log "smoke invariants after the art.draw switch")
- A red invariant is not always the invariant's subject: the network test was red because a generated catch-all reading (`show {thing:words}`) of the wrong world read a typo before the tab's repair. Read the failing assertion before blaming the named cause; the readings with and without the catalog were equal all along.
- A free-words slot in a generated pattern needs the same decline rule as any catch-all: the world's `accepts` must say what the words may be (here: names of the drawing), not accept the act.
- Two layers each kept "one step per message" (the executor's `stepGroup`, a hand merge inside `add`); the owner's rule is one step per request, so a rule stated in a spec is a test, and a spec line that contradicts a newer decision (spec 21 section on undo) is a bug to fix with the code.
- **[LIB]** The undo contract of the library should be per request with an optional "whole message" tag; hosts then do not re-implement grouping (executor, dialogue timeline and world engine each held a copy).

## Arbitration of generated worlds (worker-log "ARBITRATION")
