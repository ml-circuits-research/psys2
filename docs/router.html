Router

Status: implemented planned (vision only) Lexical router implemented; calibrated, embedding-based routing is vision only.

Specs: spec 03 Rule formalizer

Vision: vision §7

Purpose

The router decides which installed worlds are candidates for each piece of text. It exists because a system with many worlds cannot afford to formalize every segment with every world, and because input may belong to no installed world (vision §7).

Implemented: lexical router (spec 03 §5)

For each sentence every loaded world gets a score: +5 if one of its patterns matches the sentence, +1 for each token whose lemma is in one of its lexicons (trigger entries +2). Worlds with score > 0 are candidates; the top 3 are reported in segments[].worlds. The score is used for reporting, ordering ties between readings, picking example sentences when a sentence is not understood, and later for restricting the encoder strategy. Since it is cheap, the rule formalizer tries all patterns of all worlds anyway.

segments[0].worlds = [
  { id: "kids.arith",  score: 9 },
  { id: "kids.animals", score: 1 }
]

Multi-world and mixed documents

Equal-rank matches from different worlds that emit different wires are kept as alternatives and reported as ambiguity rather than resolved silently. Per sentence routing already allows one message to touch several worlds. There is no document-level segmentation with overlap, no heading or table handling, and no per-context branches yet.

Target design (vision §7)

  • A request pins a deployment snapshot at its start. Documents are segmented with overlapping context, preserving headings, paragraph structure, tables and cross-segment references.
  • The router retrieves candidate worlds with a dedicated, pinned embedding configuration and world descriptions, examples and questions: centroid retrieval plus a calibrated reranker and an unknown-world threshold. It does not assume every segment belongs to an installed world. Embeddings from a masked-language encoder need a defined pooling method and task evaluation.
  • Candidate worlds formalize the segment; validation checks schema, scope, source alignment, identity and context compatibility. Candidates are compared by calibrated scores and explicit evidence requirements. The number of filled keys is a completeness indicator, never a cross-world correctness score.
  • Compatible readings are kept with their contexts; conflicting credible readings become alternative branches and an ambiguity result; unsupported readings are rejected with a reason.
  • Changing a world adapter does not change the router; router updates are versioned and tested separately. Routing and full formalization costs are measured separately.

Vision and specs differ

Spec 03 routing is a lexical score with no calibration, no embedding model and no unknown-world decision (score 0 only means "not a candidate"). The vision requires a calibrated reranker and unknown-world rejection, with target top-3 recall of at least 95% at 100 worlds and out-of-domain false admission at most 5%.

Failure modes

  • No world scores above 0: the sentence is unparsed and the dialog says so with no examples guessed beyond the closest world.
  • Neighboring worlds with overlapping vocabulary: ambiguity reported.
  • Lexical overlap in an unrelated world (a false candidate): the pattern requirement still protects the result, since only a full pattern match emits wires.
