What sopworld can and cannot replace, world by world

Map for stage 2 of SOPWORLD-1 (spec 15). Every code line of each world's ops.mjs (and of the helper modules of the engine-heavy worlds: scene.mjs, arrows.mjs, engine/) is assigned to its function, and each function to one of five classes. Generated by node scripts/map-ops-sopworld.mjs (first classification by function name and body, corrected by hand where it was wrong; see OVERRIDES in the script). Two worlds, core and lang.common, have no ops.mjs.

  • State and rules: states, events, actions, undo. Replaceable by a matrix (fluents, effects, core.action, retract).
  • Queries and aggregates: answers computed from facts. Replaceable (queries with a status, aggregates, rules, core.calc).
  • Text handling: splitting, cleaning, parsing words. Stays code; the matrix calls it as an action or a function.
  • Engine, geometry, search: layout, chess, maps, drawing, minimax. Stays code; only its state and its validation move.
  • Reply wording: sentences, plurals, notes. Stays ours (templates; voice in the matrix worlds).
