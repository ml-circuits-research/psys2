# main-synthetic-dataset

Systematically generated training data for the next SOP-BERT round: natural text →
wire-level UI intents (the reader and the cutter). Generated by the reusable library
skill [`generate-reader-datasets`](https://github.com/ml-circuits-research/soplang-words-lib/tree/main/skills/generate-reader-datasets).


## How this dataset was built (chain, no step skipped)

1. **Wire layer — the UI's own declaration inventory.** Source:
   `training/sop-bert/data/ui-natural-v1/coverage.json` (`nativeInventory`): 124
   native operations across the five editors with every parameter's type, enums,
   ranges. The enumerator keeps every non-legacy operation and its parameter
   subsets (pairwise + a few triples).
2. **Value layer — the catalog's own vocabulary.** Source: the published knowledge
   worlds (`sop-knowledge-worlds`): 2,214 declared objects, 6,654 `core.word` senses
   (~517 object senses, 130 colour senses with natural surfaces like
   `text="mustard yellow" means=mustard`). `vocabulary.json` is the extraction; the
   reader trains on words the worlds KNOW.
3. **Seeds** (`seeds-all.jsonl`): 1,680 systematic skeletons — operation × kind
   value (UI enums exhaustive; 259 catalog-kind seeds like "add a beach umbrella")
   × parameter subsets. Numbers use the documented deterministic grid
   (30/120/260/400; coordinates are infinite — the grid is the choice).
4. **Variants, two tiers, honestly marked:**
   - `mech-variants.jsonl` — deterministic surface variants for EVERY seed
     (verb rotations, article/order/spelling shapes, catalog synonym surfaces):
     `tier: "mechanical"`.
   - five authoring agents (drawing/diagram/document/calendar/avatar) write
     12–20 human tiers per selected seed (equivalent/complex/simplified; calendar
     boosted to 16–20/seed as the thinnest editor): `tier: "human-*"`.
5. **Assembler validation** (`scripts/assemble.mjs`): every claimed constraint
   surface must occur verbatim exactly once (duplicates → quarantine), optional
   drops/blurs become `completion.requirements`, never gold; mandatory constraints,
   act and kind immutable; texts rejected on duplicates within the set and against
   `ui-human-v1`/`ui-natural-v1` corpora. Labels are always COPIED from the seed,
   never re-validated from the phrase.

Labels are always COPIED from the seed skeletons; nothing is re-authenticated from the
phrase. `typos`/`syn` claims keep canonical labels with `typo_of`/`alias_of` evidence.
The coverage gate is now part of the build: any regeneration that leaves a catalog
value under the minimum fails with the trigger list that names the batch to write.

## What is deliberately NOT here yet (next batches, honestly)

- ~~Compound multi-request messages~~ **delivered in round 2**: 38 two-intent
  compounds with per-segment spans (`tier: human-compound`), generated and
  validated through the same assembler.
- **Correction/ambiguity pairs** ("no, the other one") — needs `context.previous`
  plus an alternatives extension field; Review 29 behaviour.
- **Execution verification**: unlike `ui-natural-v1`, these recipes were NOT
  executed through the editors (`nativeTool: null`, `executed: false` in the seed
  provenance). Mechanical + structural validation only. The compile-verified loop
  (intent wires → elementary wires → world accepts) is the next skill upgrade.
- **Romanian** — not attempted; the vocabulary layers exist in the catalog.

## Files

- `seeds-all.jsonl`, `vocabulary.json`, `agent-seeds/<area>.jsonl` — inputs
- `mech-variants.jsonl`, `variants/<area>.jsonl` — variant authoring
- `examples.jsonl` — THE dataset (assembled, validated), `report.json` — validation
  report, `matrix.md` — the diversity matrix (operation × tier × area; filler
  dominance check)

## Train with it

Same record schema as `ui-human-example` (`format: psys2.synthetic-example/1`;
if the trainer filters on the format string, treat as ui-human after swapping that
one field). Keep `cohort` splits: one seed's variants must never straddle
train/dev. Consider downweighting `tier: "mechanical"` rows (they exist for
coverage, not for naturalness).
