# 03 — The rule-based formalizer (`formalization=rules`)

A light formalization strategy built from patterns and heuristics, declared per world. It runs on any CPU and in the browser, needs no model, and is used to bootstrap worlds quickly, to generate and check training data for the encoder strategy (vision §5–6), for tests, and wherever speed matters more than full coverage of natural language. See ADR-001. Input is English (other languages are translated first, spec 05).

Implementation: `src/formalizer/rules/` (browser-safe). Interface:

```js
formalize(text, { worlds, session, source }) -> {
  segments: [{ text, span:[start,end], isQuestion, worlds:[{id, score}], match: { patternId, worldId, slots } | null,
               wires: Wire[], unparsed: boolean }],
  wires: Wire[]          // all emitted wires, in order
}
```

## 1. Normalization and segmentation
1. Split into sentences on `.`, `!`, `?` (not inside numbers like `3.5`), keeping offsets; `?` marks a question. A sentence that starts with a question word (`how`, `what`, `who`, `where`, `when`, `which`, `why`, `is`, `are`, `does`, `do`, `can`, `did`) is also a question.
2. Tokenize: words, numbers, `'s`, and the arithmetic symbols `+ - * / × ÷ =` (`×` and `÷` become `*` and `/`) when they stand between two numbers (`7+5`, `12 - 4`, `3 × 4`) or `=` right after a number (`7 + 5 =`); anywhere else they are dropped. A `-` directly before a digit and not after a word or digit is a negative number (`-3`). Keep the original casing of each token (needed for names) and a lowercase form for matching.
3. Expand contractions (`doesn't` → `does not`, `isn't` → `is not`, `I'm` → `I am`, `what's` → `what is`, `don't` → `do not`, `can't` → `can not`).
4. Number words to digits: `zero`…`twenty`, tens, `hundred`, `thousand`, combinations (`twenty-one`, `one hundred and five`), `half` → `0.5`, `a dozen` → `12`.
5. **Fillers.** Always-droppable words: `please`, `ok`, `okay`, `well`, `um` (the original set), and `hey`, `uh`, `uhm`, `uhh`, `hmm`, `hm`, `lol`, `pls`, `plz`, `thx`, `ty`, `tysm`, `rn` and please-variants (`pleeease`, `plss`, `pleas`). Context fillers: `like` only as a discourse marker (clause-initial before a request or question word, or between commas, never `I like apples` or `what is a bird like`), `for me` only at the end, `u know` / `ya know` (and `you know` next to a comma or at the end) unless an auxiliary precedes (`do you know ...` is kept), and the tag `right` / `eh` / `huh` / `yeah` after the last comma of a `?` sentence. Sentence-initial `so`, `and`, `then` and `after that` are dropped too. Tokens are **marked** `filler: true` (`lead: true` for the sequencing words), not deleted: `tokenize` drops them unless `keepFillers` is set, `analyze` keeps them, and the matcher tries the views of the tokens in this order until some pattern matches (`rankMatches`):
   1. *compat*: the original fillers and a leading `so/and/then/after that` dropped, the newer fillers kept as words (a sentence an older reading understood is read exactly as before);
   2. every filler dropped (so `hey can you play c pls` reads as `can you play c` even though no pattern lists `hey`);
   3. every filler in place, for the patterns that themselves list a filler or a sequencing word (`then E F`, a pattern that requires `ok` or `please`, a greeting that requires `hey`).
   A slot never captures a filler. A sentence of only the original fillers (`ok.`) is dropped as before; a sentence with another filler (`hey.`) is kept so that a greeting pattern can read it. A clause of only fillers is dropped when a sentence is split.
6. **Question mark.** A sentence ending in `?` ends with a zero-width token of kind `qmark` (the segment span is unchanged). A pattern may list `?` as an element (`glasses on you ?`): it matches only when the mark is there and counts as one literal, so it outranks `glasses on you` for `glasses on you?`. A pattern without `?` ignores the mark (behaves as before); `rest` and `words` never swallow it. Question tags (`ok?`, `, right?`) are fillers, so `queen h5 ok?` is `queen h5` plus the question mark.
7. **Operators and percent.** `+ * / ×(=*) ÷(=/) < >` are tokens (kind `op`) between two numbers, or between two tokens when the symbol stands alone between spaces (`a + b`, `x > 3`); `-` only between numbers (a dash is also punctuation, `and/or` and `apples+pears` keep dropping the symbol); `=` after a number. In a pattern a symbol and its words are one literal (matcher `OP_WORDS`): `+` = `plus`, `-` = `minus`, `*` = `times` / `multiplied by`, `/` = `divided by`, `>` = `greater than` / `more than`, `<` = `less than` / `fewer than`, `=` = `equals`, `%` = `percent`, in both directions. `%` becomes the word `percent` (`50%` is `50 percent`); a pattern that does not list `percent` still reads `50%`, the word is dropped in a retry view.
8. **Ordinals and number words.** The ordinal words `first` ... `twentieth`, `thirtieth` ... `hundredth`, `twenty-first` are word tokens with `ordinal = n`; `1st`, `2nd`, `21st` stay a number followed by the suffix word (`2` `nd`, as they always were, so patterns that list the suffix keep working), the number token carrying `ordinal = n`. The slot class `ordinal` accepts any of these (value: the digits, `3`; for the digit form it consumes number and suffix). `{n:number}` accepts the bare number first and, when a pattern needs the suffix consumed, the pair (`take the {n:number} one` reads `the 2nd one`); it does not accept the ordinal words, because `second` and `seventh` are also time units and chord names (`Play G seventh` is not square g7). A literal `second` does not match `2nd` (a `rest` slot keeps the user's own words). A token matches a literal by `lower` or by `alt`: a converted number word keeps the word in `alt`, so `one`, `two` match the literal `one`, `two` and the slot `{n:number}` alike (`next_one` works). Number words: `one point five` / `three point one four` -> `1.5` / `3.14`, `one and a half` / `two and half` -> `1.5` / `2.5`, `half` -> `0.5`, `a half` -> `0.5` for a number slot (the `a` is consumed), misspellings `fourty`, `ninty`, `fiveteen`, `eightteen` read as 40, 90, 15, 18. `ur` is read as `your` (`alt = ur`).
9. **Possessives without apostrophe.** After tokenizing, a word `<stem>s` followed by a word or number is split into `<stem> 's` when the stem is in a name lexicon and the word itself is not (`toms apples`, `bens marbles`); `how many are toms` is left alone.

### 1b. Typo tolerance

When no pattern matches a sentence (and no clause of it), the formalizer retries **once** with the unknown words corrected to the closest known word. The vocabulary is every literal of every pattern plus every word of every lexicon of the loaded worlds (multi-word entries split into words, plural forms included). Distance is Damerau-Levenshtein (insert, delete, substitute, swap neighbours): 1 for words of 4 to 7 letters, 2 for words of 8 or more, none below 4. Never corrected: numbers, text in quotes, capitalized names (except the first word), words with digits, apostrophes or hyphens, words that are already known (also by lemma), and words with two equally close candidates. At most three words per sentence. The corrections are recorded as `segment.corrections = [{ from, to, span }]` (also in the trace) and the dialog appends `(I read "suprised" as "surprised")` to the reply. A sentence that matched without correction is never touched. **Ties**: when several words are equally close, the **preferred vocabulary** wins (the words of the world that owns the active tab, game or modal, then of the recent worlds; in `spell.mjs` the candidate world's own vocabulary), then the most frequent word (occurrences in the loaded patterns and lexicons, `vocabularyOf(set).freq`); only if that still leaves two candidates the word is left uncorrected (never an arbitrary pick). Unknown words are corrected in the same retry after fillers and lead-ins are set aside, and `u` is read as `you` in it.

### 1c. Conservative expansion of elliptic and corrected sentences (review F4, R2)

Real messages often omit or repeat words: "make your eyes and body blue", "eyes blue and body red", "draw a cat, no wait, a dog", "move left three times". The formalizer expands such sentences **before parsing** into complete clauses, in the rules (the dispatcher and segmenter never copy arguments). Implementation: `src/formalizer/rules/expand.mjs` (proposals) and `readSentence` in `index.mjs` (acceptance).

**Acceptance (conservative).** A sentence is expanded only when it is not already read cleanly, and only when the expansion is fully understood:
1. *Already read* = the whole sentence (or its clause-by-clause reading) parses, and no free-text slot (`words`, `rest`) swallowed text that signals a catch-all. Such sentences are never changed. A free slot signals a catch-all when its text contains a correction marker, `then`, or a repetition (`twice`, `N times`); or a coordination (`and`, `but`, `,`) while a required lexicon slot follows it in the pattern (`make {t:words} {c:colour}`), or the pattern is an explicit unknown-argument catch-all (emit action `...Unknown`).
2. Every expanded clause must parse completely, all in **one world** (for repetition: the repeated clause parses). A free-text slot of a coordinated or elliptic clause must lie inside that clause's own words, never over words copied from elsewhere.
3. If any condition fails, the sentence is read exactly as without expansion. Trial readings leave no trace (the session state is restored).

**Families**, tried in this order (self-correction, then clause level, then shared argument):
- *Self-correction* — a marker (`no wait`, `I mean`, `I meant`, `no sorry`, `scratch that`, `or rather`; or `, no` / `, sorry` / `, actually` / `, wait` / `, make that` / `, oops` after a comma) followed by a correction, up to the next `,` or `then`. The correction replaces the part of the abandoned clause (the last clause before the marker) that it corrects: "make your eyes blue, no, green" -> "make your eyes green"; "draw a cat, no wait, a dog" -> "draw a dog"; "knight to f3, no, knight to c3" -> "knight to c3". Alignment (`align` in `expand.mjs`, context-free, in this order): the correction restarts the command (same first word, or at least as long as the clause) -> the whole clause; a number replaces the last number of the clause ("what 3 pencils cost, no, 4 pencils" -> "what 4 pencils cost"); the correction ends with a word that is in the clause -> up to it; starts with one -> from it; else the last words. A bare `no` before the marker ("No, I meant the tree") is an answer to the previous turn, not a clause. This logic exists once (`selfCorrect`); it runs at message level (below) and, for direct callers of the formalizer, again inside `readSentence`.

**Correction phase at message level (review G2).** Before anything else with an effect, `DialogSession.send` runs `correctMessage(text)` (`expand.mjs`) on the whole English message, per sentence: before the modal interceptors (games' modal answers, yes/no), discourse, segmentation, routing, and the encoder or rules strategy. Everything downstream sees only the resulting text, so the abandoned variant has no effect (no chess move, no hangman try, no drawn object, no tic-tac-toe move, no answer for the wrong number) and the correction word ("no") is never routed to another game. Each correction is recorded in `reply.trace.selfCorrections = [{ scope, from, to, source }]` with `scope` one of `value` (one word replaced), `object` (several words), `command` (a restarted command), `modal-answer` (a short clause of at most two words replaced as a whole, e.g. `e, no, z`, `yes, no wait, no`); `source` is the span in the English text. For a short clause where a world must decide between patching and answering ("top left, no, center" vs "move left, no, right") the phase probes the rules (side-effect free): the whole correction replaces the clause when it is read with the same pattern as the abandoned clause, else the patched clause when it is read, else the whole correction. Plain answers (`no`, `yes`, `no, thanks`, `is it big, no?`) and real negation (`do not draw a cat`) contain no marker followed by a correction and are untouched. Tests: `tests/self-correction.test.mjs`.
- *Repetition* (clause level) — a clause ending in `twice` or `N times` (2 to 10) that does not parse as it stands: the clause without the repetition, read N times: "move left three times" → "move left" ×3. Other clauses are separate: "move left 3 times, then undo" → three moves and an undo. A clause that already parses with its own repetition slot ("move left twice") is untouched.
- *Verb ellipsis* (clause level) — a clause that does not parse, after a clause that does: the leading verb (one word, else two) of the parsed clause is put in front, in the same world: "make the tree red and house green" → "make the tree red; make house green".
- *Shared argument* — "A and B ARG", "A, B and C ARG" with a shared leading verb phrase and shared trailing argument (1 or 2 words): "make your eyes and body blue" → "make your eyes blue; make your body blue"; "eyes and body blue" → "eyes blue; body blue"; "make the tree and the house blue". Heads of up to three words; a determiner is never doubled.

**Provenance.** Expanded tokens keep their original offsets. Each produced segment has `text` = the expanded clause and `span` = its own words in the input (the head for a shared argument, the clause for ellipsis and repetition, the corrected region for self-correction), and `segment.expanded = { kind: 'shared-argument' | 'verb-ellipsis' | 'self-correction' | 'repetition', source: [start, end], copied: [[s,e]...], dropped: [[s,e]...], index, of }`; wires carry `core.source` with that span.

## 2. Patterns
```
@pat.arith.has core.pattern
    match="{who:agent} [has|have|had|got] {n:number} {item:noun}"
    emit="@{_} kids.arith.holding owner={who} count={n} item={item}"
    kind=statement
    priority=10
    example="Tom has 5 apples."
```
### Match syntax (token level, anchored to the whole sentence without its final punctuation)
| Element | Meaning |
| --- | --- |
| `word` | literal token (case-insensitive) |
| `[a\|b\|c]` | exactly one of the alternatives; an alternative may be multi-word with `_` (`[how_many\|how_much]`) |
| `[a\|b]?` | optional alternative |
| `{name:class}` | capture one item of the given class |
| `{name:class?}` | optional capture |
| `{name:class(args)}` | class with arguments: `words(20)`, `words(3,label)`, `rest(notes)`, `recent(<lexicon>,<agent slot>)` |
| `...` | skip 0–4 arbitrary tokens (lazy) |

| `[$id]` `[$id]?` `[$id\|lit]?` | phrase macro: one of the alternatives of the `core.phrase` `phrase.<id>` (see "Phrase macros"), optionally mixed with literal alternatives |

### Slot classes
| Class | Accepts | Captured value |
| --- | --- | --- |
| `number` | one numeric token | atom (`5`, `2.5`, `-3`) |
| `word` | any single token | atom (lowercase) |
| `words` | 1–12 tokens, lazy; `words(N)` sets the maximum to N | string (original text) |
| `recent(<lexicon id>,<agent slot>)` | zero tokens: ellipsis. The item of that lexicon most recently mentioned together with the agent captured by `<agent slot>` (an earlier slot of the pattern), else the one most recently mentioned in the session. No such item: the pattern does not match (no guessing) | atom: the lexicon entry |
| `noun` | a single word that is not a personal pronoun (i, you, we, they, he, she, it, me, us, him, her, them), or a multi-word lexicon noun | atom: singular lemma, `_` joins multi-word (`ice_cream`) |
| `<lexicon id>` (e.g. `lex.kids.animals.names`) | a word (or multi-word entry of up to 4 words, e.g. song titles) whose singular lemma is in that lexicon | atom: the lexicon entry |
| `agent` | a person: a capitalized token that is not a known lowercase word, or a name from any `class=name` lexicon, or a pronoun | reference to an agent entity (`$e.tom`) |
| `unit` | a token in any `class=unit` lexicon or the quantity unit table | atom |
| `rest` | all remaining tokens up to the end of the sentence (1 or more), commas kept in the text; use it last, for free text (dictation, titles) | string (original text) |
| `rest(notes)` | `rest` restricted to music words: every token must be a note letter (a to g, with an octave number or sharp / flat), a number, or one of a fixed list (`rest`, `sharp`, `flat`, `natural`, durations such as `half`, `quarter`, `twice`, `beats`, `octave`, `up`, `down`, `then`, `and`, `for`, `melody`, `middle`). Anything else makes the slot fail, so a bare "add <anything>" pattern cannot take "add vents to your chest" | string (original text) |
| `words(N,label)` | `words(N)` that stops at the first personal or possessive pronoun (you, your, my, me, i, our, we, his, her, its, their, it, them): a data label or place name is never "your body" or "my list" | string (original text) |

**Bounded free captures (G3).** A `words` / `rest` capture never swallows frame words. (a) A group of alternatives directly before a `rest` slot tries its **longer alternatives first** (`rename yourself to` before `rename yourself`), so `to` is part of the frame, not of the name. (b) When an optional alternative group follows the `rest` slot (a suffix such as `from now on`, `please`, a tail filler), a shorter capture that lets the suffix match to the end of the sentence is tried **before** the full-length capture (`Call yourself Zed from now on` names `Zed`). Quoted and multi-word names still work (`Bolt the Great`). Renaming patterns (`ui.avatar`) need an explicit naming cue (`call yourself`, `your name is`, `name you`, `rename`, `I will call you`, `from now on call you`); a bare lead-in such as `lets` or `try` followed by free text never renames.

Singular lemma: irregular plurals from `plural=` lexicon entries first; (and a few built-in Latin plurals: `cacti`, `octopi`, `fungi`); then `ies`→`y`, `ves`→`f`, `(ch\|sh\|x\|ss)es`→drop `es`, `-us` plurals (`octopuses`, `buses`, `viruses`, `walruses`, `cactuses`)→drop `es`, `s`→drop. Singular nouns ending in `ss`, `us` or `is` (`glass`, `octopus`, `iris`) keep their `s`; a short list of `-is` plurals (`kiwis`, `taxis`) still loses it. The lemma is used for matching lexicons and in emitted atoms.

Optional elements and lazy skips are tried in a backtracking matcher; the first full match in left-to-right, prefer-consume order wins for one pattern.

### Slot guards
A free-text slot may carry one guard as a second argument. Guards narrow a catch-all pattern without a new slot class, so the code that treats `words` and `rest` as free text (clause splitting, swallowed-separator checks) is unchanged. Only `words(N,label)` and `rest(notes)` exist; any other argument is a pattern error. A catch-all pattern of a world should use a guard whenever another world has a more specific reading of the same words (charts rename: `{a:words(3,label)} should be {b:words(3)}`; geo: `where is {x:words(4,label)}`; music: `add {notes:rest(notes)}`).

### Spoken lead-ins and chat typos (1.5a)
- **Lead phrases.** Besides the single-word fillers, `markFillers` drops a spoken announcement at the start of a sentence when something else follows it: "quick one", "just a quick one", "a quick question", "one quick thing", "real quick", "a simple one", "an easy one", "a trick question", "one sec", "just checking" and similar (list `LEAD_PHRASES` in `normalize.mjs`, longest first). They are marked `filler` and `lead` like a leading "so" (dropped for matching, kept for patterns that list them). A phrase that is the whole message is left alone ("quick one" stays a message); a phrase inside a sentence ("draw a quick one") is never touched. "real quick", "really quick", "super quick", "very quick" are also dropped at the end of a sentence ("what day is it real quick"). Words are compared on the raw token, because "one" is read as the number 1.
- **Short typos.** Below 4 letters the edit-distance corrector does nothing, so `SHORT_TYPOS` (`normalize.mjs`, exported, merged into the spell abbreviations of `spell.mjs`) lists frequent chat misspellings of short words: `wat`, `wht`, `wot` to what, `hw` to how, `mak`, `mke` to make, `ther` to there, `wher` to where, `hve`, `hav` to have, and so on. Like every spell candidate, the corrected text is accepted only when the rules then parse it. "pluss" is not read as the plural of "plus" (a word ending in `ss` plus `s` is not a plural), so it is corrected to "plus".

### Phrase macros (2.5)
A `core.phrase` wire (spec 02, `lexicon.sop`) names a list of literal alternatives. In a match string `[$lang.lead.polite]` stands for `[a|b|c...]` of that phrase, `[$id]?` for the optional form, and `[$id|extra_word]` or `[$a|$b]?` for a union of macros and literals. Rules:
- **Expansion** happens in `compilePattern(match, phrases)`: the element is an ordinary `alt` whose `alts` array is the phrase's (shared, not copied, when the group is only one macro); with several parts the macro alternatives come first, then the inline literals. Alternatives are tried in the order of the phrase, so a phrase lists longer alternatives first.
- **Matching** is identical to an inline group; `literals` and `skips` are unchanged, so ranking and routing are unchanged. `matchTokens` additionally returns `frameLiterals` (<= `literals`): the literal words that came from macro alternatives (lead-ins, suffixes, fillers), so that a later ranking can prefer content literals over frame literals (ADR-007). A phrase with `frame=false` (world-local groups of content words such as the verbs of a pattern family) is expanded the same way but never counts as frame: with mixed parts the order is frame phrases, content phrases, inline literals.
- **Scope**: phrases are global to the loaded set, like lexicons, but a pattern may only use a phrase of its own world or of a world it imports (transitively).
- **Checks**: `checkPattern` reports an unknown phrase id (`unknown phrase '$x'`) and a phrase of a world that is not imported. `compiled` patterns with an unknown id never match. `vocabularyOf` includes the words of every macro alternative that some pattern uses, so typo correction is unchanged by the migration.
- **Migration**: `scripts/migrate-macros.mjs <world> [--write]` replaces alternative groups that are subsets of a phrase by the macro (alternatives outside every macro stay inline next to it), turns identical remaining lists (3+ alternatives, used by 2+ groups) into world-local phrases `phrase.<world>.g<N>_<first alt>` in the world's lexicon.sop (`frame=false` unless every use is a lead-in or suffix), and drops alternatives that can never match because the tokenizer always removes their words (the old fillers please, ok, okay, well, um; the newer ones such as hey, pls, thx stay words in the compat reading, so alternatives with them are reachable).

### Request shapes (2b)
A `core.shape` wire in `patterns.sop` declares ONE operation; the loader expands it into the ordinary `core.pattern` objects of its request forms (`expandShape` in `src/formalizer/rules/shapes.mjs`, browser-safe and pure). Expansion runs in `loadWorlds` after the phrase macros and the lexicon `extends=` are resolved; the generated patterns are appended to the world's own patterns (hand-written first, so their order wins ties), carry `form` and `shape` fields, and every one goes through `checkPattern` (problems are load errors of the world: `world.errors`). `node scripts/expand-patterns.mjs <world> [--shape <id>] [--stats]` prints exactly what is generated, as SOP.

**Shape keys.** `family` (below), `verb` (alternatives `a|b|c`, `_` joins words: imperative verbs for `set`, `do`, `list`; have-verbs for `ask.count`, `ask.exists`), `obj` (object slot `name:class`), `val` (value slot, `set` only), `noun` (property nouns, for example `color|colour`: optional in `set`, required by `ask.value`), `det` (determiners before the object, default `the|your|ur|my`), `link` (default `to|into|be|as`, then an optional `a|an|the`), `mod` and `objmod` (optional modifier groups before the value and the object; alternatives and `$macro` ids), `extra` (one more optional slot after the value or object, for example `n:number?`), `emit` (an emit template), `emitOpts` (the emit of the `opts` form; without it no `opts` form is generated), `forms` / `skip` (comma lists), `priority`, `kind` (default: `question` for `ask.*` and for the `q` and `opts` forms of `list`, else `request`), `sample` (example words per slot, `p=eyes;c=blue`), `example` (extra examples, put first on the first pattern).

**Shapes without an object (noun-only).** `set` and `ask.value` may leave out `obj` when `noun` names the thing itself ("set the tempo to 90", "what is the key"): `<O>` is then the noun group. `set` leaves out the word-order form and the value-first short form; `ask.value` has its own templates (q: `L [$lang.shape.what] N [are|r|is|do|does|did]? <PR> [$lang.shape.now]? T` and `L [$lang.shape.whatis] D N [$lang.shape.now]? T`; imp, wish, ind as above without the object; short `L N T`), where `<PR>` is the optional pronoun group of the key `pron` (default `it|this|that|we|you|u|i`; a shape that must not take `it` lists the others). `extra` may be a literal group (`[percent|per_cent]?`) as well as a slot.

**Families and forms.** `set` (imp order wish ind q short state opts), `do` (imp wish ind q short), `ask.value` (q imp wish ind order short opts), `ask.count` (q imp wish ind short), `ask.exists` (q imp wish ind short), `list` (imp q wish ind short opts). A form the family does not have is an error; a template that needs a key the shape lacks is skipped. Notation: `L` = `[$lang.lead.filler|pls|plz]? [$lang.lead.polite]?`, `T` = `[$lang.tail.filler]?`, `V` verbs, `D` = optional determiner, `O` object slot (with `objmod`), `X` value slot (with `mod`), `N` noun, `K` = `[link]? [a|an|the]?`, `E` extra slot; `[$lang.shape.x]` are the phrase groups of `lang.common` named `lang.shape.*` (want, wishto, ind, can, be, cop, prefer, what, whatis, tellme, know, indask, howmany, numberof, now, seeall).

**Pattern ids and examples.** A generated pattern is `pat.<shape id>.<form>[.<n>]` (the shape wire is `shape.<id>`). Examples are derived from the template: the sentence with the determiner before the object ("Make your eyes blue."), or the shortest one, with `sample` words (else the first word of each slot's lexicon); they are real examples for the export (`export-training`), the hints and the per-world tests ("every pattern has an example"). The shape's own `example=` lines come first on the first pattern. A derived example always matches its own pattern (tested for every shape of every world).

**Routing.** A `short` form is the shape's least specific reading ("blue eyes", "eyes colour"): its priority is the shape priority minus 2 and `createRouter` drops a `short` match when it falls in tier 5 (everything outside the active tab world, the game world and the recently used worlds). Inside the user's own world it reads as any pattern; elsewhere it would steal sentences from the long forms of other worlds. A hand-written pattern with an optional lead verb (`[make]? {c} {p}`) is not a shape form and keeps its tier-5 reach.

**Rule of thumb for authors.** Write a shape for each operation that has several phrasings; keep hand-written patterns for what shapes cannot say (an optional object, a special lead such as "put it back like it was", a different slot order, chat phrasing of one world). New phrasing that every shape should understand goes into the `lang.shape.*` groups of `lang.common` (run the whole operational set), not into a world.

### Emit templates
`emit` is SOP Lang with placeholders:
- `{slot}` → the slot value (atom, or `$id` for agents); inside a string (`"{slot}"`) the original text, JSON-escaped.
- Ellipsis: the formalizer remembers, per session, the item (value of a lexicon slot) mentioned with each agent; `recent(...)` slots read it. Example: `Tom has 5 apples. He gives 2 to Ana.` reads the second sentence as `give who=Tom to=Ana count=2 item=apple`.
- `{slot|cap}` → the value with the first letter of every word capitalized (filter `cap`; for stored names: `im zed` → `Zed`). Applies to strings (`"{n|cap}"`) and atoms; references to agents are unchanged (the agent entity's name is capitalized when it is created). An unknown filter is a pattern error.
- `{_}`, `{_1}`, `{_2}`, … → fresh wire ids, unique per session (`w17`, `w18`).
- An optional slot that was not captured removes the whole `key={slot}` entry.

The engine adds to every emitted wire: `core.via=$<patternId>`, `core.source="<source>#<start>-<end>"`, `core.seq=<n>` (strictly increasing per session; it orders events) and `core.in=$<worldId>`.

### Prefilter (L1)
Before `matchTokens`, the engine skips patterns that cannot match. Per compiled pattern (`prefilterNeeds`) it keeps, for every mandatory literal and every non-optional alternative group, the set of possible first words (the first word of each alternative; an operator symbol also contributes the first words of its word phrases, and the reverse). The sentence view offers a bag of words (`wordBag`: each token's `lower` and `alt`, plus the first words of the operator phrases of an operator token). A pattern is tried only when every need set shares a word with the bag. The test is conservative: it never rejects a pattern `matchTokens` would match (fuzz test `tests/matcher-prefilter.test.mjs`), so results are unchanged; it only saves time.

### Pattern kinds
- `statement` — asserts facts or events into session memory.
- `question` — emits a `core.question` (spec 04).
- `request` — emits a `core.request` (an action or task).
- `chat` — conversational acts (greetings, thanks); emits `core.request action=<op>` handled by a world operation.

## 3. Entities and reference
- An `agent` slot creates (first mention) or reuses an entity wire `@e.<lowercase name> core.agent name="Tom"` in session memory, with `gender=m|f` if a name lexicon says so.
- Pronouns: `he`/`him`/`his` → most recent agent with gender `m` or unknown; `she`/`her` → `f` or unknown; `they`/`them` → most recent agent; `I`/`me`/`my` → `e.user`; `you` → `e.assistant`. An unresolvable pronoun makes the pattern fail for that sentence (no guessing).
- Mentions are tracked in order of appearance; questions also update recency.

## 4. Choosing a reading
For each sentence:
1. Try every pattern of every loaded world (patterns are cheap).
2. Order the full matches with the **routing policy** (`src/formalizer/routing.mjs`, ADR-004), which knows the application state. The dialog session passes a context `{ activeTab, tabWorld, modalWorld, gameWorld, recentWorlds, lastWorld }`. Tiers, smaller wins:
   1. **Modal intercept**: a world with an open modal input consumes the sentence before formalization (spec 07 §2).
   2. **Navigation / meta**: `ui.shell` requests without wildcard captures. 2a: naming a tab (`ui.openTab`, `ui.playGame`) always wins. 2b: settings and meta (speaker, listening, hands-free, rate, language, phrase log, help, which tab, go back) win over every other match of equal or lower priority (a world that claims the phrase with a higher priority keeps it: "Where am I?" on the map).
   3. **Active tab**: a match from the world that owns the active tab wins over other worlds, and `ui.shell` game controls (new game, give up, hint) count as the tab's when the tab belongs to a `games.*` world. Exception ("clearly more specific wins"): another world's match wins when the tab's match is a catch-all (its wildcard captures, `rest`/`words`/`...`, are more tokens than its literal words) and the other match has no wildcard capture, is not of lower priority, and has at least two more literal words, **or** a higher priority and at least two literal words when the tab's catch-all swallows three or more tokens (free-text sinks such as "let us {rest}"). Specificity is literal words minus wildcard tokens; a catch-all of another world never beats a specific match of the tab, and a lower-priority literal match does not steal from the tab's catch-all.
      - **Game controls emit the game's own action.** On a game tab the shell's controls (`ui.newGame`, `ui.giveUp`, `ui.hint`, `ui.undo`) are rewritten to the active game's action declared in its manifest (`gameNew`, `gameGiveUp`, `gameHint`, `gameUndo`, falling back to `tabNew`, `tabGiveUp`, `tabHint`, `tabUndo`): `ttt.new`, `ttt.giveup`, `ttt.hint`; `hm.new`, `hm.giveup`, `hm.hint`; `chess.new`, `chess.resign`, `chess.hint`, `chess.undo`; `guess.start`, `guess.giveup`, `guess.hint`. Off a game tab the shell form stays. One meaning has one label whatever the wording (the dataset builders use the same engine, so labels follow).
      - **Pattern routing keys** (optional, on `core.pattern`): `tabOnly=true` (the pattern is considered only while its world owns the active tab; elsewhere it is as if it did not exist), `tabPriority=<n>` (the priority used while its world owns the active tab), `yieldsTo=<world>` (a tier 2b setting that gives way to that world when it is the tab or a recent world and has a match). The decision's `winner.priority` is the effective priority.
      - **Bare tempo words**: tier 2b `ui.rate` matches of at most two literal words ("faster", "slower", "slow down") yield to `media.music` when music owns the tab or answered recently and has a reading of its own; no priority is changed. "Speak a little slower" stays a speech command.
   4. **Recent**: the world with an active game, then the worlds that produced the last readings, most recent first.
   5. **Everything else**: by `priority`.
   Inside a tier: `priority`, number of literal tokens, fewer `...`/`words` captures, router score of the world, pattern order. If the tab world has no match, nothing is claimed by the tab, so cross-world questions ("How many legs does a spider have?" on the editor tab) work.
   Every segment and the trace carry the **decision**: `{ router, tier, tierName, reason, winner, runnerUp, contested, context }`. A learned router (for example a ModernBERT/LoRA head over state + text) plugs in through `createRouter({ id, model })` with the same `route({ matches, context, scores, tokens })` interface.
3. **Indirect questions.** If no pattern matches the whole sentence and it starts with a lead-in (`tell me`, `can you / could you / would you tell me`, `can you let me know`, `I want to know`, `I need to know`, `I wonder`, `I was wondering`, `I would like to know` / `I'd like to know`, `do you know`, `let me know`; `u` reads as `you`; fillers in front are ignored) followed by a wh-word or an auxiliary (`how what who where when which why is are does do can did`, a one-edit misspelling of a wh-word included; an optional `if` / `whether` is skipped), the **bare question** is read as a question (`stripLeadIn`), clauses and all. The original text is always tried first, the segment keeps the whole sentence as its span, and the typo retry (section 1b) runs on this path too (`hey can u sumarize the story`, `hey could u tell me whats 3 plus 4`). `tell me a joke` is not stripped (no question follows).
4. If no pattern matches the whole sentence, split it into clauses at `,`, `and`, `then`, `but` (one level) and match each clause; a clause that still fails is reported as unparsed.
5. Matches from different worlds with the same tier, rank and literals that emit different wires are kept as **alternatives**; the dialog layer reports the ambiguity instead of choosing silently (vision §7).

## 5. Router
Scores every loaded world for each sentence: `+5` if one of its patterns matches the sentence, `+1` for each token whose lemma is in one of its lexicons (`trigger` entries `+2`). Worlds with score > 0 are candidates (top 3 reported). The router is used for reporting, for ordering ties, and later for restricting the encoder strategy, which cannot afford to try every world.

## 6. Training-data export
Because every emitted wire carries `core.source` offsets and the slot spans, the rule formalizer can export encoder training records (vision §6: text, mentions, key spans, references, label status `generator-backed` or `rule-derived`). `scripts/export-training.mjs` writes JSONL for `training/`. With `--routing-context` the generator's own world is the active tab (`routing` is attached to each record) and the report gives the agreement with and without that context, so cross-world ties are labelled by context instead of counted as disagreements.

## 7. Dispatcher validation layer
A learned **dispatcher** (one small shared encoder, worker-tasks D1) proposes how to cut a message and which worlds own each piece. It never produces circuits. The rule formalizers **validate** its proposals (ADR-005). Implementation: `src/dialog/dispatch-validate.mjs` (browser-safe, no `node:*`), evaluation: `scripts/eval-dispatch.mjs`.

### 7.1 Input contract (dispatcher prediction, one JSON object per line)
```
{ id, text,
  context: { tab, recent_worlds: [world...], session: [earlier user messages...] },
  boundaries: [{ offset, p }],                      // optional, per-token boundary probability (informational)
  segmentations: [                                  // beam <= 4, most likely first
    { score,                                        // log-probability of the segmentation (<= 0)
      segments: [ { start, end, text,               // character offsets in `text` and the piece text
                    worlds: [{ world, score }],     // top-3, most likely first; score is a probability in [0,1]
                    simplified? } ] } ],            // optional cleaner variant of the piece (edit-tag head)
  gold? }                                           // ignored by the validator
```
`id` must be the dataset record id so the evaluation can join gold: the id of a `training/dataset/<world>/test.jsonl` record, of a `routing.jsonl` test row, or of a `multicmd/test.jsonl` message (`mc......`). Parsing is tolerant (`normalizePrediction`): negative world scores are read as natural-log probabilities, `worlds` entries may be `[world, score]` or bare ids (rank-based score), `p`/`prob` may replace `score`, a segmentation may be a bare list of segments, a missing `segmentations` becomes one segmentation of the whole text using the record's `worlds`, `simplified` equal to `text` is dropped, missing `text` of a piece is sliced from `start`/`end`.

### 7.2 Checking a candidate
For every piece, every candidate world (score order, up to `maxWorlds`) and every text variant (original, then the spell-corrected text of section 7.9 when it differs and `trySpell`, then `simplified` when present and `trySimplified`), a **fresh dialog session** is seeded exactly as the dataset records are: active tab (`ui.shell` state), recent worlds, then the `session` messages. When `intersegmentContext` is on, the pieces chosen earlier in the same segmentation are replayed first, so pronouns and elliptic sentences see what the earlier pieces said. The candidate is then formalized with the rule formalizer **restricted to the candidate world and its `extends`/imports** (a view of the world set with only those worlds), with the session's routing context and the engine's router. The wires of parsed segments are added to the session and every wire is resolved by the interpreter.

A candidate is **valid** when
1. every segment the rules found is parsed (no unparsed token group) and at least one segment exists, and
2. the interpreter returns neither `unsupported` nor `error` for any wire (`missing`, `conflicting`, `budget` and `supported` are fine: the sentence was understood, the state may lack facts).

A candidate that parses completely but is refused by the interpreter is `refused` (typical: an illegal chess move, a drawing command with nothing drawn). With `acceptRefused` it counts as valid with a smaller penalty. **Default on** (D3: +3.8 points overall, games 68 to 83 %; a refusal is usually a state reason, questions.md Q3); `acceptRefused: false` is the strict variant and the evaluation reports both.

**Refusal reasons (F5).** The interpreter sets `envelope.reason` on every `unsupported`/`error` envelope (spec 04, "Refusal reasons"); the validator reads it per wire:
- `precondition_failed`: the reading is right, the state or a limit refuses it. The candidate is `refused` (valid with `acceptRefused`, penalty `interpreterPenalty`); the reading is kept and the refusal is explained to the user.
- `unknown_argument`: the pattern matched but an argument names nothing the world knows (a catch-all that swallowed text, "eyes and body blue"). The candidate is **not valid**: it never stops the other candidates, the spell-corrected text, the simplified text, alternates or partial windows from being tried. Only when nothing else validates for the piece is it used as a last-resort fallback, penalised by `unknownArgPenalty` (default 4.5, between `interpreterPenalty` and `unparsedPenalty`), so any reading with known arguments outranks it.
- `unsupported_operation`: the world cannot do it (no operation, unknown mode). The reading is kept like `precondition_failed`; the reply reports the limit and never confirms success.
- `execution_error`: an exception or invalid envelope, a bug. Never valid, never a training example.
Each trace attempt carries `refusal` (the reason) and `unknownArg`.

### 7.3 Scoring (log domain, all weights are policy options, defaults in `DEFAULT_POLICY`)
For a piece, each candidate (world w, variant v) scores
`s = worldWeight * ln(max(p_w, scoreFloor)) - simplifiedPenalty * [v is simplified] - spellPenalty * (corrections used) - penalty`, with `penalty = 0` when valid, `interpreterPenalty` when refused and `acceptRefused`, else `unparsedPenalty`.
The piece takes its best candidate. A segmentation scores `segWeight * seg.score + sum of the piece scores` (a piece with no candidate contributes `-unparsedPenalty + ln(scoreFloor)`). Defaults: `segWeight 1`, `worldWeight 1`, `unparsedPenalty 6` (about x 0.0025), `interpreterPenalty 3`, `simplifiedPenalty 0.05`, `spellPenalty 0.1`, `trySpell true`, `acceptRefused true`, `acceptPartial false`, `partialPenalty 1.5`, `partialUncoveredPenalty 3`, `minCoverage 0.25`, `scoreFloor 1e-6`, `tieEps 1e-6`, `maxSegmentations 4`, `maxWorlds 3`. The winner is the segmentation with the highest score (ties keep the dispatcher order). The result is `understood` iff every piece of the winner is valid.

### 7.4 Ties and routing policy
Candidates of one piece whose scores differ by at most `tieEps`, same text, different worlds, are tied. The tie is broken by the routing policy of section 4: the text is formalized with the tied worlds together (same session, same context) and the router's winner is chosen, so the tiers apply unchanged (modal, navigation, active tab, game/recent worlds, priority). The decision tier and reason are recorded in the trace.

### 7.5 Result and trace
`validateDispatch` returns `{ id, text, status: 'understood' | 'not_understood', partial, winner: { index, score }, produced: [{ start, end, text, world, textUsed ('original' | 'spell' | 'simplified' | 'partial'), usedText, corrections, partial, wires, sop }], notUnderstood, why, trace }`.
- `notUnderstood` (only when nothing validates) holds the best segmentation's failing pieces with their candidate worlds (`pieces[].candidateWorlds`, `candidateWorlds`), so `ui.help` can say "Did you mean ...?" with examples from those worlds.
- `trace.segmentations[]` lists every segmentation, every piece, **every candidate** (world, rank, variant, text, score, `valid`, `refused`, reason, matched worlds, interpreter statuses, unparsed count), the piece's choice and tie decision, and `why` explains the winner (beats the top segmentation, candidate 2 recovered after candidate 1 failed, only the simplified text validates, tie broken by tier ...).

### 7.6 Exact SOP of a message
For evaluation, the circuits of a message are the concatenation, in message order, of the id-normalized SOP (`normalizedSop`) of every produced piece; the gold is the same concatenation over the gold segments' targets. A negative record is correct when the result is `not_understood`.

### 7.7 Running the dispatcher in the browser (Encoder formalizer, D4)
The same chain runs client-side as the `encoder` formalizer strategy (spec 06 "Formalizer strategies"):
1. **Model files** (`python -m psys2_train.export_onnx --ckpt training/runs/dispatcher-<name>`): one ONNX graph with inputs `input_ids`, `attention_mask` (int64 `[b, t]`, dynamic axes) and outputs `seg_logits [b, t, 2]` (boundary head, per token) and `world_logits [b, W]` (world head on the first token), exported fp32 (opset 17) and quantized with onnxruntime dynamic int8 (per-channel weights). `labels.json` holds the world order; `tokenizer/vocab.txt` is the WordPiece vocabulary.
2. **Tokenizer** `src/formalizer/wordpiece.mjs`: the uncased BERT WordPiece pipeline (clean, CJK spacing, NFD accent stripping, lowercase, punctuation split, greedy longest match `##`); `encode(text, { maxLength })` returns ids and character offsets in the original text. `tests/wordpiece.test.mjs` checks ids and offsets against the Python tokenizer on a fixture of about 200 sentences (`tests/fixtures/wordpiece-distilbert.json`, made by `psys2_train.dump_tokenizer_fixture`).
3. **Runtime** `src/formalizer/dispatcher-runtime.mjs` `createDispatcherRuntime({ ort, session, tokenizer, worlds })` (the host injects an onnxruntime session; the core has no dependency on it) mirrors `dispatcher.dispatch` exactly: segmentation pass on the raw message (max 192 tokens), boundary candidates at word-start tokens, beam of at most 4 segmentations from flips of the 6 most uncertain boundaries (independent Bernoulli log-probability), joiners trimmed, then one world pass per distinct piece with the input `tab: <tab|none> ; recent: <w1 w2|none> ;; <piece>` (max 128 tokens) and the top-3 softmax probabilities. `predict(text, context)` returns the record of section 7.1 (without `id`).
4. **Strategy** `src/dialog/encoder-dispatch.mjs` `createDispatcherFormalizer({ load, getPolicy })`: loads the model lazily through the host's `load()` (first use or `prepare()`), calls `predict`, validates with `createDispatchValidator` (sections 7.2-7.5), then formalizes every piece of the winning segmentation with the rules of its chosen world (restricted view, section 7.2) **in the real session**, so the wires are ordinary rule wires and everything after formalization is unchanged. Pieces nobody validated are returned as `unparsed`; the dialog engine retries those with the rules over all worlds. A failing model load makes `available()` false and the engine uses the rules (the error is in `trace.formalizer.error`). `context.session` of the prediction is the strategy's own memory of the last 6 messages it formalized in that session (so pronouns and ellipsis see earlier pieces).
5. **Policy for the demo**: `acceptRefused: true` (now also the library default; a parse the interpreter refuses for a state reason, for example a chess move when no game is on, counts as understood; strict interpretation rejects refused-but-correct parses, questions.md Q3). It is the setting "Accept parses the interpreter refuses" in the webchat.
6. **Trace**: `reply.trace.dispatch` = `{ status, why, policy, winnerIndex, modelMs, totalMs, boundaries, segmentations: [{ index, dispatcherScore, score, valid, nInvalid, pieces: [{ text, valid, chosen, tie, attempts: [{ world, rank, worldScore, variant, valid, refused, reason, score }] }] }] }` and each segment of `trace.segments` has `dispatch: { world, rank, variant, worldScore }`.
`scripts/verify-dispatcher-js.mjs` runs this runtime in Node with onnxruntime-node (installed outside the repository) and compares it with the Python predictions (`psys2_train.dump_dispatch_reference`).

### 7.8 The rephraser: edit tags (simplification head, D1b)
The dispatcher model has a third head that proposes `segment.simplified` (spec 7.1) without generating text. Per **word** of a piece (`src/formalizer/edit-tags.mjs` `wordsOf`: letters/digits with inner apostrophes, every other non-blank character is a word) it predicts one tag: `KEEP`, `DELETE`, `R:<text>` (replace the word), `P:<text>` (put text before it) or `A:<text>` (append after it; glued when the text starts with punctuation); the `R/P/A` vocabulary (at most 500 entries) is built from the data and shipped as `edit-vocab.json` next to the model (`tags[k]` = channel `k` of the output `edit_logits [b, t, K]`, channels 0/1 are KEEP/DELETE). `applyEditTags` builds the rewritten text (original spacing kept); the segment carries `simplified` only when the rewrite differs from the piece and is not empty. The edit head reads the **same input as the world head** (`tab: .. ; recent: .. ;; <piece>`), so one encoder pass per piece gives the world scores and the tags; the tag of a word is read from its first sub-token. A word receives its best non-KEEP tag only when that tag's softmax probability is at least `edit_threshold` (meta.json, default 0.5). The validation layer (7.2) tries `simplified` only after the original, with `simplifiedPenalty`, so the rephraser can only add understanding. Training data: `scripts/build-edit-tags.mjs` aligns paraphrase variants to a rules-verified phrasing of the same task and keeps an alignment only when the rules formalize the rewrite to the target SOP, plus identity (all KEEP) examples and synthetic noise (fillers and word pairs mined from the real alignments). Metric: `scripts/eval-simplify.mjs` (share of variants the rules formalize on the original, on the rewrite, and on either). Python mirror: `training/psys2_train/edit.py`; the two implementations are tied by `tests/fixtures/edit-tags-python.json`.
### 7.9 Spell candidates and abbreviations
A learned or rule text often contains typos and chat forms the patterns do not list ("make bigger yes and red lips" for "eyes", "hey could u tell me whats seven times six pls"). `src/formalizer/spell.mjs` (browser-safe, no dependencies) produces **candidate texts**; a candidate is accepted only when the rules of the candidate world then parse it completely, so a wrong guess costs nothing (the original text is always tried first).
- **Vocabulary** per candidate world (with its imports): pattern literals, lexicon words with plurals, the words of legend names and of the knowledge base, plus a small list of common English function words (`FUNCTION_WORDS`). Words of the world's own vocabulary rank before function words as correction targets.
- **Abbreviation map** (`ABBREVIATIONS`, applied whole-word): `u` to you, `ur` your, `r` are, `pls` / `plz` please, `thx` thanks, `whats` what is, `hows`, `wheres`, `wanna`, `gonna`, `2nd` / `3rd` / ... second / third, `colour` color, and a few more. Same acceptance rule as spelling.
- **Spelling** (`spellCorrect`): Damerau-Levenshtein 1 for words of 3 to 6 letters, 2 for 7 and more, none below 3. Left alone: quoted text, numbers and number words, words with digits, apostrophes or hyphens (except map entries), capitalized names (except the first word), words that are known (vocabulary, function words, or an inflection of one) and ambiguous words (equal rank; rank = distance, then own vocabulary, then same letters). At most 6 corrections.
- **Known-word swaps** (`spellAlternates`): when no candidate of the piece validates, one known word at a time is replaced by a vocabulary neighbour at distance 1 that is not a function word ("yes" to "eyes"), at most 12 texts per world; again accepted only if the rules parse the result.
- The corrections are recorded as `chosen.corrections = [{ from, to, span, kind: 'spell' | 'abbreviation' }]`, copied to `segment.corrections` and shown in the trace ("eyes <- yes"); the dialog appends `(I read "yes" as "eyes")`. A correction costs `spellPenalty` in the score.
- The rules-only path has the same fallback: for a segment nobody parsed, the dialog (`DialogSession._lenient`, session option `spell`, default on) tries the open tab's world, the modal and game worlds, the recent worlds, the router's top 3 and finally all worlds, each with its own vocabulary.
**Context-anchored spelling (G3).** A word known in the active world is never changed, and a content word (4+ letters) that another world knows is not corrected into a word of the candidate world, because that changes both the world and the noun (`boat` on the drawing tab must not become `coat` of kids.animals). `spellCorrect` / `spellAlternates` take `protect` (the active tab world's words); `worldVocabulary(...).global` carries the words of all worlds, and the engine's typo retry (`correctTokens`) treats the tab / game / modal worlds' words and every word of a restricted view's parent set as known. In the all-worlds vocabulary (`*`), `spellAlternates` does not swap a known word of 4+ letters.


### 7.10 Partial understanding
Policy `acceptPartial` (library default off; the webchat setting "Partial understanding" is on by default; session option `partial`). Only when **no** candidate of a piece parses completely (a full parse of any candidate, in any rank, always wins), the best partial parse is accepted instead of "not understood":
1. **Clauses**: the original or spell-corrected text is formalized in the candidate world; the clauses the rules read are executed, the ones they did not read stay `unparsed` segments, and the dialog reports them ("I did not understand "red lips""). Needs a coverage (characters of parsed clauses) of at least `minCoverage`.
2. **Window** (`src/formalizer/partial.mjs`, `findPartialWindow`): the longest run of at least 3 consecutive words that the rules read completely; the words before and after are **ignored** and reported ("I understood only part of that: I did not use "hey could you tell me" and "sweetie""). Guards: a negation (`not`, `no`, `never`, `without`, `don't`, ..., also `stop`, `undo`, `cancel`) is never ignored; an ignored word must be a function word or unknown to every world (a word some world knows carries meaning); a window that turns a statement or request into a bare question (no question word or `?` in the original) is rejected; at most 80 windows are tried per text.
Score: `s = worldWeight * ln(p_w) - spellPenalty * corrections - partialPenalty - partialUncoveredPenalty * (1 - coverage)`; always better than `unparsedPenalty` (6), never better than a full parse. The result carries `partial: true`, `produced[].partial = { ignored: [{ text, start, end }], coverage, window }` and `why` says what was ignored. Multi-command messages: every piece that validates is produced and executed, the others are reported (section 7.5 `notUnderstood`); on the rules path, when none of several clauses parses, each clause is tried on its own (spelling, then window), and a leftover of filler words ("also", "and") next to an understood clause is dropped silently.

### 7.11 Long inputs and the segmentation contract (reviews F4, F8)
**Long inputs.** The model limits are 192 tokens for the segmentation pass and 128 for the routing pass of one piece; nothing is silently truncated. Over the limit, `psys2_train.windows.window_spans` / `windowSpans` (`dispatcher-runtime.mjs`, identical rules) cut the token sequence into overlapping windows of at most the limit (stride half a window, the last window ends at the last token). Segmentation: every window is `[CLS] tokens [SEP]`; a token takes the mean of the boundary probabilities of the windows that see it, weighted by its distance to the window edge (so a decision made at an edge counts less). Routing: the piece text is cut into windows of its own tokens, each keeps the context prefix, the world probabilities are averaged; such a piece gets no `simplified` (the edit head sees one window only). Messages and pieces within the limit take exactly one window, identical to the unwindowed behaviour. Tests: `tests/dispatcher-runtime.test.mjs`, `training/tests/test_f4_f6_f7_f8.py`.

**What the segmenter cuts.** A segment is one command for the rules of one world. The segmenter never copies or distributes arguments: shared argument ("make your eyes and body blue"), verb ellipsis ("eyes blue and body red") and self-correction ("blue, no, green") are ONE segment, expanded by the rules (R2 conservative expansion, provenance kept). Commands that act in order (a reference to a created object, "move it left twice, then undo") and commands of different worlds are separate segments. The training data (`psys2_train/compositional.py`) is generated from programs with exactly these labels; the families are `shared_arg`, `ellipsis`, `self_correct`, `ref_created`, `repeat_undo`, `world_switch`, next to the older `concat`, `single` and the evaluation-only `long`.

### 7.12 The normalizer: a seq2seq rewrite proposed to the rules (N1)
A small encoder-decoder (T5-small class, at most about 100M parameters; AGENTS.md exception of 2026-11-08) rewrites a piece into the **simplest phrasing that keeps the meaning and that the world's rules understand**. It never formalizes: the rewrite is only another candidate text, and the rules stay the only formalizer. Implementation: `createDispatchValidator({ engine, policy, normalizer })` in `src/dialog/dispatch-validate.mjs`, value checker `src/dialog/value-check.mjs`; the core has no dependency on a model, the host injects the provider.
- **Provider** `normalizer = { propose({ world, tab, text, beam }) -> string[] | Promise<string[]> }` (a bare function is accepted): up to `beam` rewrites of `text` for the candidate `world` in the open `tab`, best first. A provider that throws or returns nothing changes nothing. Results are cached per (world, tab, text, beam). `createDispatcherFormalizer({ normalizer })` passes it through.
- **When**: per piece, after the original, spell-corrected and `simplified` texts of **all** candidate worlds failed (section 7.2), and before the known-word swaps and the partial parse of 7.10 (a full parse of a rewrite always beats a partial one). For each candidate world in rank order the provider is asked for `normalizerBeam` (3) rewrites; each rewrite is tried in order and the first one that is **accepted by the rules and by the value checker** is the world's candidate (`variant: 'normalized'`, score `worldWeight * ln p_w - normalizerPenalty`, default 0.3). A rewrite equal to the piece is skipped. Rejected rewrites stay in the trace with their reason (`value check: ...`, or the rules' reason). Policy: `tryNormalizer` (default true, only effective with a provider), `normalizerBeam`, `normalizerPenalty`, `checkValues` (default true), `valueLost`.
- **Value checker** `checkValues(src, cand, { vocab, lost })` (the translation-checker idea of ADR-002: a rewrite must not change what the user said). A rewrite is rejected when: the multiset of numeric values differs (digits, number words, ordinals, tokens with digits such as `g1`; the pronoun "one" as in "the red one" is not a number); the set of colour words differs; one side has a negation (`not`, `no`, `never`, `without`, `n't` forms, `nothing`, `none`) and the other not; the quoted strings differ; or, with the world vocabulary (`worldVocabulary`), a **value word** has no counterpart in the other text. A value word is a word the world does not know and that is not a function word, chat filler or abbreviation (names, titles, junk); its counterpart is the same word or a word within the spelling budget (section 7.9), so a typo of a name may be fixed but a name may not be dropped, replaced or invented. `valueLost: 'capitalized'` relaxes the first half: only capitalized source words (not the first word) must survive.
- **Provider status (review fix)**: a provider may answer `{ status: 'not_ready' | 'error' | 'ready', rewrites }` (a plain array means `ready`). Only `ready` answers are memoized; `not_ready` (model still loading) and `error` (also a thrown error) are never remembered, and the piece trace carries `normalizerStatus`. A provider may expose `stamp` (string or function: model version and state); when it changes the memo is dropped. `validator.clearCache()` clears the candidate cache and the rewrite memo; `encoder.reset()` calls it.
- **Value checker, typed values first (review fix)**: typed values are extracted before word tokenization and compared as values: signed numbers (`-45.5`, spoken `minus 5` where it is a sign), decimals (`1.5`, `1,5`), thousands (`1,500`), times (`7:30`, `7 pm`), note names with accidentals (`C#`, `Bb`), ordinals, number words. `-45.5 25.3` is not `45.5 25.3`; `1.5` is not `1 5`. Role bindings are kept where anchorable: operand order of `A minus B` / `subtract B from A` / `A divided by B` / `divide A by B`; the order of numbers (coordinates) when there is no operation; a value bound to `from` may not move to `to`, and a typed or capitalized entity stays bound to its cue; a number keeps its unit; a colour stays bound to the part it describes (`eyes red and body blue`). Minimal-pair tests: `tests/normalizer.test.mjs`.
- **Trace**: `produced[].textUsed = 'normalized'`, `usedText` is the rewrite, `why` says "read as the normalizer's rewrite ...".
- **Training pairs** `scripts/build-normalizer-pairs.mjs` (output `training/dataset-normalizer/`): every pair is verified by the rules (synthetic noise uses the safe-noise rules of `training/psys2_train/safe_noise.py`, ported in `scripts/lib/safe-noise.mjs` with shared fixtures `training/tests/fixtures/safe_noise.json`, and every synthetic pair is audited with `checkValues`; the report lists the rejections) (the target reads completely to the SOP of the source's label in the record's world, tab and setup). Sources: paraphrase variants to the shortest verified phrasing of their task or to a pattern `example=` of the world with the same SOP (a filler-free target ranks first), and to their canonical; clean generator, rule-derived, canonical and example sentences to the shortest equivalent (idempotent: the shortest maps to itself); unlimited synthetic noise (typos, chat abbreviations, politeness and filler prefixes and suffixes, mid-sentence fillers, lower case, dropped punctuation, repetition) on clean training sentences to their shortest equivalent. Only the train split trains; dev, test, held-out and the fresh batches are never trained on. Python: `training/psys2_train/normalizer.py`; model input `<world> | <tab or -> | <piece>`.
- **Metric** `scripts/eval-normalizer.mjs` (same messages and runner as `eval-simplify.mjs`): per variant `right` / `wrong` / `fallback` before and after; **recovered** = fallback to right, **misled** = fallback to wrong (the rules read the rewrite completely but to another SOP). Target of the experiment: misled at most a quarter of recovered and a clear gain of the right share. Results: `training/results/normalizer-<model>.json`, log entry `N1` in `worker-log.md`.
- **Lexicographic preference (S1; extended across segmentations in 7.13)**: any valid original or spell-corrected reading, in any candidate world, beats every rewrite. The `simplified` text of the edit-tag head (7.8) and the normalizer rewrites are tried only when no original or spell-corrected candidate of the piece validates, so a rewrite can never replace an understood sentence (`broken = 0` by construction; unit tests in `tests/dispatch-validate.test.mjs`). The `simplified` text goes through the same value checker as a normalizer rewrite (`variant: 'simplified'`, rejected with `value check: ...` in the trace). Order inside a piece: original, spell, simplified, normalizer, known-word swaps, partial parse.
- **Policy** (defaults): `valueStrictness: 'strict'` (adds three checks to the basic ones: no opposite-capable word such as big/small, up/down, on/off, start/stop may be dropped or introduced; a content word of the rewrite must have a counterpart in the piece, except generic request frames, articles, abbreviation expansions (`u` to `you`) and typo fixes; a known content word of the piece may not be dropped, only fillers and function words), `normalizerMinScore: -0.3` (length-normalized log-probability of the rewrite; the provider may return `{ text, score }`), `normalizerSegmentations: 1` (only the pieces of the dispatcher's top segmentation), `normalizerWorlds: 2` (first two candidate worlds).
- **Browser** (`docs/webchat/ui/normalizer-host.mjs`, runtime `src/dialog/normalizer-runtime.mjs`): FLAN-T5-small int8, two ONNX graphs (`encoder.int8.onnx` with the cross-attention keys and values as outputs, `decoder.int8.onnx` one step with explicit past key values; `python -m psys2_train.export_normalizer`), the sentencepiece unigram tokenizer re-implemented in JS (identical ids on 2,560 requests), beam search identical to Hugging Face on 100 pieces (fp32). `models/normalizer/meta.json` carries the version block with a sha256 per file; the host fetches the files after the dispatcher is ready, checks and caches them by sha256 (Cache API, older versions evicted) and passes `{ propose }` to `createDispatcherFormalizer({ normalizer })`; while the model is not loaded the provider returns nothing and the rules answer. Settings: "Simplify phrasing (normalizer)", on by default (`settings.normalizer`, policy `tryNormalizer`). The trace shows `normalizer: "..."` with `used` or the rejection reason.

### 7.13 Hierarchical selection over segmentations (G1)
Selection used to compare segmentations by total score only, so an incomplete segmentation whose unread rest the normalizer rewrote (`wat do red` + `yelow mak` read as "What do red and red make?", -6.34) beat the complete spell-corrected reading of the whole message (-6.53). The order is now lexicographic over validity classes; neural scores order readings only inside a class.
- **Class of a segmentation** (`tier` in the trace): 0 = every piece read completely from the original or spell-corrected text; 1 = complete, but some piece needed generated text (`simplified` or `normalized`); 2 = complete only through partial understanding (7.10) or an `unknown_argument` fallback; 3 = some piece is not read at all.
- **Winner**: the lowest class, then the highest total score, then the dispatcher's order. A complete reading therefore always beats a partial or incomplete one, and original/spell readings always beat generated ones whenever any complete one exists.
- **Normalizer residue only**: all segmentations are evaluated first without the normalizer (the cheap `simplified` text is part of that pass). The normalizer (7.12) runs only if no segmentation in the beam is complete (class 0 or 1), and then only on the pieces of the first `normalizerSegmentations` segmentations that nothing else reads. The answer is the same with and without the normalizer whenever a complete reading exists.
- **Weak cuts**: a segmentation whose two adjacent pieces are separated inside a clause (no punctuation or connective between them) is class 3 unless both neighbours are read cleanly (top-ranked world, original text). A mid-clause split such as `what is 7 plus 5` + `minus 2` read by another world never counts as a complete reading and competes by score as before (kids.arith#053, ui.avatar#027).
- Tests: `tests/dispatch-order.test.mjs` ("and" joining colours, operands, objects, cities).

### 7.14 One runtime configuration for every host (G5)
The webchat and the evaluators used to build the pipeline separately (the webchat enabled the normalizer, `eval-operational` did not), so a reported number did not describe the shipped product. `src/dialog/runtime-config.mjs` (no `node:*` imports, copied into `docs/webchat/lib/dialog/`) is now the only place that defines it.
- **Settings**: `RUNTIME_DEFAULTS` = `{ formalizer: 'encoder', encoderAcceptRefused: true, partialUnderstanding: true, normalizer: true, spellcheck: true }`. `docs/webchat/ui/settings.mjs` spreads it into `DEFAULT_SETTINGS`.
- **Factory**: `policyFromSettings(settings)` gives the validator policy `{ acceptRefused, trySpell, acceptPartial, tryNormalizer }` (read on every call, so the webchat's live settings object takes effect at once); `sessionOptions(settings)` gives `{ formalizer, spell, partial }` for `engine.createSession`; `createRuntime({ engine, settings, load, normalizer, waitForModel })` builds, attaches and registers the encoder strategy. Model loading stays host-specific: `load` and the `normalizer` provider come from the host (onnxruntime-web in `docs/webchat/ui/*-host.mjs`, onnxruntime-node in `scripts/lib/runtime-node.mjs`).
- **Modes** (`MODES`, `settingsForMode`): `rules`, `encoder` (no normalizer), `encoder+n1` (the shipped default, `DEFAULT_MODE`). `scripts/eval-dispatch.mjs` mode `Bp` takes its policy from the same factory.
- **Reports** (`scripts/eval-operational.mjs --mode rules|encoder|encoder+n1`): `config` carries `mode`, `policy` (the runtime settings), `hashes` (sha256 of the dispatcher onnx and of the normalizer encoder/decoder onnx, each next to the value in `meta.json`, with `match`) and the date. Files are versioned as `training/results/operational/<mode>-<dispatcher sha8>-<date>.json` (`-limitN` for partial runs). `training/results/operational/published.json` names the report of the shipped configuration (mode `encoder+n1`, whole set, models matching their meta.json) and is rewritten only by such a run. Results of the old evaluator are kept under `training/results/operational/superseded/`.
- **Latency** is reported in regimes under `latency`: `cold_start_ms` (engine plus models loaded, with `model_load_ms` per model), `first_message_ms` (first answer after loading), `steady_state` (the later messages) and `warm_cache` (a second pass over the first 20 messages with the validator's memo filled); `normalizer_propose` times the model calls alone.
- **Sharding**: `--jobs N` (scripts/lib/shard.mjs) runs N workers, each building its own pipeline through `openNodeRuntime` with the same mode settings (onnxruntime one thread per worker); totals are identical to `--jobs 1`. Cold start and model load are per worker (mean in `latency`, all in `latency.per_worker`); `warm_cache` and `normalizer_propose` are reported only with `--jobs 1`; sharded latency includes CPU contention.
- Test: `tests/runtime-config.test.mjs`.

**Routing key `needsState=<path>` (dialogue-set audit).** A pattern with `needsState=charts` is considered only while that path of its world's state is non-empty, or its world owns the active tab (`populated` in `routing.mjs`; the session states travel in the routing context as `context.states`, absent states always hold). It is for catch-all phrasings about the contents of a world ("how many legs?", "cross X off", "now bigger", "how much does it cost?") that otherwise answer "There is no chart yet" to every other world's question. `data.charts` uses it on every pattern whose action needs an existing chart and whose required words name no chart (293 patterns; creation, listing and download patterns and every pattern with a required chart word are unchanged); `user.profile` uses it for "delete everything". Tests that expect the "no chart" message first open the charts tab. Legend key `core.pattern.needsState` (atom).
