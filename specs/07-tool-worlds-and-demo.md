# 07 — Tool-use worlds and the hands-free browser demo

Goal: show PSys2 as an agent that *does things* with client-side tools, controlled entirely by voice or text, with no LLM: the same formalize → plan → execute → observe loop as every other world (vision §8, effectful operations), applied to an app. The end use cases are a chatbot embedded in a website, and a tool to talk with a document and create documents from the context of the conversation.

## 1. Principle: worlds own state, the host renders it
- Every tool world keeps its state in `ctx.state` (spec 04), a plain JSON object per world and session. Operations with `semantics=action` change it. Tests and the CLI check the state directly, so tool worlds are as testable as any other world.
- The **host** (the webchat page, or a website embedding PSys2) only renders state and executes **effects** that cannot be state (speaking a text now, copying to the clipboard, downloading a file, focusing an element).
- `ctx.effect(name, args)` queues an effect. `session.send()` returns, besides the usual reply fields, `state` (a snapshot of every world's state that changed) and `effects` (the queued effects, in order). The host executes effects only from its allow-list (capabilities); unknown effects are ignored and reported back.
- Observation: the host may report an effect's outcome with `session.observe({effect, ok, detail})`, which records a `core.observation` wire in the session (vision §8: observations confirm or refute expected effects).

## 2. Modal input
Some tools need raw text instead of commands (dictation). A world may export `interceptInput(ctx, text)` from `ops.mjs`. Before formalization, the dialog engine calls the interceptors of worlds whose state has `inputMode` set; the first that returns `{ handled: true, reply? }` consumes the message. Dictation uses this: while `docs.editor` is dictating, text goes into the document, except control phrases (`stop dictation`, `new paragraph`, `new line`, `undo that`, `delete the last sentence`).

## 3. Worlds
All are `status=fixture`, English, `formalization=rules`, with tests that assert state and effects.

### `ui.shell` — app control and voice settings
State: `{ activeTab: 'robot'|'editor'|'tictactoe'|'guess'|'hangman', speaker: bool, listening: bool, handsFree: bool, rate: number, language: 'en'|'ro' }`.
Commands: "open the editor", "show me the robot", "let's play tic tac toe", "go back"; "turn on/off the speaker", "speak slower/faster", "stop listening", "hands-free mode on", "switch to Romanian"; "what can I say here?" (moved to `ui.help`, section 8).

### `ui.avatar` — a DiceBear avatar (default tab, "Avatar")
The avatar is a robot, a person or an emoji drawn by the open-source DiceBear library (`@dicebear/core` 10.7.0, MIT, vendored in `docs/webchat/vendor/`; styles voxel-bot, open-peeps and moods, all CC0). **The library's style definitions become the world's legend**: `scripts/legend-from-dicebear.mjs` reads `docs/webchat/vendor/dicebear-styles/*.json` and generates `legend.sop` (type `ui.avatar.character` with `active`, `name`, `seed`; one type per character, `ui.avatar.robot|person|emoji`; one key per component and one `<color>Color` key per palette, each with an `ask`) and `lexicon.sop` (the variant names split into words, `angryWithFang` becomes "angry with fang"; last word singular; color names with `light_` and `dark_` variants; plus data lexicons that `ops.mjs` reads with `ctx.lexicon`, because it imports nothing). Generated files start with a `core.note` wire saying so; hand-written language lives in `patterns.sop`, `operations.sop`, `templates.sop`, `ops.mjs` and `lexicon.extra.sop` (synonyms and word lists, appended verbatim to `lexicon.sop` by the generator, since the loader reads fixed file names). The script is a small worked example of C1 building a legend from a tool's documentation.

State: `{ character: 'robot'|'person'|'emoji', name, seed, robot: { eyes, mouth, top, chest, colors: { body, accent, screen, glow, background } }, person: { head, expression, accessories, facialHair, mask, colors: { skin, clothing, headContrast } }, emoji: { face, eyes, mouth, cheeks, colors: { face, background } } }`. Component values are DiceBear variant ids (`none` hides an optional component: top, chest, accessories, facialHair, mask, cheeks); colors are 6-digit hex entries of the style's own palette. `initialState()` is the robot with a blue body.

Language layer (all by name and synonym, in the active character; a part that only another character has switches to that character and says so, a part that several others have is refused with a hint):
- Set a part: "give yourself visor eyes", "use the cyclops eye", "change your antenna to a dish", "wear a medical mask", "make your hair an afro", "give yourself glasses 3", "put on goggles" (synonym of visor). Unknown names are answered with the possible ones.
- Colors by common names, mapped to the nearest palette entry (and said when it is only close): "make your body blue", "light green screen", "paint yourself pink", "make your hair gray", "make your body a bit darker".
- Relative and random: "next eyes", "previous mouth", "different hair", "change your antenna", "reset your eyes", "surprise me" (a new seed is recorded in `seed`; the same seed always gives the same look), "change everything", "use the seed banana".
- Questions: "what can I change?", "what eyes can you have?", "what kinds of masks are there?", "what are you wearing?", "do you have glasses?", "what color is your body?", "what colors can your screen be?", "describe yourself", "what is your seed?".
- Character, name, expression: "become a person", "turn into an emoji", "be a robot again"; "your name is Robi"; "look happy", "look surprised", "be calm" (each mood maps to an open-peeps expression, to eyes and mouth of the emoji, and to eyes and mouth of the robot); "take off your mask", "take off everything", "reset yourself", "start over"; moments "wave", "dance", "nod", "shake your head", "spin" as the effect `avatar.animate { name }`.
Host (`docs/webchat/ui/avatar.mjs`): maps the state to DiceBear options (`<component>Variant`, `<component>Probability` for optional components, `<color>Color`), draws it large and centered with a cross-fade on every change, pulses while speech synthesis speaks, shows a short mood from the reply status (smile for supported, surprised for missing) without changing stored state, and lists the current parts in a caption. If the vendored files fail to load, the hand-drawn robot of `robot.mjs` is used.

### Tab follow (dialog layer)

When a world that declares a tab (manifest `tab=`, or one of the built-in tabs: avatar, editor, games) gives a **supported** answer to a sentence and that tab is not the active one, the dialog runs the existing `ui.openTab` action after the message (`interp.runAction`), so the host switches tabs from the `ui.shell` state as usual. Worlds without a tab (`ui.shell`, `core`, `ui.help`, `kids.*`) never trigger it, and neither do clarification (`missing`, `ambiguous`) or `unsupported` answers.

### Avatar: capability map (descriptors instead of refusals)

`ops.mjs` keeps a per-character capability map (`CAPABILITY`): when the active character lacks the part a command names (or lacks that variant of it), the command maps to the closest thing the character has and the answer says what was done; the character is offered only when nothing close exists.
- **Person**: eyes and mouth follow the expression ("make eyes sleepy" -> tired, "make bigger eyes" -> awe, "make eyes happy" -> smile, "make the mouth sad" -> solemn). Answer: "A person's eyes follow the expression, so I made it wide-eyed." "Make your eyes smaller/bigger" uses the same map (tired / awe). A mood word as an expression ("make your expression sad") maps to the person's expression of that mood.
- **Robot, emoji**: "expression" and "face" set eyes and mouth together from the mood table.
- **Kinds of person** (`lex.ui.avatar.gender`, with misspellings such as women, wmoan): man, woman, girl and boy set hair and facial hair presets (man: short neat hair and a short beard; woman: long hair; girl: twin buns; boy: short spiky hair), with an optional mood ("make a happy man"), and switch to the person when needed. Phrasing: the L6 shape `shape.ui.avatar.gender` ("make/transform the avatar a woman", "make it a girl", "make me a boy"), `pat.ui.avatar.gender.be` ("become a woman") and the tab-only `pat.ui.avatar.gender.make` ("make a happy man" while the avatar tab is active, so that the drawing tab keeps "make a man" for `art.draw`).
- Robot or emoji parts a person lacks (a robot's antenna, chest) keep the offer: "Say yes to become the robot".

### Avatar: offers and undo

`ui.avatar` never switches character silently. When only another character can do what was asked ("use the cyclops eye" as a person), the answer says so and sets `pending` with `inputMode: 'confirm'`; the next message is offered to `interceptInput`: "yes" switches and repeats the command, "no" stays, anything else cancels the offer and is read normally. Every change of the avatar pushes the previous look on `undo` (20 steps); "undo" / "go back to how you were" pops it.

### `docs.editor` — a professional document editor you talk to
The tab is a TipTap (ProseMirror) editor (MIT, vendored in `docs/webchat/vendor/editor/`, licences in `LICENSES.md`); the world owns the document and its language layer.

**State.** `{ title, titleMarks, titleAlign, titleSize, blocks, cursor, selection, focus, doc, stats, inputMode, history, future, nextId, dictBlock }`.
- `blocks` (the model the language layer works on; ids `b1`, `b2`… kept by the blocks created from the conversation, which also carry `from`, the source wire ids): `heading { text, level 1..3 }`, `paragraph { text }`, `quote { text }`, `list { items, style: bullet|numbered|task, checked? }`, `table { rows, header }`, `rule {}`; every block may have `align` (left|center|right|justify) and `marks`: `[{ at, from, to, type, attrs? }]` with `type` in bold, italic, underline, strike, code, highlight (`attrs.color` a hex colour, `attrs.name` its name), link (`attrs.href`). `at` addresses a text container (`'0'` for a paragraph, heading or quote; the item index for lists; `'row:col'` for table cells) and `from`/`to` are string offsets, so "the word milk" in a list item is a range.
- The title is a pseudo block (id `title`) with `title`, `titleMarks`, `titleAlign`, `titleSize` (-2..4).
- `doc` is **derived**: TipTap JSON (`doc` of a title heading with `attrs.title`, then one node per block, `attrs.blockId` = block id; lists map to bulletList/orderedList/taskList, tables to table/tableRow/tableHeader/tableCell, quotes to blockquote, marks to TipTap marks, alignment to `textAlign`). It is rebuilt after every operation (every exported operation is wrapped), so the tab renders it without conversion logic; `stats` (words, characters, sentences, tasks, tasksDone, readingMinutes…) is derived the same way. Old states (no marks, no list style, no heading level) are upgraded on the next operation.
- `selection` is `null`, `{ type: 'blocks', blocks: [ids] }` or `{ type: 'range', block, at, from, to, item? }`; `focus` is `{ id, n }` and asks the tab to scroll to a block (navigation); `cursor` is the index of the block last added or changed. Undo/redo snapshots hold title, title formatting, blocks, cursor, selection.

**Direct typing (decision).** The page is **read-only** (`editable: false`): all edits come through the world, so voice, typed commands, toolbar and tests share one path and every change is undoable and observable. Typing into the page is therefore not allowed, not even in dictation mode (dictated text arrives through the chat input and the dictation interceptor). The mouse may *select* (a drag, a double click on a word, a click on a block): the tab reports it with `host.setWorldState('docs.editor', { selection, cursor })`, which is state, not an edit, and later commands ("make it bold", "delete the selection") act on it. Clicking a task checkbox sends `check task N` / `uncheck task N`. Every toolbar button sends the equivalent voice command through `host.send` and mirrors the state (bold is active when the selection is bold).

**Language layer (references).** A reference phrase is resolved by `worlds/docs.editor/target.mjs` into blocks, text ranges or list items: `it` / `this` / `the selection` (the selection, else the block last worked on), `the title`, `the second paragraph`, `paragraph 2`, `the last heading`, `the list`, `the numbered list`, `the table`, `the quote`, `the first task`, `the task buy bread`, `the last sentence`, `the first sentence of the second paragraph`, `the third word`, `the word milk` (every occurrence, the first when selecting), `all paragraphs`, `everything`. Commands:
- Formatting: "make the second paragraph bold", "make the word milk bold" (also italic, underlined, strikethrough, code), "bold/italicize/underline the heading", "highlight the last sentence in yellow" (yellow, green, blue, pink, orange, red, purple, gray, cyan, brown), "make it not bold", "remove the bold from the title", "unbold it", "make the title plain", "clear the formatting", "add a link to example dot com on the word example" (also "make the word cat a link to …", "remove the link from …"; the spoken form `dot` is accepted because the sentence splitter ends a sentence at the dot of `example.com`), "make the title bigger/smaller" (title size steps; headings change level; also "make the second heading bigger"), "center the title", "align the first paragraph to the right", "justify …".
- Conversion: "turn the list into a numbered list / bullet list / task list", "turn this paragraph into a quote / heading 2 / a bullet list" (sentences become items), "turn the list into a paragraph" (one block per item). Marks follow their text.
- Blocks: "add a heading …", "add a paragraph …", "add a list with …", "add a numbered list with …", "add a task list with …", "add a quote …", "insert a line", "add a table with 3 columns: animal, legs, food" (or "with 4 columns and 3 rows"), "add a row: cat, 4, fish", "add a column weight", "set the cell in row 1 column 2 to 5", "delete the last row", "delete the column legs", "fill the table with sea animals" (cross-world ask to kids.animals: the header names map to animal keys, rows keep the source wire ids), "add a task buy bread", "check the first task", "uncheck task 2", "check all tasks".
- Selection and navigation: "select the second paragraph", "select the word cat", "select everything", "what is selected?", "clear the selection", then "make it bold", "delete the selection", "replace it with dog", "read the selection", "copy the selection"; "go to the end / the top / the table / the second heading / the word milk".
- Questions: "how many words / characters / sentences / tasks / rows / columns are there?", "how many tasks are done / left?", "which tasks are left?", "word count", "give me the statistics", plus the earlier title, paragraph and mention questions.
- Dictation ("start dictation" … "stop dictation", punctuation words, "new paragraph", "undo that"), undo/redo, read aloud, copy (also "copy the document as markdown/html"), download as text, markdown, HTML or JSON (the TipTap document), and the document creation from the conversation (task lists from kids.tasks become task lists with the source wire ids; reports about animals; what people have; `datagen.mjs` builds training data for all of it, spec 08).

**Tab (`docs/webchat/ui/tabs/editor.mjs`, plugin `editor`, replaces the built-in tab).** A Google-Docs-like page (paper, margins, shadow), a toolbar mirroring the state (undo/redo, style select, bigger/smaller, bold, italic, underline, strike, code, highlight with a palette, link, alignment, bullet/numbered/task lists, quote, table, line, table tools when a table is the working block, dictate, read aloud, copy, download menu), the selection or working block highlighted, a dictation indicator with the last words dictated, a word/character/reading-time/task-progress status bar and an outline of the headings (a click sends "go to the second heading"). If the vendored library fails to load the plain renderer (`ui/editor.mjs`) is used.

### Games (voice- or chat-controlled)
- `games.tictactoe` — state `{ board: 9 cells 'X'|'O'|'', user: 'X', turn, winner, level: 'easy'|'perfect' }`; moves by name ("top left", "center", "bottom right", "middle row left") or coordinates ("B2"); the system answers with its move (minimax for `perfect`); "new game", "who is winning?", "let me go second".
- `games.guess` — twenty questions where **PSys2 guesses the user's animal** by asking yes/no questions chosen from the kids.animals knowledge base (split the remaining candidates as evenly as possible); answers "yes", "no", "I don't know"; at the end it names the animal or admits defeat and asks the user to teach it ("it was a zebra" → a session fact). Shows the knowledge base and planning at work.
- `games.hangman` — a word from the kids.animals or kids.shapes lexicon; "is there an E?", "the letter R", "is it elephant?", "give me a hint" (a fact about the animal from the KB).

### Implementation notes (fixtures in `worlds/`)
- Cross-world calls: `ctx.request('ui.openTab', { tab })` brings a tab forward (every changing command of the avatar, editor and games does it); games are started by `ui.playGame` / `ui.newGame` through `ctx.request('ttt.new' | 'guess.start' | 'hm.new')`. Worlds export `initialState()` so the host can read every state before the first message.
- `ui.shell` adds `previousTab` to its state (for "go back"). `ui.avatar` effect: `avatar.animate { name }`. `docs.editor` adds `future`, `nextId`, `dictBlock`; blocks carry `from` (source wire ids); effects `speech.say`, `clipboard.copy`, `file.download { filename, mime, content }` (text, markdown, html, json). `games.hangman` keeps `word` in the state: render `masked` and show `word` only when `status` is `won` or `lost`.
- The tests of these worlds assert state and effects with `expectState` and `expectEffect` (spec 02).

## 4. The demo page (`docs/webchat/`)
- Layout: chat on the left (30% of the width, WhatsApp-like bubbles, timestamps, a status line showing listening/speaking), tabs on the right (Avatar — default, Editor, Tic-tac-toe, Guess the animal, Hangman). On narrow screens the tabs stack under the chat.
- Hands-free: a hands-free toggle (also by voice) keeps speech recognition running continuously; recognition pauses while the speaker is talking, to avoid hearing itself; push-to-talk with the space bar when the chat input is not focused; the microphone and speaker buttons of ADR-002 remain.
- Every voice or text command goes through the same `session.send()`; tab switching, avatar changes, edits and game moves all come from world state, so the whole demo is controllable without mouse or keyboard.
- A collapsible trace panel shows, per message, the matched pattern, the wires, the operations and the effects: the visible proof that no LLM is involved.
- Embedding: the same engine and host code can be mounted in another page as a chat widget (`mountPsys2(element, { worlds, tabs })`), which is the website-chatbot use case.

## 5. Third-party code
The host UI may use open-source libraries (for example for the avatar or games), vendored as single bundled files under `docs/webchat/vendor/` per AGENTS.md. Worlds and the engine never depend on them: game rules, avatar state and document model live in the worlds; libraries only draw.

## 6. Library-backed tool worlds (pluggable tabs)
Principle: pick a well-made, recognizable open-source library, let what the library can do become the world's legend (types, keys, closed value lists, operations), and spend our effort on the language layer.

- **Where the library runs.** If the library supplies *rules or semantics* that answers depend on (chess move legality, distances on a map, music theory), a copy is vendored inside the world (`worlds/<id>/vendor/<lib>.mjs`, one bundled file, imported relatively by `ops.mjs`) so C2 reasoning stays deterministic and testable in Node. If it only *renders or executes* (a chess board, a synthesizer, map tiles, a chess engine), it lives in the host under `docs/webchat/vendor/` and is reached through effects.
- **Tabs are declared by worlds** in `world.sop`: `tab=<id> tabTitle="..." tabAlias=<words_with_underscores> (repeatable) tabOrder=<n> tabKind=tool|game tabNew=<action> tabHint=<action> tabGiveUp=<action> tabUndo=<action>`; games may also declare `gameNew`, `gameHint`, `gameGiveUp`, `gameUndo` (spec 03 section 4: the shell's game controls emit these on the game tab). `ui.shell` discovers them (navigation by voice, "new game", "hint", "I give up", "what can I say here?") with no change to `ui.shell`.
- **Tab plugins in the host**: `docs/webchat/ui/tabs/<id>.mjs` default-exports `{ id, label, world, order, make(holder, host) -> { update(state) }, effects?: { '<effect.name>': async (args, { ui, host }) -> { ok, detail?, data? } } }`. The build lists them in `ui/tabs/index.json`; `app.mjs` loads them. `host` offers `send(text)` (a click becomes a typed command, so mouse and voice share the language layer), `speak(text)`, `state(worldId)`, `setWorldState(worldId, patch)`, `asset(path)`.
- **Observation loop** (vision §8): every effect carries its `world`; after the host executes it, `session.observe({ effect, ok, detail, data, world })` records a `core.observation` wire and calls the world's optional `onObservation(ctx, obs)`, which may update state, queue effects and return `{ reply }`. The host shows the reply as a new message. Example: chess asks for `chess.engine.bestmove`, the host runs the engine, the world plays the move and answers "I play knight to f6".

## 8. Contextual help (`ui.help`)
`ui.help` owns every help and capabilities phrase; the earlier help patterns of `ui.shell` and `kids.common` moved here (their other behaviour is unchanged). State `{ pos, lastUnparsed, lastHelp }`; it reads the app with `ctx.peek` (spec 04): the active tab and game from `ui.shell`, the game worlds' states, and `ctx.worlds()` for tab info and summaries. Worlds that declare a tab need nothing: their pattern examples and `summary` are used automatically.

| Phrase | Action | Answer |
| --- | --- | --- |
| "what can you do?", "what commands do you recognise / understand?" | `chat.capabilities` | the grouped summary sentence of all worlds |
| "help", "help me", "I am lost" | `ui.helpMe` | the open tab and what it is for, three examples |
| "what can I say here?", "what can I do on this tab?", "what should I say?" | `ui.help` | five varied examples from the active tab world (one first example per pattern, spread over the pattern kinds); repeating the request advances a per-world cursor, so the next five come, wrapping at the end |
| "give me an example" | `ui.help count=1` | one example (cursor advances) |
| "more examples", "what else can I say?" | `ui.helpMore` | the next five |
| "what does this tab do?" | `ui.helpAbout` | "The <Tab> tab lets you <summary>." plus the state of its game |
| "how do I play?", "what are the rules?", "how do I play hangman?" | `ui.helpGame` | rules and current state of the active (or named) game: hangman masked word and wrong guesses left, tic-tac-toe marks and turn, twenty-questions progress; on a non-game tab it lists the games |
| "how do I <X>?", "how to <X>", "what do I say to <X>?" | `ui.helpHow` | search over the pattern examples of all worlds: query words are stemmed, generic verbs (change, make, add...) weigh 0.4 and nouns 1, an example must contain a noun of the query, the open tab's world gets a small bonus; up to three examples ("how do I change the eyes?" gives examples of `ui.avatar`) |
| "why did you not understand?", "what did I do wrong?" | `ui.helpWhy` | quotes the last unparsed sentence, explains that no pattern matched the whole sentence, and suggests the closest commands |

Routing: help actions of `ui.help` without wildcard captures are tier 2b (meta) like the former `ui.shell` help; `how do I <X>` has a wildcard and routes by priority (6), so a world's own `how ...` patterns win.

**Did you mean.** `ui.help` exports the pure function `didYouMean({ text, worlds, tabWorld, recentWorlds, limit })`. When a sentence stays unparsed, the dialog layer (`src/dialog/index.mjs`, unparsed branch) calls it: each pattern example of every world is compared with the sentence by meaningful words (stop words dropped, plural stemming, typo tolerance of one or two edits); an example needs at least two matching words (one for a one-word sentence) and a score `2m/(|q|+|e|) >= 0.4`, plus a bonus of 0.2 for the tab world and 0.1 for recent worlds. At most two examples are returned. The reply becomes `I did not understand "..." . Did you mean "A" or "B"?` and carries the effect `chat.suggest { items }`; with no close example the old `For example: ...` answer stays. The dialog also records `{ text, world, suggestions }` as `ui.help` state `lastUnparsed`, which `ui.helpWhy` reads.

**Host.** `chat.suggest { items }` (allow-list of `docs/webchat/app.mjs`) adds the items to the bot message as clickable chips (`p2-example` buttons, the same as the welcome examples); a click sends the item as a typed command. Every help answer that lists examples queues it.

**Guessing game, answer correction (dialogue-set audit).** "Wait, I meant yes" / "sorry, I meant no" / "actually I meant maybe" while the game asks (`games.guess.correct.*`, action `guess.correct`, priority 15) changes the answer of the last answered question, recomputes the candidates from every answer given, and asks the next question; with no earlier answer it is an ordinary answer; outside a game it is "We are not playing twenty questions". The message-level correction phase leaves it alone (a lead word such as "wait" is no abandoned clause, spec 03 section 1c). "That's wrong" is no answer (spec 11 section 10): "no, that's wrong" is.
