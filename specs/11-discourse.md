# 11 - Discourse layer (dialogue continuity)

Implemented in `src/dialog/discourse.mjs`, hooked into `DialogSession.send` (`src/dialog/index.mjs`). Decision: ADR-006. Browser-safe, rule-based, no model.

## 1. Frames (last-frame memory)
After every request or question that the interpreter answered as `supported`, the session records a frame: `{ turn, world, patternId, kind, text, slots, args, op }`.
`text` is the sentence (a question keeps its `?`); `slots` are the pattern slots with class (lexicon id, `agent`, `number`, `words`) and character offsets inside `text`; `args` are the entries of the emitted wire with their legend key types. The newest 5 frames are kept (`session.discourse.frames`). Navigation, help and games (`ui.shell`, `ui.help`, `kids.common`, `games.*`) are never frames.

## 2. Ellipsis
A fragment is split into marker and content (`splitFragment`): leading markers (`and`, `now`, `what about`, `how about`, `the same for`, `same with`, `do the same for` ...), trailing markers (`too`, `as well`, `also`, `instead`), or a pure repetition (`again`, `once more`, `the same`). Marker-led fragments and repetitions are tried before normal routing; a message that no world parsed (one unparsed segment, at most 4 content words, not starting like a full sentence) is tried afterwards as a bare fragment.
Resolution, for each frame from the newest: copy `frame.text`, replace one slot by the content (typed slots first, rightmost first; a fragment that starts with the preposition before a slot only replaces that slot; a leading determiner is dropped when needed; free-text slots last), then run the normal rule formalizer restricted to the frame's world. The result is accepted only when it is one fully understood segment of that world and no free-text slot swallowed the replacement. Argument types are therefore checked by the slot classes themselves (agent for agent, place for place, colour or size word for the key it fits, object for the target). The segment carries `discourse = { kind: 'ellipsis', how, of, fragment, rewritten, slot, world, frameTurn }`; it is also in `trace.discourse.resolved` and `trace.segments[].discourse`.

## 3. Pending expectations
One expectation per session, valid for exactly one turn (`takePending` at the start of `send`):
- `fill`: an operation answered `status=missing` with `pending: { key, type }` in its envelope (and a clarification in `note`). The dialog stores `{ type: 'fill', world, patternId, text, key, expected, op, question }`. The next utterance is tried first as the filler: `text + " " + reply`, then the reply alone, in the pending world; accepted when fully understood by another pattern than the incomplete one. Otherwise the expectation is dropped and the utterance is routed normally (so a full command elsewhere is never blocked).
- `confirm`: a world opened a modal yes/no offer (its state has `inputMode`, e.g. the avatar's "Say yes to become ..."). It is recorded in the same structure (`trace.discourse.pending`) and answered by the world's `interceptInput` as before; it too lives one turn.
Worlds with a clarification: `art.draw` ("Draw" -> "What should I draw?"), `geo.map` ("Show me" -> "Which place should I show?"), `media.music` ("Play" -> "What should I play?"). The bare patterns have priority 11, below the chess draw offer and the tic-tac-toe "play", so on other tabs nothing changes; on the world's own tab the active-tab tier (ADR-004) selects them.

## 4. Coordination
`formalize` (spec 03 section 1c, verb ellipsis) also distributes the verb over a verbless noun phrase that another world read as a command of its own ("Give yourself round glasses and a beard": "a beard" is no hangman guess when `give yourself a beard` is read by the first clause's world).

## 5. Trace
`trace.discourse = { resolved, meta, pending, consumed, frames }` (`feedback` is added when set). `resolved` is the provenance of a formalized resolution (`kind`: `ellipsis`, `fill`, `repair`, `degree`); `meta` is the provenance of a direct answer or a rewritten sentence (`kind`: `cancel`, `repeat`, `explain`, `feedback`, `topic`, `list`, `list.start`, `list.end`, `reference`, `choice`, `choice.answer`, `offer`).

## 6. Actions and undo
After every turn the session keeps, for each turn that changed the state of a world (not `ui.shell`, `ui.help`), an action `{ turn, text, worlds, before, after, frames }` (state snapshots as JSON, newest 10). A world's own `undo` removes its action. The dialog undoes by restoring the snapshot, never through a world hook, so every world with serializable state is covered. An action is "the last action" for at most 3 turns.

## 7. Meta-dialogue (`Discourse.meta`, `src/dialog/meta.mjs`)
Runs after modal input and before ellipsis, for every utterance. Recognizers are closed English phrase sets (`classify`), shared vocabulary lives in `worlds/lang.common` (phrase groups `lang.yes`, `lang.no`, `lang.decline`, `lang.unsure`, `lang.cancel`, `lang.degree.*`, `lang.comparative`, `lang.shade`, `lang.size.*`, `lang.position.*`, `lang.ordinal.last`, `lang.lead.ask`; lexicons `lex.lang.colour`, `lex.lang.ordinal`) and reaches the layer as `interp.lang`, the same table that worlds see as `ctx.lang` (spec 04); `src/interpreter/lang.mjs` only builds the functions. `openConfirm` expectations are answered by the owning world's `interceptInput` through `ctx.lang.yesNo`, so "sure thing", "nah" and "never mind" work in every confirmation. The cancel recognizer is `lang.cancel`. A world set loaded without `lang.common` has no such vocabulary (every function answers "nothing"), so test fixtures that filter the world list keep it. A meta result is a direct `reply`, a `rewrite` that goes through the normal pipeline, or a formalized `pre` like an ellipsis.
- **Cancellation** ("never mind", "cancel that", "forget it"): drops the pending expectation and the list mode; it never undoes (only "undo" does).
- **Repeat** ("what?", "say that again", "repeat"): repeats the last reply (a repeat or explanation does not replace it). **Explain** ("what did you do?", "why?"): answers in plain words ("You asked me to make the red house twice as big, so I did it." plus the world's answer); the rule (`patternId`) and the operation stay in `info` and `trace.discourse.meta` only, never in the reply.
- **Feedback** ("that's wrong", "not what I asked"): apologises, offers undo (an `offer` expectation: "yes" undoes, "no" keeps), and sets `reply.feedback = trace.feedback = trace.discourse.feedback = 'negative'`. The webchat phrase log copies it into the record (`feedback`) and the JSONL export.
- **Topic return** ("back to the chess game", "where were we?", "continue"): finds the world by id, title or tab words (or the newest topic), reopens its tab (`ui.openTab`) and summarises its state with the world hook `summary(ctx)` (fallback: the last sentence and answer of that world).
- **List-entry mode** ("let's make a shopping list"): starts when `Add milk to my <list> list` is understood by some world (probe, no side effect); every following short non-command utterance becomes `Add <text> to my <list> list` and goes through the normal pipeline; "that's all" / "done" ends it and shows the list; a question, a command or "never mind" ends it. Unlike `pending` it repeats (`session.discourse.list`).
- **Repair** ("no, I meant the tree", "actually make it green", "not that one, the other one"): restores the state before the last action, then redoes its sentence with the content replacing the argument slot that fits (as ellipsis, section 2), re-targets with a reference ("the other one" = another referent of the same kind, described as "the second house"), or, when nothing is understood, restores the state and routes the utterance normally. "Not that one" alone undoes and asks "Which one did you mean?" (a `repair` expectation).
- **Degree** on the last frame: "a bit more" / "much less" insert or replace the adverb before the comparative or direction word of the frame ("Make it a bit bigger"); "much bigger", "even smaller", "twice as big", "the same size as the house" replace the degree word or build "Make <target> <degree>". The result must be understood by the frame's world.

## 8. References and choice questions
A world lists what can be pointed at with the read-only export `referents(ctx)` of its `ops.mjs` (called through `interp.hook`): `[{ id, kind, noun, words, attrs: { color, size, x, y ... }, salient, sig }]`. `art.draw` and `docs.editor` implement it; `summary(ctx)` is the companion hook for topic return.
`resolveReference(phrase, refs)` resolves attribute ("the red one"), size ("the big one"), position ("the left one"), ordinal ("the second one", "the last house"), "the other one" and the quantifiers "both", "all the trees", "each circle" (these last three are also understood by the worlds themselves). A single match is rewritten into a phrase the world already reads ("the red house", else "the second house"); several matches leave the sentence to the world.
**Choice**: a modifying command on a bare "the house" when several referents of that kind exist, none is in focus (`salient`: last changed or selected) and their colours tell them apart, is answered "Which one: the red house or the blue house?" (`choice` expectation, one turn). The reply is matched by attribute, ordinal, or quantifier ("the red one", "blue", "the first", "both"); anything else is routed normally.

## 9. Reference world hooks used by phase 2
`art.draw`: `referents`, `summary`, operation `draw.matchSize` ("Make the tree the same size as the house"). `docs.editor`: `referents`, `summary`. `kids.tasks`, `games.chess`: `summary`. `kids.arith`: when a person's start is unknown the count reports what was received ("Ana got 2 apples from Tom"), so "And Ana?" has an answer.

## 10. Gaps found by the dialogue set (DLG audit)
`training/eval/dialogues.jsonl` (395 dialogues after the audit; `scripts/eval-dialogues.mjs`) exposed these behaviours, now specified and tested in `tests/discourse-gaps.test.mjs`:
- **Repairable request.** `_repairable()` is the newest effectful action, or, when the newest understood request is newer than it (a question, a command that changed nothing), that request as a read-only pseudo-action (no worlds to restore). "No, I meant 7 times 5" after "What is 7 plus 5?" redoes the sentence ("OK." instead of "OK, I took that back."). A world whose state did not exist before the action (kids.arith creates its state on first use) is restored to empty (`_setState` with an undefined snapshot used to throw `"undefined" is not valid JSON`); a turn made only of questions never counts the lazy creation of a state as an action (so "that's wrong" after a question has nothing to undo). `explain` and `hasAction` use the same notion.
- **Ellipsis candidates** (`_candidates`, in order): (1) the fragment on its own when it is at least three words and a complete sentence of the frame's world ("and the one before that"); (2) the **run of same-class arguments** replaced as a whole when the fragment has at least two words ("and 9 minus 2" replaces "6 times 8" in "what is 6 times 8", it is not merged into "6 times 9 minus 2"; the same candidate serves repairs); (3) **adjacent typed arguments** (a number and an item: "3 balls") replaced as a noun phrase by a fragment with its own quantity ("and a kite", "what about 5 kites"); (4) the fragment repeating the **label** of a slot ("and section 1" after "summarize section 2": the label is dropped) or ending with it ("and the last section": label and slot are replaced together); (5) one slot, as before.
- **Pronouns** (`pronoun`, after ellipsis, for a sentence no world reads): "how many legs does it have?" after "what sound does a duck make?" replaces the pronoun (it, that one, this one, that animal ...) by the noun phrase of a typed slot of a recent frame, newest first; the result must be read completely by that frame's world. `trace.discourse.resolved = { kind: 'ellipsis', how: 'pronoun' }`.
- **Feedback** (`_feedback`). Outside games: as section 7; when nothing was changed the reply ("Please say it again in other words, or tell me what you meant") opens an `offer` without an undo, so "no", "not now", "no thanks", "no, leave it" answer it ("OK, I will leave it as it is."). Inside a game (`_activeGame`: game of the shell, tab, last world): chess and tic-tac-toe offer to take the last move back (`offer` with `accept: 'rewrite'`, `rewrite: 'undo'`; "yes" sends "undo" through the normal pipeline, so the world's own undo runs); the guessing game keeps its answers (the complaint is no "no") and explains how to correct one ("wait, I meant yes"); "no, that's wrong" and, while the game itself asked ("is it a dog?"), "that's wrong" stay answers of the game; hangman passes it on.
- **Topic return.** "back to the animal game" prefers `games.*` worlds when the phrase says "game" (ties: the newest topic); "where were we?" (review decision c, 2026-11-09) is **the most recent unfinished activity the user left for a digression** (not the last thing said, not the oldest topic): the newest topic that is not the world of the open tab, else the newest topic. "Back to X" is an explicit **return** only when X was already an activity of the conversation (`Discourse.lastTopic`); the unfinished activity is then X itself and stays so, on every later ask, until a navigation to another tab (a digression) happens. "Back to X" for a world never visited is a digression out of the current one, so "where were we?" goes back to the world just left (dlg.avt#040: editor, then "back to chess", then "where were we?" = editor; dlg.mpc#009: map, charts, "back to the map", "where were we?" = map; dlg.doc#045: story, drawing, "back to the story", "where were we?" = story). Tests: `tests/where-were-we.test.mjs`. The ASTRA A11 dialogue work keeps this definition. "Continue" / "carry on" always mean the newest topic. The tab is reopened as before. "Explain" with no frame (chat, navigation, games) answers from the last thing said in the newest world ("You said ..., so I answered it. What I answered: ...").
- **Backchannel.** A lone "lol", "haha", "hmm", "um", "uh", "ok", "okay", "wow", "huh" ... (`classify` intent `backchannel`), with no pending expectation and no game that asks yes/no, is answered "Mm-hm. Tell me what you would like to do, or say help." with status `unparsed` (nothing was understood or done): no world may read it as a name, a list item or a word. In list mode it is not an entry either. `meta.status` overrides the default status `supported` of a direct reply.
- **Lead-only abandoned clauses.** `selfCorrect` ignores an abandoned clause made only of lead words (wait, sorry, oops, actually, hmm, no, hold on ...): "wait, I meant yes" is a correction of the previous turn (discourse repair, a game's answer correction), not of a clause of this message (spec 03 section 1c).

## 11. D-FIX: dialogue headline per group (clarification, topic, explain, noise)
- **Clarification with a template.** An operation that lacks the subject of a question answers `status=missing` with `pending: { key, type, template, world }`: `template` completes the sentence with the next utterance (`<x>` is the reply, "how many legs does <x> have"), `world` is the world that reads the completed sentence (default: the world of the pattern). The shared operation is `chat.ask` (`kids.common`, arguments `q`, `template`, `world`); the kids worlds carry bare patterns named `pat.<world>.ask.*` ("How many legs?", "What day is after?", "What sound does it make?", "My name is"). The `fill` resolver tries the template first, then `text + reply`, then the reply alone. A sentence read only by an `.ask.` pattern counts as unread for `pronoun`: with a frame, "what sound does that one make?" is resolved against it and the clarification is asked only when there is nothing to refer to.
- **Pronoun = last answer.** "that" / "this" / "it" in an unread sentence is first replaced by the value of the newest frame's answer (`frame.value`) when it is a lexicon word of the new sentence ("what day comes after that?" after "5 days after Friday" is Wednesday): the slot of the result must be a lexicon class (`lex.*`) holding exactly that value.
- **Hesitation and connectives** (`ctx.lang.stripFiller`, `stripConnective`, groups `lang.filler` and `lang.connective` in lang.common). Leading fillers ("lol ok", "uhh", "hmm,") are dropped from the message before any world sees it, when something follows. A leading connective ("and", "also", "but", "so", "then") is dropped when nothing earlier could be continued by the fragment and the rest starts with a question word.
- **"back to X, request".** `Discourse._backTo`: when "back to X" is followed by a comma and a request and X names no world, the request is the message; its pronoun is replaced by "a X" / "the X" ("back to the spider, how many legs did it have?"). The past tense "did" is read like "does" in the kids.animals patterns.
- **Topic return.** Opening a tab (also by "let's play hangman") makes the world of that tab the newest topic (`noteNavigation`), so "where were we?" can go back to it; "back to X" that ends on another tab (also when a world pattern handled it: "back to the story") counts as an explicit return (a following "where were we?" stays there). The world hook `topicSummary(ctx)` (docs.reader, media.music) is preferred over `summary(ctx)` for the reply of a topic return.
- **Explain.** "what did you do?" means the newest turn that changed something (a request, not a question that happened to move the map) within six turns; "why?" and the other forms mean the newest turn. A turn answered by a modal interceptor (docs.reader questions and search, avatar dictation) leaves no frame, so the session keeps it as `icptTurn` and explains it the same way ("You asked me to search for father, so I did it. What I answered: ..."); a question is "answered", anything else "done".
- **docs.reader.** The stemmer maps plural and singular to one stem ("pebbles", "pebble"); the questions of the Documents tab accept a leading "and", "so", "ok", and "what happened to her in the end".
- **More clarifications.** The same `chat.ask` serves `docs.editor` ("Add a heading." / quote / task / paragraph: "What should the heading say?"), `ui.avatar` ("Call yourself.": "What should my name be?") and `media.music` ("Change the instrument."), always with a bare pattern `pat.<world>.ask.*`.
- **Ellipsis safety.** A marker-less fragment ("asdf qwer zxcv") is never text for a free-text (`words` / `rest`) slot; a marker-led fragment that starts like a command ("now lets draw a house" after "open the story") does not fill one either. `ui.help` frames are kept, so "and a list?" continues "how do I make a heading".
- **One-anaphora.** A fragment ending in "one" ("and the G major one?") is the frame with its last determiner-and-noun phrase replaced, "one" standing for the frame's last noun ("play the G major scale").
- **Repairs that change the kind of request.** "No, I meant the outline" first replaces a slot of the old request (slot candidates before the whole fragment), then, when no slot fits, reads the words as a request of their own (`how: 'restate'`: the old action is taken back first). "No, I meant <whole sentence>" (a sentence starter or more than five words) goes straight to the restated request.
- **Chat spellings and softeners.** `SHORT_TYPOS` also covers srch, nxt, bk, opn, mpa, fr, cn, dw; the recognizers of the meta layer and the pronoun resolver read them as the word. `lang.trailing` ("instead", "then", "now", "too", "also", "as well") is dropped from a command nothing understood with it (retry), and from a connective-led fragment no frame could continue ("and a heading Dairy too" is the heading "Dairy"). Feedback also covers "that's not helpful (at all)" and "that did not help".
- **docs.reader.** Statistics of a section ("how many words are in section 2", "how many words in that one"), "which section is the longest / shortest" (`docr.sectionExtreme`, the section becomes the one being read), "how long is it in words", and a search whose words are not in the document is spelled after it ("srch fr bred" searches "bread"). The aliases story, doc and document name the Documents tab for "back to the story".
