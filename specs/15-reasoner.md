# 15 — The reasoner host layer (sopworld), stage 1

Implementation: `src/reasoner/`, the vendored library `src/vendor/sopworld/` (0.6.1, see `src/vendor/LICENSES.md`), per-world `matrix.sop` + `fns.mjs`. Browser-safe. Tasks: SOPWORLD-1 and SOPWORLD-1b (worker-tasks). The numbers are in `worker-log.md`.

## Purpose
`sopworld` (https://github.com/ml-circuits-research/soplang-words-lib, MIT, same owner) is a general library for self-consistent worlds of SOP Lang wires: a schema with a type hierarchy, rules, denies, defaults, a sequence with states changed by events (fluents), aggregates, queries with a status, actions as transactions, retract and replace, abduction, explain, step budgets on every loop and a structural `fork()`. The user wants it to become the centre of the worlds, so that they share one representation and one reasoner. Stage 1 proves it on three worlds without changing any default behaviour. Stage 2 (after the user sees stage 1): the session memory and question resolution of `src/interpreter/` on the library, then more worlds.

## The switch
- **Engine level.** `createEngine({ options: { reasoner: 'ops' | 'matrix' } })`; without the option the environment variable `PSYS2_REASONER` (`ops` | `matrix`), then `matrix`. **User decision 2026-11-11: matrix is the default.** `ops` stays available as the fallback behind the same switch: with `ops` nothing of this spec is loaded (the library is not even imported), no session has a World, every file of a world behaves as before. With `matrix` only the worlds that opt in (below) are answered by the library; every other world takes its `ops` path in both modes. The library is imported lazily inside `createReasoner` (in the webchat: in the engine worker, never on the page's first-paint path).
- **Per world.** A world opts in with `reasoner=matrix` in its `world.sop` (key `core.world.reasoner`, default `ops`) and ships `matrix.sop` (and `fns.mjs` when it needs functions). A world that does not say so is never answered by the library, whatever the switch.
- **CLI and evaluators.** `--reasoner ops|matrix` (default `matrix`; `scripts/lib/reasoner-flag.mjs` sets `PSYS2_REASONER`): `src/cli.mjs`, `scripts/eval-operational.mjs`, `scripts/eval-dialogues.mjs`, `scripts/check-ro-replies.mjs`. Any other tool follows the environment variable.
- **Webchat.** Settings › Developer › Reasoner: `Matrix where available (default)` | `Operations (fallback)`. `settings.reasoner` defaults to `'matrix'`. **Settings version 4 (2026-11-11):** a saved `reasoner: 'ops'` of an older version cannot be told from the old default (the setting stores only the value), so every saved `'ops'` of a version below 4 is migrated once to `'matrix'`; an `'ops'` chosen afterwards is saved with version 4 and respected; an unknown value is `'matrix'`. It is read when the engine starts (it chooses which files of the worlds are loaded), so changing it restarts the engine worker from the last committed state (`engineClient.restart`).

## What the library gets
Built once per engine (`createReasoner(set)`), forked per session:
1. `worlds/core/mapping.sop` (data): three `core.schema.map` wires that let the library read our legends unchanged (`core.key`, `core.type`, `core.legend`; `closed=true` also means the world knows every instance).
2. The legends of the matrix worlds and of everything they import, in dependency order, as they are (`legend.sop`).
3. The knowledge bases (`kb.sop`) of the matrix worlds, and `@e.user core.agent` (the user is a built-in agent of every session).
4. The matrices (`matrix.sop`) and the action functions of `fns.mjs` (`export const fns`), registered as the library's `actions` (a registry of their own: an action named `add` does not replace the arithmetic, so no prefix is needed).

`matrix.sop`, `mapping.sop` and the library's own wires are read by the library's parser (SOP Lang v1.1: `?` is only a variable, a pattern is an ordinary `@id` wire, `#` comments are allowed); the files our parser reads (`patterns.sop`, `templates.sop`, `operations.sop`) have no comments. A matrix re-declares keys the legend already declares with `combine=intersect`.

## Matrix-mode extras of a world
`matrix.patterns.sop`, `matrix.operations.sop` and `matrix.templates.sop` are appended to the world's patterns, operations and templates **only** when the engine runs with `matrix` and the world opts in; templates go first, because the renderer tries the templates of a status in file order. An operation with `impl=matrix` has no function in `ops.mjs` (the validator accepts it). New phrasing follows ADR-007 (phrase groups, shapes).

## Session wires
`Session.add(wires)` tells the library every wire whose type its schema knows (not `core.question`, `core.request`, `core.answer`, `core.observation`). Our wires are serialized with short keys and parsed by the library. A wire the library refuses (a deny, a conflict) is recorded in `session.rs.refused` and the library stays as it was; our memory keeps the wire as before. `Session.clone()` forks the World (nothing is copied until one of the two changes), so dry runs, validation and snapshots never touch the original.

## Questions and requests
`Interpreter.resolve` asks the library when the question type belongs to a matrix world (the longest world id that prefixes it) or the request's action is declared by one; otherwise, and when the library answers `unsupported`, the operations answer as before.
- `world.query(wire)` / `world.act(wire)` -> our envelope (spec 04): statuses map 1:1 (`supported`, `conflicting`, `ambiguous`, `missing`, `unsupported`, `budget`); `refused` -> `conflicting` with `reason=precondition_failed`, the deny's `why` (it quotes the values) and, in `vars`, the keys of the wires it was decided on (`involved`) and its `bindings`; `no` -> `supported` with value `no`; `unknown` -> `missing`; `done` -> `supported` with the action's result fields; `unsupported` with a `reason` (a calculation that cannot be done) -> `unsupported` with `why`, without a reason -> the question is not the library's and the operations answer. `via` is `core.matrix`; `from` is the library's `from`. The library's soft constraints (`soft=true`, standing `core.issue` wires) keep an impossible statement and make every answer that rests on it `conflicting` with the reason.
- **Words around the numbers.** The envelope of a library answer has no prose. The matrix puts every number a reply needs on the answer wire (the keys its rules set with `core.on=`), and the library returns that wire as `supposed`; the owning world's `voice(ctx)` (exported by `fns.mjs`) only finds the words: `ctx.supposed` (the answer wire, flat), `ctx.env`, `ctx.where`, `ctx.issues()` (the standing issues with the wire they are about), `ctx.find(type)`, `ctx.name(id)`. There are no second queries. The existing templates are unchanged and read the envelope as before; `env.vars` are template variables, `env.why` is `{why}`.
- **A missing argument.** `core.action ... required=<key> ask.<key>="..." template.<key>="add <x> to my list"`: the library answers `missing`; the envelope carries `ask` and `pending = { world, key, template }`, so the discourse layer (spec 11 section 3) keeps the question open and the next message completes the command.
- **Mirrors.** `mirror=<type>` (repeatable, `core.world.mirror`) in `world.sop`: after a library answer, wires of these types are copied from the library's World to the session memory in our shape (a wire the action removed is retracted there), so worlds that read the memory (charts, documents) see what the matrix actions wrote, as they saw what `ops.mjs` emitted.

## Budget
One budget per turn. Every library call gets `{ steps: left }` where `left` is what is left of the turn's budget (`budget.remaining('sopworld')`); afterwards the steps it took, per library site, are ticks of the turn budget at `sopworld.<site>` (`match`, `chase`, `negation`, `aggregate`, `fluent`, `withdraw`, `validate`, ...). An excess ends the turn like any other site (`BudgetExceeded`); a library call that ran out answers `budget` and left the world as it was. The library's own loops carry ticks, and `tests/reasoner.test.mjs` runs its loop scanner on the vendored file; `tests/loop-guard.test.mjs` does not scan `src/vendor/`.

## One undo
The library is the only record of what was said. Nothing else holds state that could diverge from it:
- **State derived from the library.** Each matrix world exports `toState({ find, query })` (kids.tasks: `{ lists, counter }`; kids.shop: `{ money, purchases }`; kids.arith: `{ holdings }`). The host layer writes its result into the session state after every library change (telling a wire, an answer, a rewind), so the hooks (`referents`, `summary`) and the dialogue layer's snapshots read what the library says. Like the operations' state it comes into being when the world first answers or has something to say.
- **Marks.** `ReasonerSession.beginTurn(turn)` takes `world.mark()` at the start of every dialogue turn (a mark costs nothing until the library changes); `commitTurn(turn)` keeps it when the turn changed the library (`world.stamp`). The dialogue layer's action of that turn carries it (`act.rsMark`; a statement that changed the library is an action too, so "that's wrong" offers to take it back).
- **Taking back.** "undo that" (`ReasonerSession.undo`), the dialogue layer's `undoAction` ("that's wrong", "yes") and a repair ("no, I meant ...", `_repair`) all call `ReasonerSession.rewind(mark, session)`: library `rewind`, the dialogue wires the library no longer holds are retracted in the session memory, the state and the mirrors are derived again. `rewind` returns a function that puts it all back (a repair that finds no correction gives up with it). Without the matrix reasoner nothing changes: the saved state is restored as before.

## Stage 1 limits
- The library holds the facts of the three worlds; the other worlds keep their engines and state. The switch never touches a world without `reasoner=matrix`: the same messages give the same replies, statuses and state in both settings (`tests/reasoner.test.mjs`).
- The old operations are not removed, and `ops` stays the default.
- Kept in the host layer, not the library's job: reply wording (a/an, plurals, "costs" or "cost", "about", "from Tom"); the sentence for a zero divisor; which item to name when a price is missing (a lookup of the price wires); the text handling of kids.tasks (splitting "milk, eggs and bread", list names, what a named thing matches).


## Coherence in matrix mode (SOPWORLD-1b item 2 in both strategies)
The coherence measures of spec 11 section 12 hold when `reasoner=matrix`, through the library:
- **A statement that cannot be true is said, not acknowledged.** Every segment's statements are told to the library; `ReasonerSession.refuseFacts` then looks for a hard deny of the library on those wires or a new issue (a soft constraint, `core.issue`) that was not standing at the start of the turn. The words come from the world's `problem(ctx)` export in `fns.mjs` (`ctx`: `why` = the deny's or issue's own text, `issue`, `facts`, `find`, `query`, `name`), else from the library's text (a `why` may quote the values, `?m`). The reply is "That does not add up. <reason>" with status `conflicting`, and the library is rewound to the mark taken before the segment's first tell (what the segment told is gone from the library and the session memory; the turn is a no-op for undo when nothing else changed).
- **"No, ..." revises the last statement through the library.** `Discourse._correctFact` calls `ReasonerSession.retractFacts` (library `retract`: what followed from the facts goes too; refused when the library will not) and tells the corrected sentence as a new statement. "Undo" takes the correction back as one turn.
- **"Why?" is the library's explanation.** `Discourse._known(ids)` takes the told leaves of `explain(id)` for each wire the answer (or the world's `why` hook) rests on, oldest first, and quotes the user's own sentence of each (`core.source`), never back-translated; a told wire counts even when other facts changed its value (Tom has 5, then gifts and meals: all three sentences are named). A told wire without a sentence of the dialogue is the price list. English and Romanian use the same parts (spec 11 section 12).
- **Unknown amounts and starts.** The matrix of kids.arith answers "How many apples did Tom have at first?" with rules (the count a statement gave minus the sums of what came in and went out); "Ana gives him some" leaves a bound that `voice` says ("more than 5").
- **"Which list did you put it on?"** kids.tasks' entries carry `batch` and `assumed` (legend keys); `toState` derives `last` from them.

## SOPWORLD-1b: what the `ops` strategy does now
The coherence failures that were ours (unread sentences, "why?", impossible statements, ties, unknown start) are closed in the rules and the dialogue layer, so both strategies are measured on sentences they can read: see spec 11 section 12. The `ops` strategy keeps the `from` list of every answer and explains with it; its impossible statements are refused when told (so does the matrix now, above). New rules, phrase groups (`lang.quant.some`, `lang.quant.something`, `lang.then.now`) and replies are shared by both strategies; patterns whose reading differs from a matrix extra have a lower priority than the matrix extra, so the matrix reading still wins in matrix mode.

## Certainty in replies (SOPWORLD-1b item 4, matrix mode)
An answer that rests on a value of tier `default` or `guessed` says so once, after the answer, and the turn records it. Nothing of this exists in `ops`.
- **Defaults are applied.** After every `tell` the session completes the defaults the matrix declares (`world.complete({ defaults: true })`, budgeted like any library call), so "I buy the ball" (no count said: the pattern emits no `count`) becomes a purchase of 1 with `count=1` of tier `default`. "I buy a ball" says `count=1` and is told, not assumed; "three of them" revises the cell to told, and the assumption is gone.
- **What an answer rests on.** The library's `query` result has `rests`: the cells under the answer that are weaker than `derived`. The cells of tier `default` or `guessed` become `env.assumptions` (strings `<wire>.<key>=<value> (<tier>)`) and `env.assumed`, the sentence. The words of one cell come from the owning world's `assumed(cell)` in `fns.mjs` (`cell`: `id, key, value, tier, type, attrs, name`): a phrase ("1 ball"), or `null` for a default not worth saying (kids.tasks: an entry is `todo` until it is done); without the export the phrase is "<key> is <value>". Several cells are one sentence: "I assumed 1 ball and 1 pen." The sentence is added by `Interpreter.render` to a `supported` answer; it goes through the reply table of `src/translate/replies.en-ro.mjs` (`I assumed {t}.`).
- **Said once.** A cell that was said (per session, copied by `fork`) is not said again by a later answer; a value that was told since is no assumption.
- **The record.** `reply.assumptions` (all the cells of the turn's answers; absent when empty), `answers[].envelope.assumptions`, and `detail.assumptions` of the phrase log record (`docs/webchat/ui/phrase-log.mjs`).
- **Coherence runner.** `scripts/eval-reasoner.mjs` knows the hint `assumption_visible` (also `assumption-visible`): `true` = the last answer carries assumptions and says "I assumed" exactly once; `"once"` = across the dialogue exactly one reply says it; `"none"` = no turn rests on an assumption and none says it. Cases `coh.shop.11-13`.

## games.tictactoe on the matrix (SOPWORLD-1b item 5)
`worlds/games.tictactoe` says `reasoner=matrix` and `undo=ttt.undo` (key `core.world.undo`) and ships `matrix.sop`, `fns.mjs`, `matrix.{patterns,operations,templates}.sop`. The board on the tab, the reading of places, the computer's choice (win, block, center, seeded random; minimax at `perfect`) and the reply words are the world's, shared with `ops.mjs` (`fns.mjs` imports its tables and chooser: `placeIndex`, `chooseEasy`, `bestMove`, `findWin`, `intro`, `ending`). **`ops` is unchanged**: `ops.mjs` only exports what the matrix shares, and `placeIndex` is the place-reading part of `_move` moved out unchanged; `test-world games.tictactoe` passes under both strategies, and a whole scripted game says the same words in both (`tests/reasoner.test.mjs`) (`dlg.gms#016`, `#019` expect "took back" after a bare "undo").
- **The game is wires.** One `ttt.game` (user, level, seed) and one `ttt.move` per mark (`by`, `at` 0-8 row by row, `n` = moves before it). The computer's moves also say why: `why=win|block|center|random|best` and `line` (a string). `toState` derives the state ops.mjs keeps (`board, user, turn, winner, level, seed, last`) after every change, so the tab cannot show another game than the one the rules know; `ops`'s `history` has no counterpart (the library's marks do that).
- **Rules and denies in `matrix.sop`.** `ttt.turn by=X|O` (X after an even number of moves, none when the game is over); `ttt.free at=` (the legal squares: not taken, game not over); `ttt.won winner= how=` (three of one mark on a line fact `ttt.line`, or `ttt.resign` -> the other mark, `how=resigned`); `ttt.drawn` (nine moves, no winner). Denies, whose `why` is the reply: a square taken ("The center is already taken by you. Please pick another place." / "... by me ..."), a move out of turn ("It is not your turn."), a move after the game ended ("The game is over. Say \"new game\" to play again."). The words of the first are the same as ops.mjs's.
- **Actions** (`fns.mjs`, registered as `tttMove`, `tttNew`, `tttFirst`, `tttLevel`, `tttGiveUp`, `tttWhy`): a move is checked with `world.check({ wires })` (dry), refused as `unsupported` with the deny's `why` as the note (the status ops.mjs gives a refused move), else told, and the computer answers in the same transaction. Actions the matrix does not declare (status, describe, hint, last, count, who first) fall back to `ops.mjs`, which reads the derived state.
- **Undo.** `undo=ttt.undo` in world.sop: the host layer answers that request itself by `ReasonerSession.undo` (the library goes back to before the last turn that changed it: the move and the answer, a resignation, a level change), and the world's `undoWords({ before, after })` says what that was ("OK, I took back your last move and my answer. It is your move again." or "OK, I took that back."; nothing to take back: `missing`). Bare "undo" (the dialogue layer's "undo that", the same rewind) with the game's tab open says the world's words too (`ReasonerSession.undoAction`); off the tab it is the generic "OK, I took that back: \"center\"".
- **"why did you play there?"** (matrix-only action `ttt.why`, patterns in `matrix.patterns.sop`): the reason on the computer's last move ("I played top right because I could not win and did not have to block, so I took any free square." / "... because it completes the top row, so it wins the game." / "... because you were about to complete the left column there, so I stopped you." / "... because it is the best move: I looked at every way the game can go from here."); before any move: "I have not played yet."
- **Two small host changes.** An action another world asks for by name (`ctx.request`, here the music world's "Play B2" with the game open) goes to the library when it owns the action (`ReasonerSession.request`); a result with `openTab` brings that tab forward (`ui.openTab`), as `show(ctx)` did in ops.mjs.
- **Tests.** `tests.sop`: 13 tests `reasoner=matrix` (refusals with reasons, undo, why, resignation); `tests/reasoner.test.mjs`; `scripts/test-webchat-matrix.mjs` scenario `tictactoe` (the board of the tab after a refused move and after undo).

## Wordings that follow ops (2026-11-11, from the A/B experiment)
- **"What did you do?"** in matrix mode keeps the source sentence ("I worked that out from what you told me: ..."). A computed answer (a total) is worked out on a supposed wire that the library takes away again, so the answer's `from` is empty; `ReasonerSession._restsLater` forks the world and tells the supposed wire again when someone asks, and the told leaves of what the rules derived on the way are the sources (a price told again, merged into the older wire, is found through the library's `resolve`).
- **A purchase without a count** is acknowledged with what was bought and the assumption: "OK, you bought 1 ball. I assumed 1 ball." (`ReasonerSession.ackExtras`: the defaulted keys are added to the acknowledged wire). The assumption is not marked as said, so the first answer that rests on it still says it once ("You have 15 lei left. I assumed 1 ball."), as the coherence cases coh.shop.11 and coh.shop.13 expect.
- **Budgets.** Matrix-mode library calls are charged to the turn's step budget (`_charge`), as before; the lazy re-derivation above ticks `sopworld.explain`. With matrix as the default the ticks were re-measured (`scripts/measure-ticks.mjs --mode rules`, 7400 turns): the `sopworld.*` sites reach at most 5 880 ticks per turn (`sopworld.match`, p99 3 522), far below the 1 M `perSite` default they fall under, and every other site stays below its limit in `src/dialog/budget-limits.mjs`; no limit changes.
## Stage 2: more worlds on the matrix (user decision 2026-11-11: sopworld becomes the default)
Two generic host additions serve the worlds that read tables from other worlds:
- **Knowledge bases of the imports.** The library loads the `kb.sop` of every world a matrix world imports, not only of the matrix worlds (before: `kids.shop` only). `games.hangman` and `games.guess` import `kids.animals`, so its animals are wires of the library; an animal a game teaches is told to the library and is undone with it.
- **`ctx.host` in an action function.** `lexicon(id)` (the words of a lexicon, as `ctx.lexicon` in ops) and `view(ctx)`, an ops-shaped read-only context (`find`, `val`, `vals`, `lexicon`) over the library's `ctx`, with the values decoded by the legend as ops decodes them. A world's `fns.mjs` hands it to the functions it shares with `ops.mjs` (the word list, the hint facts, the animal profiles), so the tables are not copied.

### games.hangman on the matrix
`world.sop` says `reasoner=matrix` and `undo=hm.undo`; `matrix.sop`, `fns.mjs`. **`ops` is unchanged**: `ops.mjs` only exports what the matrix shares (`MAX_WRONG`, `NOT_PLAYING`, `wordList`, `facts`); `test-world games.hangman` passes under both strategies (137; matrix 154 with 17 matrix-only tests) and a scripted game says the same words, statuses and state in both.
- **The game is wires.** One `hm.game` (the secret `word`, the `seed` of the next choice), one `hm.ch` per distinct letter, one `hm.guess` per guess (`n`, `kind` = letter|word, `what`), one `hm.hint` per hint, `hm.giveup`. `toState` derives the state ops.mjs keeps (`word, masked, guessed, wrong, wrongLeft, status, hints, seed`) after every change, so the tab cannot show another game than the one the rules know.
- **Rules.** `hm.hit` / `hm.miss` (a letter named by an `hm.ch` or not; the whole word equal to `hm.game.word` or not); `hm.lives` = 6 minus the misses (a count); `hm.left` (letters no letter guess named yet); `hm.over how=won|lost|giveup` (nothing left hidden, the word guessed, no lives left, or the player gives up).
- **Denies** (`why` is the reply): a guess when no game is on or after the game ended ("We are not playing hangman. Say \"play hangman\" to start.", status `missing` as in ops), the same letter twice ("You already tried ?c."; the action says "You already tried E." with the masked word and the status `supported`, as ops does). A guess is checked with `world.check` before it is told.
- **Actions** (`hmNew`, `hmLetter`, `hmWord`, `hmHint`, `hmGiveUp`): the seeded choice of the word, the hints and the sentences are the world's (the same words as ops.mjs). `hm.status` stays in ops.mjs and reads the derived state.
- **Undo** (the matrix adds this): bare "undo" with the hangman tab open takes back the last turn that changed the game: a guess ("OK, I took back your last guess. The word is as it was before."), a hint, a give-up (the game is open again), a new game (the old game is back). Nothing to take back: the dialogue layer's "There is nothing to undo.". In `ops` there is no undo for hangman.

### games.guess on the matrix
`world.sop` says `reasoner=matrix` and `undo=guess.undo`; `matrix.sop`, `fns.mjs`. **`ops` is unchanged**: `ops.mjs` only exports what the matrix shares (`FEATURES`, `readAnimals`, `truth`, `pickQuestion`, `factOf`, `slug`, `an`, `words`); `test-world games.guess` passes under both strategies (118; matrix 130 with 12 matrix-only tests) and a scripted session (a solved game, a corrected answer, a clue, a taught animal, a game that ends in "I give up") says the same words, statuses and state in both.
- **The game is wires.** `guess.game` (`max`), one `guess.animal` per animal the game started with (`name`, `i`), `guess.out` for every animal an answer, a clue or a wrong guess took out (`how` = ans|ev|rej), `guess.ans` per answered question (`n`, `feature`, `value`, `text`, `answer`), `guess.ev` per clue the player volunteered, the open question `guess.q` or the open guess `guess.try`, `guess.learn` (the game waits to be taught), `guess.solved`. `guess.learned` (name, `trait="feature=value"`, `not="feature=value"`) keeps what was taught from game to game; the animal itself is also told as a `kids.animals.animal` wire of the library, which the next game reads like any other animal (and undo takes back).
- **Rules.** `guess.cand` = the animals of the game that are not out; `guess.tally` (`count` asked, `left` = `max` minus the count); `guess.phase p=asking|guessing|learning|done` from the open question, the open guess (not once solved), the wait for a name, the solution. `toState` derives the state ops.mjs keeps (`phase, candidates, asked, count, max, current, guess, rejected, solved, learned, evidence`).
- **Denies** (their `why` is the reply, status `missing` as in ops): an answer when no game is on, the game is over, the game waits for the name, or "maybe" / "I don't know" to my guess; a clue (`guess.clue`) outside a question; giving up (`guess.quit`) outside a game; naming the animal (`guess.named`) when no game was played. The probes are checked with `world.check` before the action tells anything.
- **Actions** (`gsStart`, `gsAnswer`, `gsCorrect`, `gsReveal`, `gsGiveUp`, `gsEvidence`): the choice of the question (the most even split), how an answer or a clue narrows the animals (`truth`, shared) and the sentences are the world's; `guess.why`, `remaining`, `count`, `repeat` and `hint` stay in ops.mjs and read the derived state. A library action receives its arguments as tokens (a string keeps its quotes): `fns.mjs` unquotes them.
- **Undo** (the matrix adds this): bare "undo" with the game's tab open takes back the last turn that changed the game: an answer ("OK, I took back your last answer. I am asking that question again: ..."), a clue, a lesson ("OK, I forgot the animal you taught me.") or a new game. Nothing to take back: "There is nothing to undo." (the dialogue layer). ## Stage 2: session memory on the library (user decision 2026-11-11: matrix is the default; stage 2 started)
Goal: the library is the one record of what a session was told, for **every** world, and everything that takes a statement back or asks what an open question refers to goes through it. `--reasoner ops` is untouched: no World, no library import, the `Memory` and the dialogue layer's snapshots as before.

### Design
- **One World per world, not one per session (user decision 2026-11-11, section "One instance per world" below).** The earlier target (one World per session holding the legends of every world) is withdrawn: it measured too slow (2026-11-11: session creation 1.8 -> 23.6 ms, matrix-world turn p50 11.6 -> 75 ms, because every dry run forks and the first write after a fork copies the whole World) and it contradicts what a world is. A session holds one library World per world that was used, created on first use. (The grouping below, "The conversation instance", refines this: worlds that talk about the same people and things share one instance; the target "one World with every legend" is not wanted and is not built.)
- **Memory stays the reader's view.** `Session.memory` (`src/interpreter/memory.mjs`) remains the structure the hooks, referents (`it`, `them`), follow-up questions and the renderer read; it is no longer the only place the wires live. The two cannot diverge on undo because the library drives it: `ReasonerSession.rewind` retracts in the memory every dialogue wire the library no longer holds.
- **Undo for every world through `mark` / `rewind`.** `beginTurn` takes the mark for every turn and `commitTurn` keeps it when the turn changed the library; for every turn that told a library fact. "undo that", "that's wrong" + "yes" and a repair rewind the library; the wires of the undone turn leave the memory (before stage 2 the wires of a non-matrix world stayed in the memory after an undo and only the state was restored). **State of a world without `toState`** (the engine-heavy worlds keep their engines) is still restored from the dialogue layer's snapshot (`act.before`) by the same call (`Discourse._back`, and the "undo that" branch), because it is not derived from the library; a world with `toState` is derived as in stage 1. "Undo that" does not take back an older library turn when a newer action of a world without library state is what "that" means.
- **Question resolution (plan, next slices).** What an open question refers to and which argument is missing move to library queries in this order: (1) missing-argument questions of every world's operations (`required=` / `ask.<key>` on `core.action`, today only the matrix worlds' actions); (2) referents (`it`, `them`: the latest wire of a type, `core.select=latest`, already used by `shop.revise`) read through `world.query` instead of `memory.find` + sort by `core.seq`; (3) stale facts (a fact whose value a later one replaced) through the library's `resolve` / fluent states instead of the memory's retraction marks. Each slice is behind the same switch and keeps the memory read as the fallback until the A/B experiment shows no difference.
- **The engine-heavy worlds** (chess, diagram, documents, music, charts) keep their engines; they move only their state and validation, when they get a `toState` and a `matrix.sop`.

### Cost and limits
- Telling a wire costs one library `tell` (one parse of a serialized wire and its schema check); no wire is mirrored back per turn (`syncTo` only walks the `mirror=` types and the worlds with `toState`). The turn times before and after are in `worker-log.md`.
- Per-turn budget as before: the tells are charged to `sopworld.*` sites.

## One instance per world (user decision 2026-11-11)
"Why do we call them worlds if we combine them all?" A session no longer has one library World holding the facts of every matrix world. It has **one World instance per world, created lazily**, and worlds are isolated: kids.shop's purchases are not in kids.arith's World and a rule of one world can never fire on the facts of another. Worlds are combined only when it really makes sense, by an explicit composite world, never implicitly.

> **Superseded in part (WORLDS-APART, 2026-11-11):** the sections below describe one instance per world; the worlds in `session.conversation`'s `compose=` share one instance, and the games stay one each. Read "instance of a world" as "instance the world lives in" (`reasoner.instKey`).

### Engine and session
- **Base per world, built once per engine, on first use.** `reasoner.baseOf(id)` builds the base World of a matrix world: `worlds/core/mapping.sop`, the legends of the world and of its imports (dependency order), their knowledge bases, `@e.user core.agent`, the world's own `matrix.sop` and its own `fns.mjs` (the library's `actions` registry of that World holds only that world's functions). A world's imports are loaded into **its own** instance: games.hangman and games.guess each hold their own copy of the kids.animals knowledge base, so an animal guess teaches is a fact of guess's World. `reasoner.problems` is filled as bases are built; `reasoner.buildAll()` builds them all and returns the problems (tests, `test-world`).
- **Instance per session, on first use.** `ReasonerSession.insts` maps a world id to `{ id, world, completedAt }`. An instance is created (a fork of the base: nothing is copied) when the session first tells it a wire, asks it a question or a request, or when the world's own undo needs its state. A session that never used a world has no instance of it and no state of it (`toState` of an unused world is the empty state, `emptyState`, read from the base). A session that fresh is as small as before the matrix: creation allocates no World.
- **Routing.** A wire of the dialogue is told to the instance of the world that owns its type (the longest world id that prefixes the type: `kids.shop.price` -> kids.shop). A question or request goes to the instance of the world that owns its type or action (as before). Nothing is told to a World whose schema does not know the type (`reasoner.knowing(type)`: the matrix worlds whose imports include the owner of the type).

### What is shared, and how
Only what several worlds really have in common, which today is `core.agent` (the user, named people: kids.arith's rules read `e.tom` as an agent) and whatever other `core.*` / `kids.common` type a session wire has. There is **no combined instance**; instead the few shared wires are **copied into the instances that know their type**:
- A session wire whose type is known by more than one world, or whose owner is not a matrix world (`core.agent`), is told to every existing instance that knows it **and kept in the session's shared log** (`sharedLog`, small). An instance created later replays the log (only the wires its schema knows) right after it is forked from the base.
- The user (`@e.user core.agent`) is in every base, so it needs no copy.
- An imported kb is not shared: each world's instance loads it from its import, so the worlds cannot disturb each other (what guess learns about animals does not reach hangman until the kids.animals world itself is on the matrix and tells it; then it is told to every instance whose schema knows `kids.animals.*` by the rule above).
The instances therefore cannot diverge on a shared wire except by an undo, which rewinds every instance the turn changed (below).

### The session timeline and undo
- `beginTurn` marks every existing instance (a mark costs nothing until the instance changes) and notes the shared log's operation counter. `commitTurn` keeps the turn when some instance changed (its `world.stamp` differs) or the shared log did; the entry is `{ turn, mark, worlds, said }` where `mark` = `{ marks: Map(world id -> { mark, birth? }), ops }` holds the marks of the instances that changed, and of the ones created in the turn (`birth`: rewinding one is a rewind to the fork of the base and a replay of the shared log up to `ops`).
- "undo that", "that's wrong" + "yes" and a repair rewind the instances the turn changed, and the shared log with them (`ReasonerSession.rewind(mark, session)`); the dialogue wires no instance holds any more leave the session memory; the derived state and the mirrors are computed again. `rewind` still returns the function that undoes it. A world's own `undo=` action (hangman, guess, tic-tac-toe) is answered by the same call and takes back the last turn that changed anything, whichever world that was, in the words of the world that turn concerned (next section).
- A statement that cannot be true (`refuseFacts`) takes back the instances the segment touched, to the marks taken before the segment's first tell into each (an instance created by the segment goes back to its birth).
- `retractFacts` ("No, ...") retracts in every instance that holds the wire and, for a shared wire, in the log.

### why, refusals, assumptions, state, dry runs
- **why / explain.** `leaves` and `explain` ask the instance that holds the wire (the one that gave the last answer first). A shared wire is a copy in that instance, so the chain through it needs no other instance.
- **Refusals** (`check` / `issues`): the issues of every instance are read (an issue is identified by instance and id); the world's `problem(ctx)` hook is given the instance of the world that owns the statement. **Assumptions** (`rests` of a result, `ackExtras`) read the instance that answered or the one of the statement's world. `name(id)` reads the instance in use, then the others.
- **toState** of a world reads that world's instance only; `session.state[id]` is derived after every change of that instance.
- **Dry runs.** `ReasonerSession.fork()` forks the existing instances (a structural fork, no copy); only an instance that is written afterwards, by the dry run or by the original, pays the copy (the library's copy-on-write), and it pays for the size of that one world, not for the size of all of them. A dry run that reads one world therefore costs what that world costs. `_restsLater` forks the instance that answered. `adopt` (user.profile) reads and writes the world's own instance only; its `written` map is per world id as before.
- **Mirrors** (`mirror=`) are read from the instance of the world that declares them.

### The conversation instance (user decision 2026-11-11, WORLDS-APART)
Worlds are combined only when they really share facts, and only by declaration. The grouping that is declared today (`worlds/session.conversation/world.sop`, a composite world with `compose=` and no rules of its own):
- **One conversation instance per session** holds the facts of the user, the people named and their names (`core.agent`), `kids.common`, `lang.common`, and the worlds **kids.shop, kids.arith, kids.tasks, kids.time, kids.animals, kids.shapes and user.profile** (its tab reads the user's facts from there). They talk about the same people and things: "Ana has 5 lei, she buys ..." and "how many does she have now?" see one another's facts, and the arithmetic rule that counts what the user buys in the shop (`arith.shop`) fires in the same World, so `kids.arith` no longer needs `reads=world.kids.shop` (removed).
- **One instance per game** (games.tictactoe, games.hangman, games.guess), each its own World, sharing nothing: a pet told in the conversation is not in hangman's World and a move is not in guess's. What a game's instance gets from outside is only the agents (the user's name, the people named), copied by the shared log.
- **The tab worlds with engines** (chess, draw, charts, map, documents, music, diagram, avatar) stay as they are; each gets its own instance only if it moves to the matrix.
- **Every instance can read the conversation's agents**, read-only: `core.agent` wires are told to every instance whose schema knows the type and replayed into one created later; a tab never writes into another instance (a type declared by a matrix world is told to the instance of that world only, `route(type).shared` is true only for types no matrix world declares, such as `core.agent`).
- **Mechanics.** `compose=` names the worlds that live in the composite's instance. `reasoner.instKey(worldId)` is the instance a world lives in: the composite that names it, else itself. The base, the instance (`ReasonerSession.of/_inst`), routing, the state (`toState`) and `syncTo` all go through it; `ownerOfType` / `ownerOfAction` and the hooks (`voice`, `undoWords`, `adopt` ...) stay per world id. A composed world has no instance of its own. The composite is built from the legends, knowledge bases, matrices and functions of the worlds it names; if two of them used the same rule or function name they would collide, so names stay prefixed per world (they are).
- **Nothing is automatic.** A world is in the conversation instance only because `compose=` in `session.conversation/world.sop` says so; a new world gets its own instance until that file (or another composite) names it.

### The session timeline and undo across instances (UNDO-1)
- The timeline (`ReasonerSession.turns`, the last 40 turns that changed anything) is one list across the instances; an entry is `{ turn, mark, worlds, said }`: the marks of the instances it changed, the worlds it concerned (the worlds whose types it told and the games whose own instance it changed) and the sentence the user said.
- **"undo" takes back the newest entry, whichever world it belongs to, and says which** (`ReasonerSession.undoLast`): in the words of the world the entry concerned (`undoWords` over its state before and after: "I took back your last guess", "I took back the new game", "I took back your last move and my answer") or, when that world has no words or the state cannot tell what changed, `OK, I took that back: "<what the user said>".` An undo that says it took something back names it and changes something; a world's `undoWords` returns no value when its state did not change in a way it can tell.
- The dialogue layer takes "undo" through the timeline first, so a game with nothing left to take back falls through to older turns of other worlds (a purchase before a hangman game is undone by the fourth undo). A game's own `undo=` action (a tab button) is answered by the same call. When the timeline is empty after undos, the reply is `There is nothing more to undo.`; with no undo yet the world's own wording stays ("There is nothing to undo yet: no guess has been made.").
- "undo" also is not cut off by the age of the history while the user is undoing: the history is walked back one entry per undo (a run of undos); outside a run an entry older than six messages is left alone, as before.

### Composite worlds and `reads=` (explicit; `compose=` is used by session.conversation, `reads=` by no world today)
`compose=world.<id>` (repeatable, `core.world.compose`, written like `imports=`) in the `world.sop` of a world that says `reasoner=matrix` and ships a `matrix.sop` of its own makes it a **composite world**: its instance is built from the legends (with imports), kbs and matrices of the worlds it names plus its own, with the functions of all of them. Rules:
- the composed worlds live in the composite's instance (they have none of their own): their wires, questions and actions all go to it (`instKey`), and their rules meet there on the facts they share;
- a composed world's own base is never built alone (`baseOf(id)` is the composite's base);
- nothing is composed implicitly: a world that only imports another one gets that world's legend and kb, never its matrix. `session.conversation` (above) is the one composite; `tests/reasoner.test.mjs` and `tests/reasoner-worlds-apart.test.mjs` check it.

`reads=world.<id>` (repeatable, `core.world.reads`) is the light form: the world's instance holds the legends and knowledge bases of the named worlds (so the types are known and their wires are copied in through the shared log) but **not their matrices or functions**. It is for a rule that only reads another world's facts. No world uses it now: `kids.arith` used to say `reads=world.kids.shop` for the rule that counts what the user buys in the shop as a buy (`arith.shop`); the two worlds are in the conversation instance, so the line is gone. The feature stays for a world outside a group that only needs another world's facts.
The loader reads the keys (`World.compose`, `World.reads`), the reasoner's `schemaWorlds(id)` / `matrixWorlds(id)` implement them, and `tests/reasoner.test.mjs` patches a loaded world to test `reads=`.

### Behaviour and cost
Replies, statuses and state are unchanged for the ten matrix worlds (kids.time, kids.animals and user.profile included) (`scripts/dump-turns.mjs` before/after on the operational, dialogues, coherence and gold sets; the differences, if any, are listed in `sop_world_status.md`). The turn times (`scripts/bench-reasoner.mjs --reps 3`) before and after are in `sop_world_status.md`.

## docs.editor and docs.reader on the matrix (user decision 2026-11-11: every world moves to the library)
The two document worlds are engine-heavy: the **text engine stays in code** (`ops.mjs`, `model.mjs`, `target.mjs` for the editor; `analyze.mjs`, `text.mjs`, `lang.mjs` for the reader: editing operations, parsing, marks, rendering, search, BM25, entity and event extraction), because none of it is state or validation. What moves is the **document state** and its **validation**: both worlds keep running their operations on the session state (`adopt` / `toState`, as `user.profile`), and the world's own library instance is the record. `ops` mode is unchanged byte for byte (no instance, no `guard`, the world's own history).

### Host additions (generic, optional exports of `fns.mjs`)
- **`guard({ action, args, state, check, find })`** (`ReasonerSession.guardRequest`, called by `Interpreter._resolveRequest` before the operation runs). The world asks its rules whether the request's target exists: `check({ wires })` is a dry run of the world's rules on its own instance (the wire is never kept). A violation is the refusal: `missing` with the rule's reason as the note and `why`. The instance first takes over what changed the state since (`adoptState`).
- **`redo=<action>`** in `world.sop` (next to `undo=`; `core.world.redo`): the host keeps what each `undoAction` took out (the function `rewind` returns) and puts it back; a turn that changes the library empties it. **`undoAction(world, session, n)`** takes `n` steps (`arg.n` of the request, "undo twice") and says it with `undoWords({ before, after, steps })`; `redo` calls `undoWords({ before, after, redo: true })`.
- **`isView({ before, after })`**: a step that only moved what the user looks at (cursor, selection, dictation mode) is not counted by "undo": the editor's history only ever held edits, and the selection is a wire of the instance, so without this "undo" would first undo the selection.
- While a world's modal input is on (dictation), "undo", "undo that" and "scratch that" are not offered to `interceptInput` in matrix mode: they take the library's last step back like everywhere else.

### docs.editor
`world.sop`: `reasoner=matrix`, `undo=doc.undo`, `redo=doc.redo`, `source="the document"`; files `matrix.sop`, `fns.mjs`.
- **Wires.** `docs.editor.doc` (title, cursor, number of blocks, and one JSON for everything else the engine keeps: title marks, size and alignment, next block number, dictation, focus), `docs.editor.block` for each block (`bid`, `n` = its place, `kind`, `level`, `chap` / `sec` for a heading that starts a chapter and its number, `cols` / `minc` for a table, `json` = the block with its marks, items, rows), `docs.editor.sel` (type, the selected blocks, JSON), `docs.editor.gone` for every block that was taken out (a deleted chapter keeps the number it had). A document nobody wrote in has no wires and the initial state. `toState` derives the whole state the engine and the tab keep (`doc` and `stats` through `finish` of `ops.mjs`); `history` is only a count (`histN` in the document wire; the tab shows "N undo steps") and `future` has one entry for each undo that can be taken back (`toState` gets `redo`, the number of redos the host holds for the world): the steps themselves are the library's.
- **Derived by rules.** `docs.editor.have`: how many headings, paragraphs, quotes, lists, tables and chapters there are.
- **Denies.** A heading has a level from 1 to 3; two blocks never share a place; the cursor is inside the document; the selection names blocks that exist; the rows of a table have one length (invariants the engine keeps; the host refuses a state that breaks them and goes back to before). **Targets** (`guard`): "read the third paragraph", "delete the fifth paragraph", "select the second list", "go to the third heading", "delete chapter 2", also by the `kind` / `ord` / `n` arguments of the patterns, are asked as a `docs.editor.want` wire: "There is no third paragraph; the document has two." / "There is no quote in the document." / "That section is already deleted." (chapter number of a gone heading, asked again) (all `missing`, as the engine's own refusals). A heading that says "Chapter 3" is chapter 3 and is left to the engine. Anything else a request names ("it", "the word milk", "the last sentence") is resolved by the engine as before.
- **Undo and redo** through the instance: "OK, I put back the list you deleted.", "OK, I undid it: the paragraph you added is gone.", "OK, I took back your change to the paragraph.", "OK, the title is "Plans" again.", several edits in one sentence, "(2 changes)"; redo: "OK, I added the list again." / "OK, I deleted the paragraph again."; "There is nothing to undo." / "There is nothing to redo.".
- **Stays in code, and why.** All editing operations, reference resolution (`target.mjs`: ordinals, phrases, "it", words, sentences, sections), marks and formatting, conversion, tables, statistics, search, reading aloud, copy and download, dictation, creating documents from other worlds' facts (`fromList`, `report`, `holdings`: they read the session memory). They are text handling, geometry of a string, or rendering; the library has no string operations.
- **Gains over `ops`.** The reasons for a target that does not exist and for a section that is gone; the invariants; undo by what it did (and "undo twice" over exactly the edits); redo is exact (the library as it was); the document is a record other rules can read.

### docs.reader
`world.sop`: `reasoner=matrix`, `source="the documents you opened"`, `untold=` for the six wire types `toSop` emits; files `matrix.sop`, `fns.mjs`; **no `undo=`** (the generic "undo that" is the library's, with the world's words).
- **Wires.** `docs.reader.shelf` (which document is open, how many there are, the rest of the state as JSON: the last answer for "tell me more", the section being read, what was wired, the tab's flags), `docs.reader.open` for each document (`did`, `n` = its place, title, words, sentences, paras, sections and `json` = the analysis the engine works on), `docs.reader.focus` (where the reader is: the document, the highest sentence number cited, how many are cited, JSON), `docs.reader.search` (document, the hit the reader is at, how many hits, JSON) while a search is on. A reader nobody changed has no wires and the sample open, as before. `toState` derives the whole state `ops.mjs` keeps and the Documents tab renders; the tab's own state patches (a dropped file) are taken over by `adopt` at the next request or turn.
- **Facts of the text stay in the session memory** (`untold=docs.reader.document|sentence|entity|event|said|relation`, new `core.world.untold` key): the engine reads sentences, entities and events from `state.docs`, the answers cite them by wire id from the memory (`why?`, the highlights), and telling 250 wires per document to the instance cost about 1 ms per turn (the first measurements) for nothing the rules use.
- **Denies.** State: the open document is on the shelf; a cited sentence is in the document; the search is at one of its hits. **Targets** (`guard`): "read sentence 99" -> "There is no sentence 99; the document has 66 sentences."; "read the ninth section" -> "There is no ninth section; the document has four."; paragraphs the same; any request of the world with no document open (every `docr.*` action but `loadSample`, `more`, `clearSearch`) -> "There is no document open. Drop a .md, .txt, .pdf or .docx file on the Documents tab, or say "load the sample"." (the engine's own sentence, now said by a rule; all `missing`). `ops` mode says `"Title" has only 66 sentences.`.
- **Undo.** The generic "undo that" says what it took back: "OK, I put "Hansel and Gretel" back on the shelf.", "OK, I closed "X" again.", "OK, "Y" is open again.", "OK, I cleared the search for "witch".", "OK, the search for "witch" is back.", "OK, I took that answer back. The highlights are as they were." (an answer is a library step: it moves the focus).
- **Stays in code, and why.** Parsing and analysis of a text (`analyze.mjs`: sections, sentences, entities, co-reference, events, dialogue, relations, keywords), BM25 and TF-IDF (`text.mjs`), English forms (`lang.mjs`), the choice and wording of every answer, summaries, search and its stepping, reading aloud, the modal free-question input. They are text handling and search; the library has no strings, no ranking, no corpora. Which sentence an answer cites is the engine's result and is recorded (`docs.reader.focus`), not computed by rules.
- **Gains over `ops`.** The reasons for a sentence, paragraph, section or document that is not there, from rules over what is on the shelf; the invariants; "undo that" for opening, closing and searching, with the words of what was undone; the shelf and the reading position are records other rules can read.

### Host additions of the second wave (generic, optional)
- **`stateKey(state)`** in `fns.mjs`: a cheap text that changes when the state does. The host compares it instead of stringifying the whole state, which cost 1 ms or more per turn for a state with the analysis of a text or a TipTap JSON (`ReasonerSession` uses `reasoner.json(id, state)` everywhere it compared JSON).
- **`untold=<type>`** in `world.sop` (repeatable, `core.world.untold`): wire types the world's operations emit that only the session memory keeps; `ReasonerSession.isFact` is false for them.

## geo.map and data.charts on the matrix (user decision 2026-11-11: every world moves to sopworld)
Two engine tab worlds, each with its own instance (they are WORLDS-APART). `world.sop` of both says `reasoner=matrix`, `undo=`, `redo=`, `kb=lookup` and a `source=`; files `matrix.sop`, `fns.mjs`, `matrix.templates.sop` (geo.map also `matrix.operations.sop`, `matrix.patterns.sop`). **`ops` is unchanged in behaviour** (`ops.mjs` only exports what the matrix shares: `isIn`, `isCapital`, `borderYN` were already exported; data.charts exports `NONE`, `DOWN`, `joinAnd`, `low`, `round`, `itemsWord`); `test-world` passes under both strategies (geo.map 441 ops / 459 matrix, data.charts 267 / 277), and scripted sessions say the same words and leave the same state in both (`tests/reasoner-geo-charts.test.mjs`).

### Host additions (generic)
- **Undo and redo: one mechanism, the session timeline.** `undo=geo.undo` / `redo=geo.redo` (data.charts: `chart.undo` / `chart.redo`) and `export function isView() { return false; }` (the world has no view-only steps; having it makes `undoAction` keep what it took out for `redoAction`), `undoWords({ before, after, redo })` for the words ("OK, I undid the last change to the map.", "OK, I did it again."; nothing to take back: the operations' own notes). The operations' history (`history`, `future` in the state) is not wires and not derived back: in matrix mode the state has neither key, the library's timeline is the history (a first attempt, `ownUndo`, kept the operations' history in wires so that redo kept working; it is dropped now that `redo=` exists). **Host fix:** `ReasonerSession.undo` first takes back what the same message changed before the undo ("make it a pie chart then undo"), then the turn before; before, the turn before went.
- **`kb=lookup` (`core.world.kb`).** The world's knowledge base, and those of its imports, are not loaded into the library's instances. Measured on geo.map (1,250 places as wires): a turn took 37 ms against 6 ms in ops, almost all of it the library's copy-on-write after a fork (`_detach`, `sets`) and garbage collection; with the base out of the instance the same turn takes about 8 ms. The knowledge base is a static, read-only, ops-shaped index (`find`, `val`, `vals`, `wires`), parsed once per engine and reached from an action as `ctx.host.kb(worldId)`. An action that must let the rules judge a question tells them the few wires of the knowledge base the question needs, next to the question's own wire, with `ctx.world.check`; the denies decide. data.charts says it too, because its imports (kids.arith, kids.shop, kids.tasks, kids.animals) bring kbs its matrix never reads.
- **`adopt` with `inPlace=false`** (geo.map `fns.mjs`): inside an action the transaction is `ctx.retract` + `ctx.tell` only (an action has no `sets`), so `adopt` can be asked not to plan in-place sets.

### The state is wires (both worlds, the pattern of user.profile)
The operations keep working on the session state and the library takes it over after every operation (`adopt`; `toState` is the way back), one transaction per turn that changed it. Every wire carries the keys the rules read and `obj`, the exact JSON of the object it stands for, so `toState` is lossless and key-ordered like the operations' state (a test compares library and session state key by key). The bookkeeping the operations keep (`nextId`, `pending`, `inputMode`) is one `dialog` wire whose keys are written in a fixed order, so the same state is the same wire whatever order the operations left the keys in.

### geo.map
- **Wires.** `geo.map.view` (center, zoom, layer, bounds), one `geo.map.marker`, `geo.map.highlight`, `geo.map.line` per item (with `i`, its place in the list), `geo.map.focus`, `geo.map.me`, `geo.map.clicked`, `geo.map.dialog`. The 1,250 places of kb.sop are not wires of the instance (`kb=lookup`).
- **Rules and aggregates.** `geo.map.onmap` (markers, highlights, lines, `km` = the sum of the lines' lengths; count and sum aggregates, anchored on the view); `geo.map.shown` (how a country is said: "the Netherlands", "The Netherlands"; 21 `geo.map.the` facts and a rule with a `not`).
- **Denies** (their `why` is the reply, status `conflicting`): a zoom outside 1..18 ("The zoom level must be between 1 and 18, not ?z."), a zoom above 12 on the offline map ("The offline country map zooms in to 12 at most, not ?z. Say \"street map\" to zoom closer."), a latitude or longitude off the Earth (view and markers), a line from a place to itself ("A line needs two different places, not ?n twice."). The operations clamp all of these, so the denies are the library's guarantee that the tab never shows a state the rules forbid (`rs.adoptState` refuses it, rewinds the instance and the state with it).
- **Claims, with a reason.** `geo.isIn`, `geo.isCapital` and `geo.borderYN` are library actions (`core.action` in matrix.sop). Each runs the operation of ops.mjs on a scratch context over the state the wires say (so the view, focus and highlights it changes are taken back as wires), and lets the rules judge a "No": the claim (`geo.map.claim kind=city_in|country_in_continent|country_in_region|city_in_continent|borders|capital`) is checked with `world.check` together with the wires of the knowledge base it needs, and the deny's `why` is the answer's "No, ...": "Paris is not in Germany; it is in France.", "the capital of France is Paris.", "Spain and Germany do not share a border.", "Spain is not in Asia; it is in Europe." Six denies, in the words of the operations (`tests/reasoner-geo-charts.test.mjs` asserts the same replies with the switch on and off). Cases the rules do not cover (a group such as the EU, a name the knowledge base has twice, several capitals) are answered by the operation alone. When the rules agree with the answer, the action returns the knowledge-base wires as `from`, so "why?" says "I worked that out from what I know about places." (`source="what I know about places"`).
- **A new question** (matrix-only pattern): "How long are the lines in total?", "What is the total distance?", "How many things are on the map?" are answered from the derived counts (`geo.onmap`).
- **Left to the operations** (`ops.mjs`, 918 lines, unchanged): the geometry (fitting the view, zoom, panning, haversine), the data index and all questions about places (capital, population, area, comparisons, superlatives, lists, counts, currency, languages, info, describe), markers, highlights and lines as actions, the number formatting, the effect for the browser's location, undo and redo.

### data.charts
- **Wires.** `data.charts.chart` (id, order, type, title, active, horizontal, stacked, number of series, `obj` = the chart), one `data.charts.point` per number (chart, series, place, label, value), `data.charts.dialog`. The legend already declares `type`, `title`, `horizontal`, `stacked` of a chart; the matrix adds `cid`, `ord`, `active`, `nseries`, `obj` and says `combine=intersect` for the type's enum.
- **Rules and aggregates.** `labeltotal` (the sum of a label over the series), `charttotal` (sum, count, max, min of the labels' totals), `top` / `bottom` (the labels with the biggest and the smallest total, all of them when tied: a rule with `eq` over the totals), `seriestotal`.
- **Denies:** the same label twice in a series ("?l is in the chart twice."), a number of a chart that is not there, two active charts. A real gain: "rename apples to pears" keeps both labels in ops (two bars called Pears); in matrix mode it is refused ("That does not add up. Pears is in the chart twice.", status `conflicting`) and the chart stays as it was. `matrix.templates.sop` has a `conflicting` template per operation, because the refusal of a turn is worded by the operation's own template.
- **Questions answered by library actions** (`dcExtreme`, `dcTotal`, `dcAverage`, `dcDifference`, `dcCompare`, `dcPercent`, `dcValueOf`, `dcCount`): the numbers are the derived wires, the words are ops.mjs's (the same sentences, `from` = the chart's source wires, so "why?" still says what the numbers came from). The label lookup ("apples" finds "Apple") is `labelKey` of ops.mjs; the percentage and the average are divided in JS from the library's sum and count (the library's decimal division rounds differently at the half in rare cases).
- **Left to the operations** (`ops.mjs`, 983 lines, unchanged): parsing "apples 5, pears 3", reading the other worlds' holdings, prices, lists and legs (cross-world `ask`), types, titles, colors, palettes, order, orientation, legend, stacking, the pictures and files (effects), `interceptInput` (a click on a bar, "remove plums"), `chartView` (what the tab draws), undo and redo (the operations' history; the library's timeline does it).
- **Known difference after a chain of undos:** the library takes the undone turns' dialogue wires out of the memory, so an ellipsis such as "what about grapes" may be read from another context than in ops.
- **Not done: "assumptions said once".** The default chart type (bar) is chosen in `blank()` of the operations and the wire already carries it, so nothing rests on a library default; to say "I assumed a bar chart" the operation would have to hand the library a value of tier `default` (see the library notes in `worker-log.md`).

## art.draw and diagram.sketch on the matrix (user decision 2026-11-11: every world moves to sopworld)
The two most engine-heavy tab worlds. **The drawing, layout and geometry engines stay in code** (art.draw: `ops.mjs`, `scene.mjs`; diagram.sketch: `ops.mjs`, `engine/`, `arrows.mjs`, `refs.mjs`); what moves is the **scene state** and its **validation**. Both keep running their operations on the session state (`adopt` / `toState`, the pattern of geo.map and data.charts), the world's own instance is the record, and undo and redo are the session timeline's, in the world's words (no world-private history). `ops` mode is unchanged in behaviour: `ops.mjs` of art.draw only gained an `export { ... }` line of helpers (words and a predicate) the matrix functions share, `ops.mjs` of diagram.sketch is untouched.

### art.draw
`world.sop`: `reasoner=matrix`, `undo=draw.undo`, `redo=draw.redo`, `source="the picture"`; files `matrix.sop`, `fns.mjs`, `matrix.templates.sop` (a `conflicting` template per operation, generated).
- **Wires.** `art.draw.object` per thing on the canvas (`oid`, `ord`, `kind`, effective `color`, `x`, `y`, `size`, `rotation`, `z`, `fill`, `tag`, `flip`, and `obj` = the exact object with its `parts`, so `toState` is lossless and key-ordered), `art.draw.sel` (the selected thing), `art.draw.last` (what the last command made or changed: "it", "them"; `i` keeps the order), `art.draw.scene` (paper, sky, ground, ground colour, mood, `nextid`, `label` = the words of the last step, and `rest` = canvas, `seq`, `seed`, `sunStash`, `sunPose`). Points and shape geometry are never wires: scene.mjs computes them from `kind` and `size` when the tab draws, so a picture of 1,000 things is 1,000 wires, not tens of thousands. The state has no `history` or `future` (the library's timeline is the history) and carries `lastLabel`.
- **Rules.** `art.draw.total` (the number of things, anchored on the scene) and `art.draw.tally` (one count per kind, anchored on 26 static `art.draw.kindfact` facts so that an empty kind has its 0, and so that the aggregate is not evaluated once per member of its group; see the cost note below). The count of a colour is a filter over the object wires in `fns.mjs` (a colour is any of 260 names).
- **Denies** (their `why` is the reply, status `conflicting`, the scene goes back): two things with one id, a thing smaller than 1, a selected thing or an "it" that is not on the canvas, a kind the board cannot draw, a ground or a mood it does not have (enums of the slots). The operations never produce these; the denies are the guarantee that the tab never shows such a scene.
- **Target guard** (`guard`, optional export of `fns.mjs`, as docs.editor): "move the green circle to the left", "make the cat blue", "select the star", "what colour is the dog" are asked as an `art.draw.want` wire when the request names a plain noun phrase (kind, optional size and colour); the deny says "I can not find a green circle in your picture." and adds " Your picture is empty. Try "draw a red house"." for an empty picture (both are the operations' own sentences, status `missing`). When the kind is there in another colour the operations say it with their hint ("But there is a red circle, so you can say "the circle"": a grouped description of the other things, which the rules do not build) and the guard leaves the request to them; "it", ordinals, positions, parts and "the one on the left" are resolved by the operations as before.
- **Questions answered by library actions** (`draw.count`, `draw.exists`, `core.action` in `matrix.sop`): the numbers are the derived wires (the count of a colour is the wires the filter found), the words are `ops.mjs`'s; `from` = the object wires, so "why?" says "I worked that out from the picture."
- **Undo and redo.** The session timeline: "OK, I undid it (made it night).", "OK, I undid it (colored it blue).", "OK, I did it again."; "There is nothing to undo." / "There is nothing more to undo." `isView` ignores a step that only changed the selection or what "it" means (the board's history only held changes to the picture), `stateKey` compares the state without the undo snapshots the operations keep. The label of a step is the label the operations gave their snapshot (`remember(s, label)`), carried in `art.draw.scene`'s `label`.
- **Differences from `ops` (all intended).** (1) After an undo the counters (`nextId`, `seq` = the cycle of openers "Ta-da!", "Nice!", `seed`) are the library's, so a thing drawn after an undo takes the id the undone one had and an opener repeats; ops never took those back. (2) The `undo` of the board hands the request to the document, chess or music world when that tab is in front (`SHARED`); in matrix mode the session timeline takes back the newest turn of any world and names it in that world's words, which is the same thing unless the board's turn is newer than the other world's. (3) The refusal of a missing thing comes from a rule; its words are the operations'.
- **Left to the operations** (`ops.mjs`, 1,574 lines, and `scene.mjs`, 477, unchanged): the vocabulary, noun-phrase parsing and resolution ("the second tree", "the big one on the left", "it"), placement, regions and relations ("next to", "between"), geometry and shapes, moods and the night sky, ground, duplicates, the pictures and downloads, every reply that is not a count or a refusal, the hint of a refusal.

### diagram.sketch
`world.sop`: `reasoner=matrix`, `undo=diagram.undo`, `redo=diagram.redo`, `source="the diagram"`; files `matrix.sop`, `fns.mjs`, `matrix.templates.sop` (generated). `ops.mjs` and the engine are unchanged.
- **Wires.** `diagram.sketch.shape` per shape (`sid` = the short id, `name`, `ord`, `shape`, `x`, `y`, `size`, `w`, `h`, `color`, `layer`, `label`, `obj` = the exact shape), `diagram.sketch.edge` per arrow (`eid`, `ord`, `from`, `to`, `style`, `arrow`, `obj`), `diagram.sketch.group` with one `diagram.sketch.member` per member, `diagram.sketch.sel` (what is selected: `what` = shape or edge, `ref`), `diagram.sketch.last` (what "it" is), `diagram.sketch.scene` (counts, and `rest` = rules, facts, counters, frames, pending, `rev`). Routes, layouts and templates are the engine's: the library never sees a path. The engine's own undo and redo stacks (`undo`, `redo`) are not wires: the timeline replaces them (the state has empty ones).
- **Rules.** `diagram.sketch.degree` per shape: arrows out, arrows in, total (aggregates anchored on the shape, so a shape with no arrow has 0). No operation reads it yet: the engine answers "how many connections does A have" (and neighbours, paths, reachability, cycles) with its own Datalog reasoner, which duplicates what rules over the arrows do, but its answers are wired to its reader of sentences and to highlights, so they stay (see "Left to the engine").
- **Denies** (state; the diagram goes back): two shapes with one name or one id; two arrows for one pair ("That arrow already connects A and B."); an arrow that starts or ends at a shape that is not there ("The arrow a9 goes to Z, which is not in the diagram."); a group member that is not there; a selection or an "it" of nothing; a shape kind the editor does not have (enum).
- **Guard.** "connect A to B" with an arrow A to B already there is refused before the engine runs: `guard` reads the sentence with the engine's own reader (`read` of `ops.mjs`; one command with one pair), asks `diagram.sketch.want` and the deny says "That arrow already connects A and B." (status `conflicting`; ops mode says "A → B already exists.", the engine's note). Chains and fan-outs are left to the engine, which says which pair exists.
- **Undo and redo.** The session timeline: "Undid the last change." / "Redid it." / "There is nothing to undo."; the selection and a question's highlight are views (`isView`: shapes, arrows, groups, rules, facts and frames unchanged), so "undo" takes back what changed the diagram; one undo takes back a whole template.
- **Left to the engine** (`engine/` 5,012 lines, `ops.mjs` 569, `arrows.mjs`, `refs.mjs`, unchanged): reading a sentence (typos, ids, references, layout words), every command and its reply, the 17 questions (count, list, exists, property, check, describe, neighbours, connected, degree, nearest, extreme, path, reachable, cycle, members, group of, rules), templates and colour schemes, auto layout and arrow routing, facts and rules. They are geometry, language and a Datalog interpreter of its own; the library holds the state they change and refuses what cannot be.
- **Cost.** A diagram of 20 shapes, 14 arrows and 4 groups is 83 wires and 5.9 kB of state; a picture of 32 things 62 wires and 4.7 kB. Measured numbers are in `sop_world_status.md`.

### Limits and costs common to both
- **Undo after a restart.** The library's timeline is session memory. A session the page restores after a watchdog restart has the picture or the diagram (the state travels as data and `adoptState` takes it over) but no turns to undo: "undo" answers "There is nothing to undo." In `ops` mode the board keeps 50 snapshots, the editor 30, in the state, so they survive. `tests/discourse-memory.test.mjs` asserts both. (Persisting the timeline, or the world's snapshots, would fix it for every matrix world; not done.)
- **Cost per turn** (matrix against ops, same machine, interleaved; `sop_world_status.md` has the numbers): the instance takes the state over once per turn that changed it (`adoptState`: the state compared by `stateKey`, one patch of in-place `sets`), and `_state` derives it back. Scaling, measured on synthetic scenes: 1,000 things on the board, one moved: 11 ms; every one moved: 90 ms; told all at once: 39 ms. An aggregate anchored on each member of its group (a count per kind with the anchor on a thing) made one move 433 ms at 1,000 things (the group is counted once per member): the counts are anchored on static kind facts instead.

## ui.shell, ui.avatar and ui.help on the matrix (user decision 2026-11-11: every world moves to the library)
The three UI worlds keep their operations (`ops.mjs`) running on the session state, as `user.profile` and the document worlds: `adopt` / `toState`, the world's own instance is the record. `ops` mode is unchanged: no instance, no `guard`, the operations' own sentences. Their knowledge bases (`kb.sop`) are **generated** by `scripts/gen-ui-kb.mjs` from the manifests and the tables of the worlds (`--check` and `tests/reasoner-ui.test.mjs` fail when a file is out of date); the types of a kb are declared by the world's legend (the loader's validator requires it).

### Host additions of the third wave (generic, optional)
- **`passive=true`** in `world.sop` (`core.world.passive`): a world whose state follows the other worlds (the shell's tab: the editor, a game or the map bring their tab forward). What another world's request changes in it, or its creation by one, is **not a step of that turn**: `ReasonerSession.commitTurn` leaves it out of the turn's marks, so undoing the editor's turn does not switch the tab back. Only a turn of its own (the shell's operation: `adoptState(session, ownId)` is told which world's operation just ran) is a step, and "undo that" takes it back. A host patch (`setWorldState`: a click on a tab, a toggle) is taken over at the end of the next turn the same way: not a step.
- **One timeline.** The session timeline's per-turn `worlds` list is the only record of which world a turn changed: a passive world that another world's request moved is not in it (and has no mark), so it is not a step; a world's counted undo (`undo=` with `isView`) only walks back turns whose `worlds` name it. A turn of the shell's own (a tab switch, a setting) is a step: "undo" takes it back in the shell's words, and "Let's play tic tac toe" is such a turn (it goes back after the moves).
- **`guard` may name the reason** (`{ status, reason, note }`): `reason: 'unknown_argument'` keeps a refusal of a name the world does not know ("There is no weather tab.") a weak reading for the dispatcher, as the operation's "I do not know a tab called weather." is (`reasonOf`). The default stays `precondition_failed`.

### ui.shell
`world.sop`: `reasoner=matrix`, `passive=true`, `source="the app"`; `matrix.sop`, `fns.mjs`, `kb.sop` (generated).
- **Wires.** `ui.shell.view`, one, told when the state first leaves the initial one and set in place after that: `tab`, `prev` (`none` when there is no previous tab), `speaker`, `listening`, `handsfree`, `rate` (hundredths), `lang`, `rest` (the other keys of the state as JSON: the game the host says is active). `toState` derives the state ops.mjs keeps; the titles of the tabs ride along unseen for the words of an undo. The kb: `ui.shell.known` (tab id, title, world: the five builtin tabs and every tab a manifest declares), `ui.shell.alias` (the words that name a tab: ids, titles, `tabAlias`), `ui.shell.game` (the actions of a tab's game: `tabNew`, `tabHint`, `tabGiveUp`), `ui.shell.lang`, `ui.shell.settings` / `stab` / `salias` (the Settings dialog).
- **Rules.** The speech rate is from 0.5 to 2 (the slot's `min`/`max`). The tab is **not** checked on the state: the host names tabs as it likes (`avatar` and `robot`, test tabs) and clicks move it with no `previousTab`. What the chat asks (`guard`, `ui.shell.want` wires, never kept): a tab that no word names ("There is no weather tab."), a game ("There is no foo game."), a game control on a tab with no game ("There is no game open on the Avatar tab. You can say, for example, "let's play hangman"."), "go back" with no previous tab, a language ("I do not speak french yet."), a Settings tab ("I do not have a settings tab called colors. The tabs are ..."). The refusals of a name are `unsupported` / `unknown_argument`, as the operations' own.
- **Undo.** "undo that" says what it took back: "OK, I am back on the Avatar tab.", "OK, I speak English again.", "OK, the speaker is off again.", "OK, my speech rate is 1 again." (several parts: "OK, I am back on the Editor tab, and my speech rate is 1 again."). The language switch is unchanged: the operation sets `language`, the host reads it from the state; undoing it switches back.
- **Stays in code, and why.** Resolving a word to a tab with the manifests' merge (`refresh`), starting a game through the game worlds (`ctx.request`), the phrase log and Settings effects, the speech rate arithmetic (clamping and rounding, the sentence for a limit): the library has no way to run another world's action from a rule and no number formatting.
- **Gains over `ops`.** The refusals come from rules over a kb that is derived from the manifests, so a new tool world's tab, aliases and game actions are known to the rules without editing the shell; "undo that" of a tab switch and of every setting (ops: nothing to undo); the shell is a record other rules can read.

### Host additions of the third wave, continued (generic)
- **An action the matrix does not declare is the operations'** (`ReasonerSession.owns` / `request`): a request is the library's only when the world's matrix declares a `core.action` for it (or it is the world's `undo=` / `redo=`). A world that keeps its state with `adopt` and runs its operations in code (the document worlds, the profile, the UI worlds) used to get an instance and an `act` call for every request, even a read-only one, only for the library to say "unsupported"; now the operations run directly and the instance is made when the state first changes.
- **`guard` makes the instance lazily**: the instance is made when the guard asks the rules (`check`) or reads wires (`find`), not for a request the guard has nothing to say about (every other action of the world).
- **A world's own "undo" without a step of its own**: `undoAction` answers "nothing to undo" (the world's `undoWords` with `before: null`) with no instance; and "undo" typed while the world of the open tab (the avatar, at the start) has nothing to take back **falls through to the last turn of another world** (a statement in the shop, a setting of the shell), but not to the switch to that very tab (`tic tac toe` opened the tab: "no move to take back").

### ui.avatar
`world.sop`: `reasoner=matrix`, `undo=avatar.undo`, `source="how I look"`; `matrix.sop`, `fns.mjs`, `kb.sop` (generated; the types are in `legend.extra.sop`, which `scripts/legend-from-dicebear.mjs` appends to the generated `legend.sop`).
- **Wires.** `ui.avatar.look` (one, once the look changes: `character`, `name`, `seed`, `rest` = the other keys of the state as JSON: chips, caption, an offer that waits for a yes, the looks to undo (the last whole, the others as their character), `char` = a reference to the kb); `ui.avatar.part` (`ch`, `key`, `value` = a variant id or `none`, `n`, `slot` = a reference to the kb's slot) and `ui.avatar.color` (`ch`, `key`, `hex`, `n`) for each part and color of every character that is shown, was changed or is already wired (the three first characters when they differ from the start, the active one always). (the parts of the caption that changed) / "...: my glow is as it was." / "There is nothing to undo.". Redo has no pattern in this world (the only `redo` pattern is the editor's): see the library notes.

The variants (581) and palette entries (251) are **not** wires: every wire of a kb costs about 10 microseconds per turn (the library copies the world at the first write after each turn's mark and validates what a change touches), and the rules could say nothing about them that the lexicons do not already enforce; the first version with them cost 170 ms per nine turns instead of 76.

### ui.help
`world.sop`: `reasoner=matrix`, `passive=true`, `source="the help I know"`; `matrix.sop`, `fns.mjs`, `kb.sop` (generated). **The library adds little to this world, and it is kept thin.**
- **Knowledge base** (generated from the manifests, the shell's tab words and the canonical examples of the patterns): `ui.help.area` (a word that names an area: a tab id, title or alias, the last part of a world's name, the last word of its summary; the world behind it; `says` = "To show places on a map, you can say, for example: "...", "..." or "...".", the first three examples in the order the rotation of `ops.mjs` uses). The words are also the lexicon `lex.ui.help.areas` (a test checks they are the same list).
- **New request.** "What can you do in the map?", "What can I do with charts?", "What can you do on the chess tab?" (`pat.ui.help.area`, a `core.question type=ui.help.area seek=says where.word=<word>`, template `ui.help.area.says`): a lookup in the kb. The library answers it in matrix mode; ops mode answers the same question from the same kb wires (the memory holds every world's kb), word for word.
- **State.** `ui.help.state`, one wire, `rest` = the state ops.mjs keeps as JSON (the rotation cursor of each world, the last help, the last sentence that was not understood). - **Stays in code, and why.** Everything that chooses what to show: the rotation of examples over a world's patterns, "how do I ...?" (stemming, edit distance and a score over all the canonical examples), the rules and live state of each game (read from the game worlds' states), the capability sentence (the common prefix of the summaries), the identity answers, `didYouMean`. Moving the 972 canonical examples into wires would make every turn pay for them (each wire of a kb costs about 10 microseconds per turn, see ui.avatar).
