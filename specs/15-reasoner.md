# 15 — The reasoner host layer (sopworld), stage 1

Implementation: `src/reasoner/`, the vendored library `src/vendor/sopworld/` (0.6.1, see `src/vendor/LICENSES.md`), per-world `matrix.sop` + `fns.mjs`. Browser-safe. Tasks: SOPWORLD-1 and SOPWORLD-1b (worker-tasks). The numbers are in `worker-log.md`.

## Purpose
`sopworld` (https://github.com/ml-circuits-research/soplang-words-lib, MIT, same owner) is a general library for self-consistent worlds of SOP Lang wires: a schema with a type hierarchy, rules, denies, defaults, a sequence with states changed by events (fluents), aggregates, queries with a status, actions as transactions, retract and replace, abduction, explain, step budgets on every loop and a structural `fork()`. The user wants it to become the centre of the worlds, so that they share one representation and one reasoner. Stage 1 proves it on three worlds without changing any default behaviour. Stage 2 (after the user sees stage 1): the session memory and question resolution of `src/interpreter/` on the library, then more worlds.

## The switch
- **Engine level.** `createEngine({ options: { reasoner: 'ops' | 'matrix' } })`; without the option the environment variable `PSYS2_REASONER` (`ops` | `matrix`), then `matrix`. **User decision 2026-11-11: matrix is the default.** `ops` stays available as the fallback behind the same switch: with `ops` nothing of this spec is loaded (the library is not even imported), no session has a World, every file of a world behaves as before. With `matrix` only the worlds that opt in (below) are answered by the library; every other world takes its `ops` path in both modes. The library is imported lazily inside `createReasoner` (in the webchat: in the engine worker, never on the page's first-paint path).
- **Per world.** A world opts in with `reasoner=matrix` in its `world.sop` (key `core.world.reasoner`, default `ops`) and ships `matrix.sop` (and `fns.mjs` when it needs functions). A world that does not say so is never answered by the library, whatever the switch.
- **CLI and evaluators.** `--reasoner ops|matrix` (default `matrix`; `scripts/lib/reasoner-flag.mjs` sets `PSYS2_REASONER`): `src/cli.mjs`, `scripts/eval-operational.mjs`, `scripts/eval-dialogues.mjs`, `scripts/check-ro-replies.mjs`. Any other tool follows the environment variable.
- **Webchat.** Settings › Developer › Reasoner: `Matrix where available (default)` | `Operations (fallback)`. `settings.reasoner` defaults to `'matrix'`. **Settings version 4 (2026-11-11):** a saved `reasoner: 'ops'` of an older version cannot be told from the old default (the setting stores only the value), so every saved `'ops'` of a version below 4 is migrated once to `'matrix'`; an `'ops'` chosen afterwards is saved with version 4 and respected; an unknown value is `'matrix'`. It is read when the engine starts (it chooses which files of the worlds are loaded), so changing it restarts the engine worker from the last committed state (`engineClient.restart`).

## What the library gets
Built once per engine (`createReasoner(set)`), forked per session:
1. `worlds/core/mapping.sop` (data): three `core.schema.map` wires that let the library read our legends unchanged (`core.key`, `core.type`, `core.legend`; `closed=true` also means the world knows every instance).
2. The legends of the matrix worlds and of everything they import, in dependency order, as they are (`legend.sop`).
3. The knowledge bases (`kb.sop`) of the matrix worlds, and `@e.user core.agent` (the user is a built-in agent of every session).
4. The matrices (`matrix.sop`) and the action functions of `fns.mjs` (`export const fns`), registered as the library's `actions` (a registry of their own: an action named `add` does not replace the arithmetic, so no prefix is needed).

`matrix.sop`, `mapping.sop` and the library's own wires are read by the library's parser (SOP Lang v1.1: `?` is only a variable, a pattern is an ordinary `@id` wire, `#` comments are allowed); the files our parser reads (`patterns.sop`, `templates.sop`, `operations.sop`) have no comments. A matrix re-declares keys the legend already declares with `combine=intersect`.

## Matrix-mode extras of a world
`matrix.patterns.sop`, `matrix.operations.sop` and `matrix.templates.sop` are appended to the world's patterns, operations and templates **only** when the engine runs with `matrix` and the world opts in; templates go first, because the renderer tries the templates of a status in file order. An operation with `impl=matrix` has no function in `ops.mjs` (the validator accepts it). New phrasing follows ADR-007 (phrase groups, shapes).

## Session wires
`Session.add(wires)` tells the library every wire whose type its schema knows (not `core.question`, `core.request`, `core.answer`, `core.observation`). Our wires are serialized with short keys and parsed by the library. A wire the library refuses (a deny, a conflict) is recorded in `session.rs.refused` and the library stays as it was; our memory keeps the wire as before. `Session.clone()` forks the World (nothing is copied until one of the two changes), so dry runs, validation and snapshots never touch the original.

## Questions and requests
`Interpreter.resolve` asks the library when the question type belongs to a matrix world (the longest world id that prefixes it) or the request's action is declared by one; otherwise, and when the library answers `unsupported`, the operations answer as before.
- `world.query(wire)` / `world.act(wire)` -> our envelope (spec 04): statuses map 1:1 (`supported`, `conflicting`, `ambiguous`, `missing`, `unsupported`, `budget`); `refused` -> `conflicting` with `reason=precondition_failed`, the deny's `why` (it quotes the values) and, in `vars`, the keys of the wires it was decided on (`involved`) and its `bindings`; `no` -> `supported` with value `no`; `unknown` -> `missing`; `done` -> `supported` with the action's result fields; `unsupported` with a `reason` (a calculation that cannot be done) -> `unsupported` with `why`, without a reason -> the question is not the library's and the operations answer. `via` is `core.matrix`; `from` is the library's `from`. The library's soft constraints (`soft=true`, standing `core.issue` wires) keep an impossible statement and make every answer that rests on it `conflicting` with the reason.
- **Words around the numbers.** The envelope of a library answer has no prose. The matrix puts every number a reply needs on the answer wire (the keys its rules set with `core.on=`), and the library returns that wire as `supposed`; the owning world's `voice(ctx)` (exported by `fns.mjs`) only finds the words: `ctx.supposed` (the answer wire, flat), `ctx.env`, `ctx.where`, `ctx.issues()` (the standing issues with the wire they are about), `ctx.find(type)`, `ctx.name(id)`. There are no second queries. The existing templates are unchanged and read the envelope as before; `env.vars` are template variables, `env.why` is `{why}`.
- **A missing argument.** `core.action ... required=<key> ask.<key>="..." template.<key>="add <x> to my list"`: the library answers `missing`; the envelope carries `ask` and `pending = { world, key, template }`, so the discourse layer (spec 11 section 3) keeps the question open and the next message completes the command.
- **Mirrors.** `mirror=<type>` (repeatable, `core.world.mirror`) in `world.sop`: after a library answer, wires of these types are copied from the library's World to the session memory in our shape (a wire the action removed is retracted there), so worlds that read the memory (charts, documents) see what the matrix actions wrote, as they saw what `ops.mjs` emitted.

## Budget
One budget per turn. Every library call gets `{ steps: left }` where `left` is what is left of the turn's budget (`budget.remaining('sopworld')`); afterwards the steps it took, per library site, are ticks of the turn budget at `sopworld.<site>` (`match`, `chase`, `negation`, `aggregate`, `fluent`, `withdraw`, `validate`, ...). An excess ends the turn like any other site (`BudgetExceeded`); a library call that ran out answers `budget` and left the world as it was. The library's own loops carry ticks, and `tests/reasoner.test.mjs` runs its loop scanner on the vendored file; `tests/loop-guard.test.mjs` does not scan `src/vendor/`.

## One undo
The library is the only record of what was said. Nothing else holds state that could diverge from it:
- **State derived from the library.** Each matrix world exports `toState({ find, query })` (kids.tasks: `{ lists, counter }`; kids.shop: `{ money, purchases }`; kids.arith: `{ holdings }`). The host layer writes its result into the session state after every library change (telling a wire, an answer, a rewind), so the hooks (`referents`, `summary`) and the dialogue layer's snapshots read what the library says. Like the operations' state it comes into being when the world first answers or has something to say.
- **Marks.** `ReasonerSession.beginTurn(turn)` takes `world.mark()` at the start of every dialogue turn (a mark costs nothing until the library changes); `commitTurn(turn)` keeps it when the turn changed the library (`world.stamp`). The dialogue layer's action of that turn carries it (`act.rsMark`; a statement that changed the library is an action too, so "that's wrong" offers to take it back).
- **Taking back.** "undo that" (`ReasonerSession.undo`), the dialogue layer's `undoAction` ("that's wrong", "yes") and a repair ("no, I meant ...", `_repair`) all call `ReasonerSession.rewind(mark, session)`: library `rewind`, the dialogue wires the library no longer holds are retracted in the session memory, the state and the mirrors are derived again. `rewind` returns a function that puts it all back (a repair that finds no correction gives up with it). Without the matrix reasoner nothing changes: the saved state is restored as before.

## Stage 1 limits
- The library holds the facts of the three worlds; the other worlds keep their engines and state. The switch never touches a world without `reasoner=matrix`: the same messages give the same replies, statuses and state in both settings (`tests/reasoner.test.mjs`).
- The old operations are not removed, and `ops` stays the default.
- Kept in the host layer, not the library's job: reply wording (a/an, plurals, "costs" or "cost", "about", "from Tom"); the sentence for a zero divisor; which item to name when a price is missing (a lookup of the price wires); the text handling of kids.tasks (splitting "milk, eggs and bread", list names, what a named thing matches).


## Coherence in matrix mode (SOPWORLD-1b item 2 in both strategies)
The coherence measures of spec 11 section 12 hold when `reasoner=matrix`, through the library:
- **A statement that cannot be true is said, not acknowledged.** Every segment's statements are told to the library; `ReasonerSession.refuseFacts` then looks for a hard deny of the library on those wires or a new issue (a soft constraint, `core.issue`) that was not standing at the start of the turn. The words come from the world's `problem(ctx)` export in `fns.mjs` (`ctx`: `why` = the deny's or issue's own text, `issue`, `facts`, `find`, `query`, `name`), else from the library's text (a `why` may quote the values, `?m`). The reply is "That does not add up. <reason>" with status `conflicting`, and the library is rewound to the mark taken before the segment's first tell (what the segment told is gone from the library and the session memory; the turn is a no-op for undo when nothing else changed).
- **"No, ..." revises the last statement through the library.** `Discourse._correctFact` calls `ReasonerSession.retractFacts` (library `retract`: what followed from the facts goes too; refused when the library will not) and tells the corrected sentence as a new statement. "Undo" takes the correction back as one turn.
- **"Why?" is the library's explanation.** `Discourse._known(ids)` takes the told leaves of `explain(id)` for each wire the answer (or the world's `why` hook) rests on, oldest first, and quotes the user's own sentence of each (`core.source`), never back-translated; a told wire counts even when other facts changed its value (Tom has 5, then gifts and meals: all three sentences are named). A told wire without a sentence of the dialogue is the price list. English and Romanian use the same parts (spec 11 section 12).
- **Unknown amounts and starts.** The matrix of kids.arith answers "How many apples did Tom have at first?" with rules (the count a statement gave minus the sums of what came in and went out); "Ana gives him some" leaves a bound that `voice` says ("more than 5").
- **"Which list did you put it on?"** kids.tasks' entries carry `batch` and `assumed` (legend keys); `toState` derives `last` from them.

## SOPWORLD-1b: what the `ops` strategy does now
The coherence failures that were ours (unread sentences, "why?", impossible statements, ties, unknown start) are closed in the rules and the dialogue layer, so both strategies are measured on sentences they can read: see spec 11 section 12. The `ops` strategy keeps the `from` list of every answer and explains with it; its impossible statements are refused when told (so does the matrix now, above). New rules, phrase groups (`lang.quant.some`, `lang.quant.something`, `lang.then.now`) and replies are shared by both strategies; patterns whose reading differs from a matrix extra have a lower priority than the matrix extra, so the matrix reading still wins in matrix mode.

## Certainty in replies (SOPWORLD-1b item 4, matrix mode)
An answer that rests on a value of tier `default` or `guessed` says so once, after the answer, and the turn records it. Nothing of this exists in `ops`.
- **Defaults are applied.** After every `tell` the session completes the defaults the matrix declares (`world.complete({ defaults: true })`, budgeted like any library call), so "I buy the ball" (no count said: the pattern emits no `count`) becomes a purchase of 1 with `count=1` of tier `default`. "I buy a ball" says `count=1` and is told, not assumed; "three of them" revises the cell to told, and the assumption is gone.
- **What an answer rests on.** The library's `query` result has `rests`: the cells under the answer that are weaker than `derived`. The cells of tier `default` or `guessed` become `env.assumptions` (strings `<wire>.<key>=<value> (<tier>)`) and `env.assumed`, the sentence. The words of one cell come from the owning world's `assumed(cell)` in `fns.mjs` (`cell`: `id, key, value, tier, type, attrs, name`): a phrase ("1 ball"), or `null` for a default not worth saying (kids.tasks: an entry is `todo` until it is done); without the export the phrase is "<key> is <value>". Several cells are one sentence: "I assumed 1 ball and 1 pen." The sentence is added by `Interpreter.render` to a `supported` answer; it goes through the reply table of `src/translate/replies.en-ro.mjs` (`I assumed {t}.`).
- **Said once.** A cell that was said (per session, copied by `fork`) is not said again by a later answer; a value that was told since is no assumption.
- **The record.** `reply.assumptions` (all the cells of the turn's answers; absent when empty), `answers[].envelope.assumptions`, and `detail.assumptions` of the phrase log record (`docs/webchat/ui/phrase-log.mjs`).
- **Coherence runner.** `scripts/eval-reasoner.mjs` knows the hint `assumption_visible` (also `assumption-visible`): `true` = the last answer carries assumptions and says "I assumed" exactly once; `"once"` = across the dialogue exactly one reply says it; `"none"` = no turn rests on an assumption and none says it. Cases `coh.shop.11-13`.

## games.tictactoe on the matrix (SOPWORLD-1b item 5)
`worlds/games.tictactoe` says `reasoner=matrix` and `undo=ttt.undo` (key `core.world.undo`) and ships `matrix.sop`, `fns.mjs`, `matrix.{patterns,operations,templates}.sop`. The board on the tab, the reading of places, the computer's choice (win, block, center, seeded random; minimax at `perfect`) and the reply words are the world's, shared with `ops.mjs` (`fns.mjs` imports its tables and chooser: `placeIndex`, `chooseEasy`, `bestMove`, `findWin`, `intro`, `ending`). **`ops` is unchanged**: `ops.mjs` only exports what the matrix shares, and `placeIndex` is the place-reading part of `_move` moved out unchanged; `test-world games.tictactoe` passes under both strategies, and a whole scripted game says the same words in both (`tests/reasoner.test.mjs`) (`dlg.gms#016`, `#019` expect "took back" after a bare "undo").
- **The game is wires.** One `ttt.game` (user, level, seed) and one `ttt.move` per mark (`by`, `at` 0-8 row by row, `n` = moves before it). The computer's moves also say why: `why=win|block|center|random|best` and `line` (a string). `toState` derives the state ops.mjs keeps (`board, user, turn, winner, level, seed, last`) after every change, so the tab cannot show another game than the one the rules know; `ops`'s `history` has no counterpart (the library's marks do that).
- **Rules and denies in `matrix.sop`.** `ttt.turn by=X|O` (X after an even number of moves, none when the game is over); `ttt.free at=` (the legal squares: not taken, game not over); `ttt.won winner= how=` (three of one mark on a line fact `ttt.line`, or `ttt.resign` -> the other mark, `how=resigned`); `ttt.drawn` (nine moves, no winner). Denies, whose `why` is the reply: a square taken ("The center is already taken by you. Please pick another place." / "... by me ..."), a move out of turn ("It is not your turn."), a move after the game ended ("The game is over. Say \"new game\" to play again."). The words of the first are the same as ops.mjs's.
- **Actions** (`fns.mjs`, registered as `tttMove`, `tttNew`, `tttFirst`, `tttLevel`, `tttGiveUp`, `tttWhy`): a move is checked with `world.check({ wires })` (dry), refused as `unsupported` with the deny's `why` as the note (the status ops.mjs gives a refused move), else told, and the computer answers in the same transaction. Actions the matrix does not declare (status, describe, hint, last, count, who first) fall back to `ops.mjs`, which reads the derived state.
- **Undo.** `undo=ttt.undo` in world.sop: the host layer answers that request itself by `ReasonerSession.undo` (the library goes back to before the last turn that changed it: the move and the answer, a resignation, a level change), and the world's `undoWords({ before, after })` says what that was ("OK, I took back your last move and my answer. It is your move again." or "OK, I took that back."; nothing to take back: `missing`). Bare "undo" (the dialogue layer's "undo that", the same rewind) with the game's tab open says the world's words too (`ReasonerSession.undoAction`); off the tab it is the generic "OK, I took that back: \"center\"".
- **"why did you play there?"** (matrix-only action `ttt.why`, patterns in `matrix.patterns.sop`): the reason on the computer's last move ("I played top right because I could not win and did not have to block, so I took any free square." / "... because it completes the top row, so it wins the game." / "... because you were about to complete the left column there, so I stopped you." / "... because it is the best move: I looked at every way the game can go from here."); before any move: "I have not played yet."
- **Two small host changes.** An action another world asks for by name (`ctx.request`, here the music world's "Play B2" with the game open) goes to the library when it owns the action (`ReasonerSession.request`); a result with `openTab` brings that tab forward (`ui.openTab`), as `show(ctx)` did in ops.mjs.
- **Tests.** `tests.sop`: 13 tests `reasoner=matrix` (refusals with reasons, undo, why, resignation); `tests/reasoner.test.mjs`; `scripts/test-webchat-matrix.mjs` scenario `tictactoe` (the board of the tab after a refused move and after undo).

## Wordings that follow ops (2026-11-11, from the A/B experiment)
- **"What did you do?"** in matrix mode keeps the source sentence ("I worked that out from what you told me: ..."). A computed answer (a total) is worked out on a supposed wire that the library takes away again, so the answer's `from` is empty; `ReasonerSession._restsLater` forks the world and tells the supposed wire again when someone asks, and the told leaves of what the rules derived on the way are the sources (a price told again, merged into the older wire, is found through the library's `resolve`).
- **A purchase without a count** is acknowledged with what was bought and the assumption: "OK, you bought 1 ball. I assumed 1 ball." (`ReasonerSession.ackExtras`: the defaulted keys are added to the acknowledged wire). The assumption is not marked as said, so the first answer that rests on it still says it once ("You have 15 lei left. I assumed 1 ball."), as the coherence cases coh.shop.11 and coh.shop.13 expect.
- **Budgets.** Matrix-mode library calls are charged to the turn's step budget (`_charge`), as before; the lazy re-derivation above ticks `sopworld.explain`. With matrix as the default the ticks were re-measured (`scripts/measure-ticks.mjs --mode rules`, 7400 turns): the `sopworld.*` sites reach at most 5 880 ticks per turn (`sopworld.match`, p99 3 522), far below the 1 M `perSite` default they fall under, and every other site stays below its limit in `src/dialog/budget-limits.mjs`; no limit changes.
## Stage 2: more worlds on the matrix (user decision 2026-11-11: sopworld becomes the default)
Two generic host additions serve the worlds that read tables from other worlds:
- **Knowledge bases of the imports.** The library loads the `kb.sop` of every world a matrix world imports, not only of the matrix worlds (before: `kids.shop` only). `games.hangman` and `games.guess` import `kids.animals`, so its animals are wires of the library; an animal a game teaches is told to the library and is undone with it.
- **`ctx.host` in an action function.** `lexicon(id)` (the words of a lexicon, as `ctx.lexicon` in ops) and `view(ctx)`, an ops-shaped read-only context (`find`, `val`, `vals`, `lexicon`) over the library's `ctx`, with the values decoded by the legend as ops decodes them. A world's `fns.mjs` hands it to the functions it shares with `ops.mjs` (the word list, the hint facts, the animal profiles), so the tables are not copied.

### games.hangman on the matrix
`world.sop` says `reasoner=matrix` and `undo=hm.undo`; `matrix.sop`, `fns.mjs`. **`ops` is unchanged**: `ops.mjs` only exports what the matrix shares (`MAX_WRONG`, `NOT_PLAYING`, `wordList`, `facts`); `test-world games.hangman` passes under both strategies (137; matrix 154 with 17 matrix-only tests) and a scripted game says the same words, statuses and state in both.
- **The game is wires.** One `hm.game` (the secret `word`, the `seed` of the next choice), one `hm.ch` per distinct letter, one `hm.guess` per guess (`n`, `kind` = letter|word, `what`), one `hm.hint` per hint, `hm.giveup`. `toState` derives the state ops.mjs keeps (`word, masked, guessed, wrong, wrongLeft, status, hints, seed`) after every change, so the tab cannot show another game than the one the rules know.
- **Rules.** `hm.hit` / `hm.miss` (a letter named by an `hm.ch` or not; the whole word equal to `hm.game.word` or not); `hm.lives` = 6 minus the misses (a count); `hm.left` (letters no letter guess named yet); `hm.over how=won|lost|giveup` (nothing left hidden, the word guessed, no lives left, or the player gives up).
- **Denies** (`why` is the reply): a guess when no game is on or after the game ended ("We are not playing hangman. Say \"play hangman\" to start.", status `missing` as in ops), the same letter twice ("You already tried ?c."; the action says "You already tried E." with the masked word and the status `supported`, as ops does). A guess is checked with `world.check` before it is told.
- **Actions** (`hmNew`, `hmLetter`, `hmWord`, `hmHint`, `hmGiveUp`): the seeded choice of the word, the hints and the sentences are the world's (the same words as ops.mjs). `hm.status` stays in ops.mjs and reads the derived state.
- **Undo** (the matrix adds this): bare "undo" with the hangman tab open takes back the last turn that changed the game: a guess ("OK, I took back your last guess. The word is as it was before."), a hint, a give-up (the game is open again), a new game (the old game is back). Nothing to take back: the dialogue layer's "There is nothing to undo.". In `ops` there is no undo for hangman.

### games.guess on the matrix
`world.sop` says `reasoner=matrix` and `undo=guess.undo`; `matrix.sop`, `fns.mjs`. **`ops` is unchanged**: `ops.mjs` only exports what the matrix shares (`FEATURES`, `readAnimals`, `truth`, `pickQuestion`, `factOf`, `slug`, `an`, `words`); `test-world games.guess` passes under both strategies (118; matrix 130 with 12 matrix-only tests) and a scripted session (a solved game, a corrected answer, a clue, a taught animal, a game that ends in "I give up") says the same words, statuses and state in both.
- **The game is wires.** `guess.game` (`max`), one `guess.animal` per animal the game started with (`name`, `i`), `guess.out` for every animal an answer, a clue or a wrong guess took out (`how` = ans|ev|rej), `guess.ans` per answered question (`n`, `feature`, `value`, `text`, `answer`), `guess.ev` per clue the player volunteered, the open question `guess.q` or the open guess `guess.try`, `guess.learn` (the game waits to be taught), `guess.solved`. `guess.learned` (name, `trait="feature=value"`, `not="feature=value"`) keeps what was taught from game to game; the animal itself is also told as a `kids.animals.animal` wire of the library, which the next game reads like any other animal (and undo takes back).
- **Rules.** `guess.cand` = the animals of the game that are not out; `guess.tally` (`count` asked, `left` = `max` minus the count); `guess.phase p=asking|guessing|learning|done` from the open question, the open guess (not once solved), the wait for a name, the solution. `toState` derives the state ops.mjs keeps (`phase, candidates, asked, count, max, current, guess, rejected, solved, learned, evidence`).
- **Denies** (their `why` is the reply, status `missing` as in ops): an answer when no game is on, the game is over, the game waits for the name, or "maybe" / "I don't know" to my guess; a clue (`guess.clue`) outside a question; giving up (`guess.quit`) outside a game; naming the animal (`guess.named`) when no game was played. The probes are checked with `world.check` before the action tells anything.
- **Actions** (`gsStart`, `gsAnswer`, `gsCorrect`, `gsReveal`, `gsGiveUp`, `gsEvidence`): the choice of the question (the most even split), how an answer or a clue narrows the animals (`truth`, shared) and the sentences are the world's; `guess.why`, `remaining`, `count`, `repeat` and `hint` stay in ops.mjs and read the derived state. A library action receives its arguments as tokens (a string keeps its quotes): `fns.mjs` unquotes them.
- **Undo** (the matrix adds this): bare "undo" with the game's tab open takes back the last turn that changed the game: an answer ("OK, I took back your last answer. I am asking that question again: ..."), a clue, a lesson ("OK, I forgot the animal you taught me.") or a new game. Nothing to take back: "There is nothing to undo." (the dialogue layer). In `ops` there is no undo for the game.

### kids.shapes on the matrix
`world.sop` says `reasoner=matrix` and `ops=<key>` (below); `matrix.sop`, `matrix.templates.sop`, `fns.mjs`. **`ops` is unchanged** (`ops.mjs` only exports `summaryWords`, the sentence of a summary, which `describeShape` now calls); `test-world kids.shapes` passes under both strategies (476; matrix 484 with 8 matrix-only tests) and a scripted session says the same words and statuses in both.
- **Facts.** The knowledge base (`kb.sop`: shapes, families, colors, mixes, things) and what the dialogue teaches are wires of the library; a taught fact is undone with the rest ("undo" gives "OK, I took that back: ...", the question is `missing` again).
- **Rules** (`matrix.sop`): a shape is `summary=round` when it has no sides and no corners and `summary=flat` when it has any (or when all that is known is a count of zero); the library answers the summary question from it, and `voice` (`fns.mjs`) words it as ops.mjs does (`summaryWords`). The families (`kids.shapes.family`) are answered natively: `holds=true` is yes, an explicit `holds=false` is no (its `because` becomes the answer's `note`), both is `conflicting`, neither `missing`; `matrix.templates.sop` has the sentences, selected by `when="value=true|false"`. The sides, corners, lists, counts, the kind of a color and the shape of a thing are native library queries answered by the existing templates.
- **`ops=<key>` (new, `core.world.ops`, repeatable): keys the matrix leaves to the operations.** A question about `type.key` is never asked to the library (`ReasonerSession.owns`), so `ops.mjs` answers it from the session memory as before. kids.shapes leaves four: the checks that carry the value they seek (`thing.is_color`, `color.is_kind`: "is a banana red?" — a library query would answer the value it was given), the colors of a thing (`thing.color`: several colors are all true, not a conflict), and what two colors make or which colors make one (`mix.result`, `mix.recipe`: the facts are read in both orders, which a rule cannot say without making a second wire for every mix).

### "why?" names the source per world
`source="..."` in world.sop (`core.world.source`) is how a world calls its own facts (no sentence of the dialogue) in "why?": kids.shop "the price list", kids.animals "what I know about animals", kids.shapes "what I know about shapes and colors"; without it the phrase is "what I know". `Discourse._known` picks the phrase of the world that owns the wire type (several worlds: "A, B and C"); the Romanian reply table has the sentences.
