# 21 — Acts and schemas: one grammar, one executor, worlds as schemas (ACTS x SCHEMAS)

Implementation: `worlds/acts/` (module world: phrase groups, legend, `acts.mjs`), generator `scripts/build-schema-world.mjs`, a schema world is a directory with `schema.sop` plus GENERATED `patterns.sop`, `operations.sop`, `templates.sop`, `lexicon.sop`, `ops.mjs` (never edited, stale-checked by test). Tests: `tests/acts.test.mjs`, fixture `tests/fixtures/worlds/test.seating/`.

## 1. Why
Every doing world (draw, diagram, avatar, Talk, charts, editor, map) has its own patterns, operations and replies, so each has its own holes and a phrase learned in one helps no other. What users ask is the same dozen acts. They are said once; a world declares only what exists in it.

## 2. The acts and their roles
Roles (same everywhere): `thing` (what), `set` (several things: "all", "the guests"), `attribute` (colour, seats), `value` (blue, 4, "Ann"), `place` (a relation and a reference: "at table 2", "next to the lake"), `amount` (a number, "a bit", "more").

| act | meaning | roles | needs |
| --- | --- | --- | --- |
| make | create an instance | thing, [value=name], [place], [amount] | |
| remove | delete instances | thing or set, [place] | |
| change | `set` an attribute to a value, `more`, `less` | thing or set, attribute, value or amount | |
| place | move / put / seat | thing or set, place | |
| connect | relate two things | thing, place (the other) | |
| group | `group` things / `apart` take a group apart | set | |
| pick | make a thing the focus ("select the first table") | thing | |
| ask | `what` (attribute value, what is at a place), `count`, `where`, `why` | thing or place, [attribute] | |
| copy | duplicate | thing | |
| send | hand a thing to another world (an effect, `ctx.host.send`) | thing, place = the world | host |
| undo / redo | one step per request | | |
| save / load | name the state / restore it | value = name | |

The English forms of the acts are written ONCE, as `core.phrase` groups in `worlds/acts/lexicon.sop` (verbs) and as FACTS, one `lang.en.frame` per way of saying an act (`handover/lang.en/shards/frames-acts.sop`, sets `acts`, `acts.more`, `acts.data`), read through `src/lang/en.mjs` (`en.frames()`; `acts.mjs FORMS` is `en.frames('acts')`). The schema worlds generate their patterns from these facts. The seed verbs are local and marked `seed=temporary`: they are deleted when the knowledge repo's `k.actions` (verb -> act, roles) is read through the catalog.

## 3. The schema (SOP Lang, `schema.sop`)
```
@seat acts.schema        noun="seating plan" acts=make acts=remove acts=change acts=place acts=ask acts=undo ...
                         limit.items=60 limit.history=30
@seat.table acts.kind    plural=tables numbered=yes max=10
@seat.guest acts.kind    plural=guests named=yes in=table
@seat.seats acts.attr    of=table type=number min=1 max=12 default=4 more="more seats" less="fewer seats"
@seat.colour acts.attr   of=table of=guest type=colour default=white
```
`acts.kind`: `plural`, `numbered=yes` (instances are "table 1"), `named=yes` (an instance has a `name`), `in=<kind>` (the container kind a `place` refers to, with `capacity=<attr>` on the container), `max`, `acts=` (restricts the world's acts for the kind), `any=knowledge` (any drawable kind from knowledge: the kind is accepted when `know.kind(word)` returns one). `tabOnly=yes` on `acts.schema` makes every generated pattern `tabOnly` (a doing world with a tab: its role slots `{thing:words}` would otherwise read the sentences of other worlds); the world then declares `tab=` and a tab plugin (`docs/webchat/ui/tabs/seating.mjs` is the 50-line one of `plan.seating`).
`acts.attr`: `of` (kinds, repeatable), `type` (`number`, `enum` with `values`, `colour`, `text`, `bool`), `min`, `max`, `default`, `more`/`less` (words), `word` (synonyms of the attribute name). Defaults of values come from the schema, then from `know.attrDefault`.
Generated from it (`scripts/build-schema-world.mjs`): `lex.<ns>.kinds`, `lex.<ns>.attrs`, `lex.<ns>.values` (lexicons), the patterns (about 40 per world, role slots `{thing:words}`, never one per kind), one operation `acts.do` per act, one template per act (`{note}`), the `meta.worlds` card words, the help examples (`examples(schema)`), and the coverage sentences (`sentences(schema)`, A5).

## 4. The executor (`createExecutor(schema, hooks)`)
State (`ctx.state`): `items [{id, kind, n, name, attrs, place}]`, `focus {ids, act, place, kind}`, `history`, `future`, `saved`, `last` (the last act with its roles and the difference), `pending`, `counter`. `run(state, act)` applies one act and returns `{ status, note, diff, guesses, why }`; `diff` = `{ added, removed, changed: [{id, attr, from, to}] }`. The reply ("I removed the glasses") and the why-answer ("because you asked me to remove them") are built from the act and the diff, once, for every world. Undo restores the snapshot taken before the request (one step); redo the reverse. Referents: `it`/`them`/`that` = focus; "table 2", the name, the kind alone (all of it when plural or the only one, else one question), ordinals, spelling slips of one letter. Bounded: every loop ticks the turn budget; `limit.items`, `limit.history`.

## 5. Delegation and the graded fallback
A missing role is filled by the first tier that has it: `said` > `focus` (`hooks.focus`, std.focus when vendored) > `scene` (the state) > `knowledge` (`hooks.know`: kind synonyms, usual place, default value) > `default` (the schema). The reply says every guess ("I used table 2, the one we just talked about"). Order of the fallback: (1) complete -> do. (2) role missing -> fill, do, say the guess. (3) the act does not exist here -> say where it does (`hooks.whereActs(kind, act)`: "a table has no hat; the avatar does"). (4) else ONE question naming the guessed act and thing, answered by "yes" / a role (the `pending` of the world, read by `interceptInput`). A bare "I did not understand" is never produced by a schema world.

## 6. What stays out
Chess legality, the hangman word, arithmetic: rule worlds that keep their moves and only declare their acts for routing. Layouts (`place` with `space`) go through `hooks.layout`. The reader tagger (P3) and the coverage grid (A5) are separate tasks.

## 7. How a schema world meets the engine (implemented)
Every pattern emits `action=<ns>.<act>` with the role arguments plus `arg.text="{segment}"` (the user's sentence, kept in the act log for the why-answer). The generated `ops.mjs` exports one function per act, `interceptInput` (the answer to the one open question: a role, or yes / no to a guessed act; a message that is a new command cancels the question and is read normally) and `outOfScope` (the engine's hook for the world of the open tab when nothing read the sentence: the guessed act and thing, one question, examples). Lexicons of attributes, values and comparatives are `class=modifier` (the engine must not take "blue" for a thing that "it" can mean). The engine's discourse layer owns "redo": it works through the world's own undo and is cancelled by any later turn, a query included; the executor's own redo is the fallback for hosts that call it directly.
Measured on the seating plan (schema of 49 lines, 41 generated patterns): 40 natural requests written without looking at the grammar, read by a rule of the grammar and answered with an act reply in 39 of 40 in both reasoners (the miss is a fragment, "a bigger table 1", which belongs to the dialogue module); reading the replies by hand showed that reading is not correctness: the first run had 9 wrong or odd answers among the 35 read (a table added for "table 2 to have 8 seats", "how many seats does table 1 have" counting tables, "table 1 and table 2" not coordinated, "next to" silently read as "at", duplicate names, ...). Each was a general cell (coordinated things, unread leftovers, relation words the world does not have, attribute questions, unique names), fixed once in the executor or the forms and pinned in tests/acts.test.mjs; the second run was correct on all but the fragment. **P2 on a fresh set of 60 (2026-11-13, `scripts/exp-seating.mjs`, world `worlds/plan.seating/`, the same schema, 49 lines):** 60 natural requests in six conversations, written before the act grammar was read, 6 of them (conversation 3) with a verb drawn from `k.actions` (read through `facts.wires('k.actions.verb')`) for the act. Both reasoners gave identical replies. Read (an act reply, not "did not understand"): 48 of 60. Right by hand (the reply read against the state it left): **31 of 60**. The 29 failures are in `training/eval/failures.jsonl` (tab `plan.seating`, class = cell): act phrase 18 (verbs of `k.actions` that the seed verbs do not hold: generate, produce, scatter, label, forget; "which table is X at", "where is X now", "what is in the plan", "how many are at", "give X N seats" read as send, "swap", "clear", "show me"), referent 9 (a name the plan does not know with a seating verb: the executor says "there is no Tom" instead of adding him; "her", "everyone", "them all" after an add, "it" over two tables), kind 1 (a list of names read as one name), executor 1 (removing a table silently unseats its guests), attribute 0. Run with every world loaded and the tab of the plan open (the default of the script; `--only` loads the plan alone) the same 60 give 31 right again; the 11 requests that nothing read get the graded question of the world ("I did not catch what to do with table 1. I can add, remove, ...") instead of the generic refusal, and two leak to another world although the tab is open ("swap Zoe and Max" to the drawing, "forget the guests" to the task list: a routing cell, the verbs are unread). The round-trip paraphraser needs the on-device translation model, which is not in this checkout: the variation came from the verbs of `k.actions` and from writing the same act several ways.


## 8. More forms and the pilot of the drawing board (art.draw, 2026-11-13)
`worlds/acts/forms.more.mjs` holds the flags and lexicons of further English forms of the acts (the forms are the facts of set `acts.more` in `frames-acts.sop`), gated by flags of `acts.schema` so that worlds that do not set the flag keep their generated files: `wish` (a wish or a need before a thing, "I want a red house", "it needs a rainbow"; a bare kind with modifiers and a count, "5 stars", "a purple tree please"; value-first and thing-first short forms; the bare verb, which asks what to make), `list` (is there / do I have / any X in there, describe the picture, what did I draw, what can I draw / what colours), `say` (count, where and "what colour is" in other words; another / one more / N more = copy), `scale` (an amount or a factor with a comparative, "a bit smaller", "twice as big"; enlarge / shrink; "move it up a bit"), `turn` (turn, flip, rotate, mirror around, upside down, to the right, degrees), `clear` (clear everything, clear the picture, a new sheet), `random` (a surprise picture, "draw something"). The world nouns ("picture", "drawing") are the lexicon `lex.<ns>.nouns` (the noun and the view words of the schema). A form may carry roles beyond the six (`m1`, `m2` modifier words before the kind, `amount2`, `noun`): the hooks of the world join them back. `hooks.referents` lets a world whose things are not `state.items` name its own. The rules formalizer now gives `accepts` the text of the segment (it was always null).

**art.draw is the generated schema world (switched 2026-11-14; `worlds/art.draw`).** `schema.sop` is the source (the colours are the open class `open=colour`, the kinds `open=knowledge`); the scene operations are in `engine.mjs`, the renderer geometry in `scene.mjs`; the world is a view of the session things (visual + spatial, `hooks.thingsOf`), with kinds `thing` (any drawable kind of the knowledge), `ground`, `sky`, `group` and attributes colour, size, fill, time, cover; it has no pattern of its own (96 generated). `hooks.mjs` maps the roles of an act onto the scene operations of `worlds/art.draw/engine.mjs` (noun-phrase resolution, placement over the space module, layouts through `draw.spatial`, drawing from facts) and rereads an act when the words say so ("put a sun in the corner" with an indefinite thing is `make`; "put them together as a hut" is `group`; "give the house a door" is `make` of a part). Not yet read, because they are not acts of the schema: parts of a thing as kinds, "the same size as", ellipsis with "one", several things in one sentence ("draw a sun, a cloud and a man"), the chart and editor hand-over.


## 9. General mechanisms of round 5 (several things, catalog kinds, parts, undo phrasing, own reader, matrix generator)
- **One undo step per request (owner rule 2026-11-13; this line said "per message" until 2026-11-14).** Only an explicit act group (`executor.group`, ids `grpN_`) is cut back to one entry; before that change `operation` of the executor records the length of the world's history (`hooks.history(state)`, else `state.history`) before the first request of a turn (the turn is read from the request id, `t3_w9`) and cuts the history back to that one entry after each later request of the same turn: "put on a hat and make it red" is one "undo". `hooks.afterGroup(state)` lets a world with its own bookkeeping (the board's `prev`) follow.
- **Several things in one role.** `splitThings(text)`: a coordination of noun phrases in the head of a role (before its first preposition), every part after the first starting with a determiner or a number. The whole phrase is tried first; when that is not a supported reply, each part runs as its own act with the other roles and the replies are joined ("draw a sun, a cloud and a dog"). The std.acts `act([...])` was not used (Q7: it has no reply, referents or domain effects).
- **Rewritten clauses keep their slot text.** The one-anaphora expansion ("a white house and a green one") builds clauses from tokens whose offsets run backwards; the matcher now takes the text of a multi-token slot from the words of the tokens when the span is not a plain slice (it was empty: "draw a green house" read with no thing).
- **Catalog kinds at pattern level.** A kind with `catalog=<knowledge world>` is also said by every lemma those shards hold in the catalog's `vocab.json` (singular and plural), generated by `scripts/build-schema-world.mjs` (parts of an object and words the schema uses as value, attribute, verb or frame word are left out). `accepts` gets `kindWord(w)` so a world can accept a bare catalog word before the lookup found its picture.
- **Parts as kinds.** `make.give` / `make.have` (flag `wish`): "give the house a blue door", "could the house have a yellow door": owner = place, part = thing; the hooks read a word that is a part of the owner (k.objects part names) as that part, not as the kind of the same name.
- **Undo / redo phrasing** of every schema world is the phrase groups `lang.undo` (new, lang.common) and `lang.redo`; the forms hold no list.
- **The world's own reader** (flag `reader`, act `own`, form `read.own`, tab only, tabPriority 30): in the open tab a sentence that the world's engine reads as a family the acts do not name is the world's. `hooks.accepts` decides ('focus' keeps it against other worlds), `hooks.domain.own` runs it. Used by the diagram pilot (forget, swap, snap, flip, fit, check, path, extreme, cycle, rules, facts ...).
- **A generated matrix.sop** (flag `matrix=yes`, `worlds/acts/matrix.mjs`): `<ns>.item` and `<ns>.state` wires with one slot per attribute, refusals from the schema (min / max, one id), tallies per kind, `fns.mjs` with `toState` / `adopt` / `stateKey` / `isView`. Verified on `plan.seating` (7 of 7 in both reasoners, conversation by hand). NOT enabled in a shipped world: with it loaded, six cases of other worlds fail in the matrix reasoner ("undo that" answers "OK, I took that back" instead of the world's own words: the turn of another world is also counted for this world); cause not found yet (open question).

## 10. Open classes by lookup, parts, act groups and the std.acts bridge (round 6, 2026-11-14)
- **Open classes.** A lexicon with `open=knowledge` and `catalog=<knowledge world>` (repeatable) matches its own words and any word the catalog vocabulary knows as a word of those worlds (`src/knowledge/open-words.mjs`, `OpenWords` in `src/worlds/lexicon.mjs`): the plural comes from the reader's lemma, synonyms are catalog words of their own, a word of the world's other lexicons or of the acts (verbs, determiners, prepositions) stays theirs, and the part names of `k.objects` are never kinds. `open=colour` is the same for colours: any colour the one colour reader (`src/knowledge/values.mjs`: k.values, spellings, chat shorthand) knows. The generator emits the two lines and NO words (the art.draw kinds lexicon went from 1,388 to 431 lines; `addCatalogWords` is gone). The lookup is synchronous (the matcher is): the dialogue calls `ready()` at the start of a turn, which waits at most 250 ms once and never again for a hanging catalog, so a slow catalog changes nothing for that turn (the reading is that of no catalog; invariant test `network-never-changes-reading`). The typo corrector's vocabularies answer `has` through the open lexicons too, so "sea" is not corrected to "sec". Schema flag `opencolour=yes` makes the values lexicon open to colours.
- **Parts as kinds.** The part names come from the `k.objects.part` wires by lookup (`facts.loadParts()` / `peekParts()`), never from a generated list; "give the house a blue door" and "the house needs a pink door" (`make.part.needs`) make a part of the owner.
- **Modes in the schema, not patterns.** `pick` has the mode `none` (deselect, nothing selected, clear the selection: flag `none`), `change` the mode `same` ("the same size as the house"), `save` takes the format as its value ("save as SVG", "download the drawing as a PNG"). Colour and size words before a kind are roles of their own (`make.mods`: `m1`, `m2`, `amount`, `thing:KIND`), so a repair ("actually make it blue") replaces the value of the request it takes back.
- **Act groups.** `executor.group(ctx, [{ act, args }, ...])`: several acts that one sentence asked for are one undo step and one reply; it stops at the first act that is not done and says why. This is the bridge of the library's `act([...])` (std.acts `_actAll`) over host state.
- **std.acts as the executor: partly switched (0.29.0, round 7).** The library carries what it can without the host's state being wires: `worlds/acts/effects.mjs` builds one World per executor (declaration `std.schema.effect of=host act=<act> action=host_effect` for make, remove, change, place, connect, group, copy, send) and gives every mutating act and every sentence of several steps to `world.act(...)` / `act([...])`. (1) **Sentences are all or nothing:** `executor.group(...)` and the parts of one act ("draw a moon, a star and a ghost") run as one `act([...])`; the first step that is not done undoes the earlier ones (a snapshot of the session state taken for sentences of more than one step, restored in place), where the bridge left them done under one undo step; a refused group says "I changed nothing". (2) **The difference** of a mutating act (things added, removed, changed, from the world's `referents` signatures) is `diff.effects` of the library act and comes back as `diff` of the result. (3) **Reserved names do not meet:** the state of these worlds stays outside the wires (`items`, `history`, `future`, `log`, `focus` ... are keys of the session state, not slots), so `kind`, `world`, `id` and `std.*` types are not in play. What is still bridge, and why: (a) **replies** are the host's words: the drawing board, the diagram engine, the face and the chart say what they did in their own sentences, and the generic executor's `label`/`labels`/replies read host items, so `actReply` templates have nothing to be filled from until a world's reply is made from a diff (the templates are available in the library: `actReply(w, req, res, { templates })`); (b) **referents by words** (sopworld 0.38.0 vendored; since the round after 0.29): `worlds/acts/np-lib.mjs` puts the executor's things on a World as `std.schema.thing` wires (id `<kind><n>`, name, attribute values, `at=`), names the open classes of the phrase (kinds, values, names: the schema owns them) and calls the library's `resolve(phrase)` over `std.grammar` reading the facts of `lang.en` in place (`np`, determiners, numbers, prepositions, pronouns); ids and tier come from the library. What stays host code, and why: the **failure classes of the replies** (no such kind / none of that kind / nothing in focus / a number nobody has: the library returns `why` and the executor chooses the words), a **bare name** ("Ann": no rule NP -> NAME), **choice / part of a set / the other one / relative clause** (`en.nounPhrase`, `src/lang/np-resolve.mjs`: the grammar facts carry them as `status=read` through the host reader, `resolve` does not), **coordination** (`lang.en.coord.sep text=` is not the library's `g.coord word=`; "tables 1 and 2" distributes a bare number), the **focus rule** (only a bare pronoun reads the focus; the library also lets the focus pick among several, the executor asks), the reading of "table 3" as *the thing numbered 3* (the library falls back to the third table), a plural noun with no determiner as every one of them, and the **guess sentence** of a pronoun; the drawing board's own noun-phrase code (`art.draw` engine: kind, colour, size, place, ordinal, spatial relation over its scene) is not on wires and stays. **Defaults (`std.know.fill`) are not used here**: it fills a key of the library's own `make`, and no executor world runs its `make` in the library (the state is off the wires); the host lookups that fill defaults (`habitat` in `src/knowledge/commonsense.mjs`: the places of the facts of the scene, the commonsense catalog, the kind-of chain and learned facts, with zones and advice; `know.attrDefault`, `know.kind`) are richer than one catalog and one key, so they stay; (c) **history** (`undo`, `redo`, one undo step per message: `stepGroup` over the engine's separate requests): each world keeps its own timeline of snapshots, and the engine calls the clauses of one message as separate actions, so no library sentence spans them; (d) **questions and pointers** (`ask`, `pick`, `save`, `load`, `own`) are not effect acts of the library and are called as they are; (e) the generic executor for worlds without a domain function (plan.seating, plan.timeline: items in the session state) is the bridge's `run()`. The list is in questions.md (Q11, status entry).


## 11. A data world on the acts: data.charts (2026-11-14)

- **The decline hook** replaces the hand-written `interceptInput` of the chart (regexes for remove, add, what is, colour): a sentence is the chart's when it names a chart, a bar of the open chart or data, and `focus` when the open tab is the charts and the sentence is "what is <bar>".

The matrix files (`matrix.sop`, `matrix.templates.sop`, `fns.mjs`) are gone: the chart is no longer a matrix world.

## 12. The map on the acts: a pilot that reads places by lookup (geo.map, 2026-11-14, NOT switched)
`worlds/geo.map` (SWITCHED 2026-11-14: 394 / 441 own tests in the ops reasoner after the test values were derived from the catalog, 90.5% of the old world; the 43 rows left are in the ledger, build `geo-map-switch`) is the map as a schema world (`schema.sop` 197 lines: kinds `place` (any place of k.geo: country, city, river, mountain, continent, region, lake, sea), `pin`, `route`, `label`, `view`; attributes name, colour, zoom, centre, layer and the read-only facts of a place: capital, population, area, currency, language, continent, neighbours, landlocked; acts make, remove, change, place, pick, ask, send, undo, redo; flags `say list rel facts clear opencolour`, `boost=5`). The expected values of `tests.sop` are derived from the catalog by `scripts/derive-geo-map-tests.mjs` from `tests.template.sop` (placeholders `{{pop:Tokyo}}`, `{{nb:Hungary}}` ...): the rows measure the reading of the sentence, not the numbers of an older table. The sentence forms over any attribute or relation of a place are frames of `lang.en` (set `acts.facts`: `ask.*` and `layer.*`), not map patterns. With no catalog the map knows no places (no local table).
- **One reading path for places.** The map keeps no table of places. `places.mjs` builds the index (countries, cities, groups, other names, the capital of a country) from the catalog's `k.geo` wires; the host loads them before an operation through the world's `needs` hook (`wires:k.geo.country`, `wires:k.geo.city`, `wires:k.geo.group`, `wires:core.word@k.geo`; `knowledge.peekWires(type)` reads them synchronously), the same way the avatar's faces are loaded. A river or a mountain is the `thing()` lookup of its name (`openSlots`). What k.geo lacks (box and aliases of 38 regions) is `regions.mjs`, listed in `handover/knowledge-out/catalog-lacks.md`.
- **Reading a place** (`open=place`, `catalog=k.geo` on `lex.geo.map.places`): `knowsPlace` in `src/knowledge/open-words.mjs` asks the catalog vocabulary: names of several words ("new york"), accent-free spellings ("sao paulo" for "são paulo"), a plural name by the lemma ("united_state"), a place by the relation k.geo states ("the capital of Sudan", "Sudan's capital" is Khartoum), and never a colour or a word that only the schema's doc lists ("river", "north"). The accepts hook uses the same function, so the arbiter and the lexicon agree.
- **The geographic aspect as a view.** `view` / `adopt` are the map's operations of the transfer slice (spec 23 section 9), unchanged; the host now also loads the `needs` of the view a `things.show ... to=<view>` request names (`preloadThings`), so a thing handed to the map is looked up with its places loaded. A `send` whose target is the map is the source view's act, not the map's (the accepts hook says so).
- **What the acts read and what they do not.** make / place of a pin (put a marker on Paris and Rome), remove a pin, highlight or line (take the pins off the map), pick a place (show, highlight, mark by the verb), ask where / capital / population / area / currency / languages / continent / neighbours / landlocked (`facts` frames: what currency does Japan use, how big is Romania, is Hungary landlocked, does Spain have a coast), the place act of the view (move west, pull back a bit, put a marker here), change of zoom, layer and centre. Not acts, kept as the world's own operations with their hand patterns (`patterns.extra.sop`, 216 patterns): show / go to / fly to a place, compass pan, zoom in / out, the whole world and reset, coordinates, comparisons, superlatives, counts and lists, distances and lines between two places, "is X in Y", the capitals of a continent as markers, where am I, what is here, describe the map.
- **State.** The map keeps its own state shape (`center zoom bounds markers highlighted lines layer focus me`): `hooks.noState` tells the executor not to add its `items / focus / history / log` keys (the map's `focus` is a place, not a selection) and not to log acts; undo and redo are the map's own snapshots.
- **Measured** (numbers in worker-log "geo.map pilot"): own tests 246 of 441 in the ops reasoner (55.8%; the old world 441 of 441), 257 of 459 in the matrix reasoner (the pilot has no matrix: the 18 matrix-only rows cannot pass); with the map tab open 241 / 252; owner log a 45 right / 10 wrong identical to today, logs b and c unchecked as before; T1 map column 3 right / 31 said plainly / 0 wrong, identical; gain set "place where" 0 of 40 today, 40 of 40 by lookup; of the 195 failing rows, 112 are a different fact in the catalog (or the rows after it in a session), 55 a sentence form that the acts do not generate (which countries border X, how many people live in X, take X off, no more X, pull up X), 16 another world answered, 12 a name k.geo does not list (Cluj, Peking).
- **Decision.** Below the 90% of the switch rule on its own tests, so the world is not switched; the old `worlds/geo.map` stays, the pilot is the comparison and its 195 rows are in the ledger (`build: geo-map-pilot`). What would make a switch pass is not a pattern: the catalog's facts (the data class, 112 rows: the tests would be re-derived from k.geo), the frames of lang.en for attribute questions (55 rows) and an act of the view (zoom, pan and show with an implicit thing: the map's grammar is navigation, not editing).
