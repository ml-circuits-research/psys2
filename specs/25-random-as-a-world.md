# 25. Random as a world (host side of `std.sample`)

Historical implementation: implemented with sopworld 0.59 (vendored 0.62) (`sample`, `diversity`). Code: `src/dialog/sampler.mjs`, the worker op `sample` in `docs/webchat/ui/engine-worker.mjs`, the host in `docs/webchat/app.mjs`. Tests: `tests/sampler.test.mjs`. Measurement: `scripts/measure-dice.mjs` (rows in `training/eval/dice-samples.jsonl`).

## Rule
No hard-coded examples and no generator of our own. The dice, the example chips and the action buttons all come from the library's `sample`. Deleted by this spec: `docs/webchat/surprise-pool.json` (214 hand-validated texts, a 25-minute build), `src/dialog/surprise.mjs` (pool build and picker), `tests/surprise.test.mjs`, the welcome examples (`EXAMPLES` in app.mjs), the empty-state lists of the Talk, Charts, Editor and Documents tabs and the "Try: ..." hints of the Map and the editor view, and the generator of `scripts/coverage-grid.mjs` (forms x verbs x kinds, with its placeholders).
When the library has no sampler, `available` is false, every call returns `[]` and the host shows no dice result, no chips.

## The library interface (0.59, confirmed against `docs/api.md` and the source)
`sample(world, { seed, n, mode: 'one' | 'few' | 'actions', prefer: { world, thing }, seen, realise, read })` returns `{ frames: [{ action, args, world, why }], tried, kept, roundTrip? }`. The frames are language-free and legal in the world's state (a dry run on a fork). It reads `std.schema.kind` (acts per kind), `core.slot` (enum, range, join), `std.schema.kinds from=` (open kinds from facts) and the things of the world, and weighs recency, novelty (`seen`, the history) and chance. `diversity(frames)` counts acts, kinds, attributes.
Differences from the first description of this spec: the library takes a `World` the host built (not a host object), the language world is the host's (`realise`/`read` are optional hooks), and `mode: 'one'` draws a frame among several (`undo` is offered even when the host has nothing to undo).

## What the host states to the library (`sampleWorldOf`)
Per schema world (`acts.schema`, spec 21), rebuilt for each call from the session:
- a type and a `std.schema.kind` per kind, with the acts of the kind, minus the acts the schema marks `dice.not=<act>` on the kind (acts that need words, a second thing or data: a heading needs its text, an arrow two shapes, a route two places); `make` of an open kind (`any`) comes from its nouns as facts (`std.schema.kinds`), minus the generic words (object, item, shape, thing); `make` of a kind that lives `in` a numbered/named container needs that container; `make` of `group` is the act group.
- a `core.slot` per attribute: enum and colour values as plain words (at most 14, no `light_red` forms), a number with its `min`/`max`; a text attribute has no slot (the host does not invent words).
- one wire per thing of the session (the world's `referents`, at most 40), typed with the schema kind it belongs to.
Schema attribute added: `dice.not=<act>` on `acts.kind` (`worlds/acts/acts.mjs`, parseSchema; the generated `ops.mjs` carries it).

## Host checks the library cannot make
`undo` only when the world has history; a `change` to the value the thing already has is dropped; the label of a thing is the world's own (`executor.labels`), made unique by its colour or its name when two things read alike, and dropped when it stays ambiguous; attributes named like prepositions (`to`, `from`) are not said as "Set X to to V".

## Rendering
`realise(frame)` (sopworld 0.71, 2026-11-14): the sentences are the generation templates of `w.lang.en` (`w.lang.en.template`, bundled in `src/knowledge/bundled-compose.mjs`), filled by the library's `realise`; the host (`src/lang/en-generate.mjs`, `actSentence`) picks the template of the act whose slots are exactly the roles of the frame and supplies the English plural and the article (a, an) from the world's facts. There is no host template in `src/dialog/sampler.mjs`: make "Add a K.", remove, copy, pick ("Select L."), undo, redo, change "Change the A of L to V.", ask "What is the A of L?" (no attribute: no sentence). A thing named from knowledge keeps its own verb (the entry says it). The round trip (`read`) is not used yet: the measurement judges by state instead (`scripts/measure-dice.mjs`, which also reports the dry-read rate).

## Host uses
1. Dice in the input bar: `rollDice(view)`, worker op `sample` mode `one`: the open tab's world, else a world used lately, else any loaded schema world; a sample of another world's tab opens that tab first.
2. Talk: 3-4 examples (`few`) from the worlds of the session, refreshed after each turn; the welcome message shows the same.
3. Every other tab: the acts that fit the selected (salient) or newest thing (`actions`), in the strip above the input, refreshed after each turn and on each tab change.
4. A small dice in the corner of every tab panel but Talk (full-screen tabs), the same `rollDice(tabId)`.
5. Empty states of Talk, Charts, Editor, Documents ask `host.sample('few', { tab })`.
6. `scripts/coverage-grid.mjs` (grid v3): the cells of a world are a walk of the sampler (`--per`, default 40) with the walk before a cell as its setup.

## Measurement (2026-11-14)
`node scripts/measure-dice.mjs --per 23` presses the dice in one session per tab world, with the tab open, and judges by state: a changing act must change the state of any world except the conversation's own bookkeeping, and must not answer with a counter-question; a question must be answered and supported. 207 samples across 9 tab worlds: see `docs/lessons.md` and `worker-log.md` for the result and the diversity (acts, kinds, attributes), and `training/eval/dice-samples.jsonl` for the rows.

## Known limits
Every schema world publishes its referents the same way: the default `referents` of the executor reads `state.items`, and a world whose things live elsewhere declares WHERE in `schema.sop` with `thing=<state path>:<kind>[:<id key>[:<name key>[:dice]]]` (a fifth field `dice` marks things that only the dice names: pronouns and "the last one" do not resolve to them; the reader's documents, whose own context is its search results and sections) (data.charts `thing=charts:chart`, geo.map `thing=markers:pin` and `thing=highlighted:place:cc:name`, media.music `thing=current:song`, docs.reader `thing=docs:document::title`). The executor derives id, kind (the entry's own `kind` when the schema has it), name (named kinds only), `n` (the position in the list: "chart 2" is the second chart, "list 2" the second list of the document, never the digits of an id) and the schema attributes the entry carries. A hook `referents` (art.draw, diagram.sketch, docs.editor) still wins. Kinds whose acts the world cannot do from a sentence are marked `dice.not=<act>` (a document cannot be re-added, a pin has no colour, a song is not changed or removed by name).
The avatar world has no sampleable kind; its dice falls back to another world.

## Roles from knowledge, weights, round trip (2026-11-14)
- **Knowledge lists.** A kind says `know=<list>[:<verb>]` in `schema.sop`; the world publishes the lists with its hook `sampleKnowledge(ctx)` (`{ list: [text | { text, act }] }`, read from the world's own knowledge, never typed): geo.map `places` (countries and the biggest cities of the place index; verb `show`) and `distances` (whole sentences, act ask), media.music `songs` / `scales` / `chords` (library songs, the scale and chord types of theory.mjs on every pitch class), data.charts `charts` ("Make a bar chart of the legs of the river animals.": the habitats and classes of k.animals the reader takes) and `bars` ("Add parrot 2.", only when a chart is open), docs.reader `search` (keywords of the open document), `sections` ("Read section 2.", "Summarize section 2."). A verb `*` means the entries are whole sentences; no verb means "Add <entry>."; `act` overrides the frame's act. The host adds `colours` (k.values) for every colour attribute (and any attribute with `know=<list>`). A seeded subset of 30 entries per list is stated to the library as the names of its one open kind per world (`std.schema.kinds`; the library takes a plain token, so an entry is named by its slug and the host keeps the text).
- **Weights.** Undo: only after a change the dice's own press made (the history grew after an offered change), and at most about one press in ten (a seeded roll). Redo: right after the dice's own undo (70 %). A kind or act shown counts double in the library's novelty (`seen`), and one sampler does not repeat a sentence it showed while other tries remain.
- **Round trip.** The library's `read` is synchronous and the host's reading is not, so the round trip is measured host-side: `scripts/measure-dice.mjs` runs `session.dryRead(text)` on every press (a copy of the session) and reports how many sentences are read as one whole message.
- **Limits.** Objects of art.draw come from its built-in nouns: the catalog's things ("Draw a giraffe") need the knowledge catalog (`PSYS2_KNOWLEDGE`), which this machine has not.
- **Measurement (207 presses, 9 tab worlds, `training/eval/dice-samples.jsonl`):** executed 205/207 = 99.0 %, round trip 205/207, 192 distinct sentences (about 185 of 200), 8 acts (make, copy, remove, undo, redo, ask, change, pick), 81 kinds, 19 attributes.

## Declared schemas (2026-11-14)
Worlds with their own patterns and operations (user.profile, games.chess, games.guess, games.hangman, games.tictactoe) declare a schema with `declare=yes` (spec 21 section 6) and publish whole sentences with `sampleKnowledge` from their own state; the dice, the chips and the buttons serve them like any schema world. The states in which a game has nothing to play (a finished game, not the user's turn) give no sentence, and the dice falls back to another world.

## The Diagram tab (2026-11-15)
The dice of the Diagram tab no longer says only "Add a circle.": the `text` kind carries `know=diagrams:*` and the world's `sampleKnowledge` publishes `diagrams`, whole sentences "Make a <kind> of <topic>." for each kind x topic the knowledge can draw (`diagramSentences`, spec 14 section 9: the library's `diagramTopics`, kept when the request composes and reads back). 30 presses on the tab: 30/30 executed, 30 distinct sentences, 23 kinds of thing (`scripts/measure-dice.mjs --world diagram.sketch --per 30`). Repeated presses draw on top of what is there (undo takes the last one away).


## Chips from what comes next (owner export 2026-11-14 22:43)
After a sunny scene with a house and a dog the chips offered "Add a weapon.": the drawing board gave the sampler every lemma of the catalog's vocabulary that has a drawing, so a chip named a random catalog word. The rule now: the knowledge list a world gives depends on the mode (`sampleKnowledge({ ..., mode })`). The dice (`one`, "something random") may draw from the whole vocabulary; the chips (`few`, `actions`) name what comes next in this picture: art.draw `nextThings` reads the catalog's scenes (k.scenes.has: the scenes each kind of the picture is in, then the other things of those scenes, ranked by the number of the picture's kinds they share a scene with, kept when they have a drawing). The wires are fetched after the turn by the discourse hook `nextNeeds` (`prefetchNext` in src/dialog/knowledge-lookup.mjs: never awaited by a turn) and read synchronously (`facts.peekWiresBy`). When the world fills a kind's knowledge list in chip mode the built-in nouns of that kind are not offered (`sampleWorldOf` `preferKnown`); before anything is fetched the chips act on the things of the picture and name the built-in kinds. Measured on the live catalog after "draw something random": next things bee, butterfly, snail, person, bush, fence, rabbit, grass, bench, squirrel, tulip, duck; chips such as "Add a bush.", "Add a fence.", "Add a bee.", "Change the colour of the house to red.". Tests: `tests/sampler-next.test.mjs`.
No weapons by default: the catalog has no sensitivity or audience key (the live index was searched), so the dice, which still draws from the whole vocabulary, cannot exclude them by a rule of the catalog yet: asked as [KNOW] (questions.md Q21). The chips exclude them by construction (only what the picture's scenes have).

## The example bar of a page, in the selected language (reviewer 2026-11-15 03:15 item 3)
The example bar shows the open page's own chips: the acts that fit its selected (or newest) thing (`actions`), and when the page has none yet, examples of the page's world only (`few` with `onlyTab`: the worker's order of worlds is the tab's world alone, no other loaded or recent world, no default dice world). Only the chat page (and the greeting) shows examples of every world. A chip is shown in the selected language: `chipsInLanguage` (src/dialog/sampler.mjs) says each English chip with the rules translator (its tables and grammar, never a machine translator), keeps it only when the translation is complete AND reads back to the same English command (the tapped chip reads as what it shows), and keeps the English in `en`; a chip it cannot say is left out, never shown in English. The bar is refreshed on a language change. Test: tests/chips-page-language.test.mjs.

**Natural or nothing (reviewer 2026-11-15 04:50 decision 3).** A chip in a language other than English is shown only when it is natural. Natural means one of two things. (1) It is composed from the language world's act templates. This is pending: Q25 K4 asks for w.lang.ro request templates, and no language has them yet. (2) It is a rules translation that the grammar realised without a calque. The English→Romanian grammar (`src/translate/en-ro.mjs`) lists in `calques` each construction it can only say word for word. The text still comes back, so a reply keeps it. Two kinds are listed today: `of-genitive` ("of" before a definite noun phrase or a name, said "de": "Ce este mărimea de c1?" for "What is the size of c1?", where Romanian takes a genitive) and `no-verb` (a clause with no verb read, said word for word). `chipsInLanguage` leaves out a chip whose translation has a calque. The rule is general: it does not depend on a world or a sentence. When the act templates land, path (1) comes first and the calque check stays as the guard of path (2).

## Sensitive things are never offered unasked (reviewer 2026-11-15 03:35 (a), knowledge Q76)
The catalog marks lemmas `k.kinds.sensitivity name=<lemma> sensitive=weapon|drug|alcohol|tobacco` (shard k.kinds/shards/sensitive). `src/knowledge/sensitive.mjs` loads that one shard in the background when a sampler is made (never awaited by a turn), and `engineSampler` drops a thing found there from every list a world gives the sampler (`sampleKnowledge`: the dice's vocabulary, the chips' next things) and from every sampled item (`sample`, `actions`, `dice`), unless the user named it in the last turn (its English or the words as typed, singular or plural). Before the shard arrives, or at a catalog commit without the type (the current pin ab3b2ab), nothing is known sensitive: the filter starts working when the pin moves to a commit that has it. Test: tests/sensitive-chips.test.mjs (a fixture catalog; fails with the filter off).

## New-reader application integration (2026-11-17)

The new worker uses `native-request-sampler.mjs` to adapt declared native operations, exported semantic bindings and actual observations to the existing sampler schema. `std.sample` chooses frames and the existing English language world realises them; no example list or sentence parser is added. Candidate properties use finite declared enums, bounded numeric ranges or the same knowledge value source used by native execution. Existing objects come from the current observation.

At most eight proposed sentences go through the normal SOP-BERT route on independent state copies. Only an observed changing effect with the sampled act is offered; creation must create the sampled kind, and a change must affect the sampled existing id. Probing never commits changes or journals. If the live state changes during generation, suggestions are discarded. Sampling and actual turns serialize model use; unsupported areas and missing reader/bindings report no suggestion. The dice sends the chosen sentence through the normal user-turn route, retaining correction and undo. This does not bypass the reader or certify broad semantic accuracy.

Current generation covers creation and changes with declared finite values, with novelty retained between rolls. It does not generate arbitrary free text, complex relations or scheduling values without finite declared generation contracts. Non-English UI proposals use the existing machine-translation boundary.
