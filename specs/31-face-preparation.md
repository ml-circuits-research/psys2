# Truthful face observation and explicit host preparation

This implements a bounded host preparation boundary. It is not Avatar-to-Drawing integration or a new-path binding. The legacy `faceOf` helper still initializes/migrates state for legacy readers; that path has not been declared replaced. The previous audit incorrectly said `toolView` called `faceOf`: it was already read-only, but reported a synthesized default face when no supported face was stored.

`toolView` now reports only a stored version-2 face. An absent or older-format face yields no supported face facts; this is not a proof of empty-world coverage. A sparse version-2 face does not acquire a preset or parts merely because it was observed. The legacy application's initial state explicitly contains the default face it displays, so normal startup observes real baseline state. Session construction is the baseline, not an undoable user action. The standalone preparation tool below provides explicit undoable actions for supplied state.

`createFacePreparation({instanceId,state,catalog})` requires a JSON-serializable state (cycles and BigInt are rejected before ownership), and copies and owns the supplied host state and catalog for one in-memory lifetime. `observe()` returns copied state, available face facts, instance identity, version and status (`uninitialized`, `migration_required` for older formats, or `ready` for a version-2 representation). `ready` identifies the supported representation; it does not assert semantic completeness or validate every catalog value. No observation creates, repairs or migrates state. Restoring a snapshot creates a new lifetime with a fresh instance ID; version zero alone is never a cross-instance identity.

| Resolved host operation | Behavior |
|---|---|
| `initialize`, explicit catalog `preset` | Requires the face property to be absent and the preset to exist. Creates the catalog face while preserving every unrelated state field. An existing face is never overwritten. |
| `migrate`, optional explicit `preset` | Supports sparse version-2 records. Uses the stated preset or the record's existing preset; rejects an unknown preset, an explicit preset conflicting with the stored one, or malformed record fields. Fills missing structural fields and colours, records new catalog slots as absent (`none`), and preserves existing values and extensions. Older versions require a separately declared converter and are refused here rather than guessed. |
| `undo`, target operation identity | Restores the exact state before a recorded preparation only if no later state-changing operation intervened. Restoring absence is distinct from restoring an empty face. A successful undo is a new version. |

Every command carries `operationId`, `instanceId` and `expectedVersion`. Stale/wrong-instance commands are refused without mutation. A repeated successful command identity with identical arguments returns its original receipt without reapplying the change, including after undo; `currentVersion` distinguishes the present version from the original receipt's observation. Reusing an identity for different arguments is refused. A no-op migration has a receipt but does not increment version. Results and observations are copies, so callers cannot mutate owned state through them. Receipts are local to the tool lifetime and are not a persistence format or the pending shared trace contract.

This tool owns a copied state; legacy reader mutations are not silently routed through it. A future integration must choose and bind one authoritative state owner, initialize/migrate explicitly, and make ordinary face edits participate in the same version/history protocol. It must not keep this tool and the old singleton as competing writable stores. No picture-placement, multi-face identity or language behavior is claimed by this preparation.
