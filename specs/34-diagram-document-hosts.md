# Declared native hosts for Diagram, Document and Charts

These adapters expose native capabilities to the new request coordinator. They accept resolved structured arguments, never sentences. A reader, resolver and planner must establish the intended operation and its arguments before invoking a host. Registering these adapters does not establish English coverage or verified request satisfaction.

## Shared transaction and observation contract

`createDiagramHost` is asynchronous because it loads the vendored native engine. `createDocumentHost` and `createChartHost` are synchronous. Each accepts `{state, instanceId}`; Document also accepts explicit knowledge `composer` and `rewriter` providers. Each returns `bindings()`, `observe()` and `invoke(packet)`. Operation declarations give stable IDs, acts, native target types and closed typed parameters. The coordinator can register every returned declaration together, without routing by example sentences.

A packet has exactly `{invocation, expectedVersion, operation, args}`. Arguments must be finite ordinary JSON: accessors, hidden properties, symbols, cycles, sparse arrays, class instances and undefined values are rejected. Declarations supply explicit defaults and enum/range constraints. Unknown fields or operations refuse before mutation. Native handlers operate on detached staged state; failure discards both mutation and queued UI effects. The staged population and receipt data are checked before committing. Read-only or otherwise immutable root state refuses mutation. Limits default to 10,000 population objects, 100,000 copied data nodes, depth 48 and 4,000,000 code units of serialized state; callers may lower population/string limits. At most 10,000 successful invocation receipts are retained per host.

An observation is `{instanceId, version, scope, complete:true, objects}`. Completeness means the entire declared native population, independent of viewport, selection, active chart or current document focus. Every object has `id`, `kind`, `sourceType`, `source`, `version` and property `inputs`. Input values are canonical SOP scalar tokens: strings remain quoted and numbers remain numeric. Numeric bindings additionally declare unit/dimension/frame where supported. Link objects retain endpoint IDs and predicate. The instance identifier must be fresh for a newly loaded native store. A source combines instance, scope, native ID and incarnation counter. Removing and subsequently restoring an ID, including undo, creates a new incarnation. A delete/recreate that occurs externally entirely between observations cannot be detected; external store replacement must create a new host instance.

The version changes when the complete native state changes, including history or focus metadata. A stale expected version refuses. Repeating an identical accepted invocation returns its historical receipt with `replayed:true`; it does not reapply the operation or assert the current state still equals the historical result. Reusing the ID with a different packet refuses. The coordinator must not replay deferred UI effects twice.

Receipts retain complete `before`/`after` snapshots, versions, operation and invocation identity, changed native IDs, optional native data and deferred UI effects. Their `verification` is always `unverified`. `changed` means native state changed, including history; it does not prove requested semantic properties. A separate published assessor must bind request/step/invocation and compare the relevant typed observations. The coordinator owns request identities, resolution, expectation capture and any sayable assessment. No receipt-derived success claim is permitted.

## Native capabilities

| Area | Declared families | Observed population and boundaries |
| --- | --- | --- |
| Diagram | Node creation, colour/size/label changes, absolute placement, layout, removal; link creation/removal; observation, undo and redo | All nodes and links, including template/layer nodes. Positions and sizes use canvas pixels in `diagram.canvas`. Colours are the actual engine legend enum, discovered at construction; arbitrary RGB strings are unsupported. Node creation admits the engine shape family except free text, with 1–12 nodes and declared size/layout grades. |
| Document | Write explicit blocks, compose through supplied knowledge provider, rewrite through supplied knowledge provider, block text change/removal, complete section removal/reordering, document removal, observation and history | Whole document, every block and heading-defined section. A section begins at a heading of level 1 or 2 and includes its following blocks until the next such heading. Reordering requires an exact permutation of all sections and preserves preface blocks. |
| Charts | Create explicit numeric series, change chart title/type, change an indexed value, remove charts, observe and restore history | Every chart and every indexed point, independent of active chart. Current native contract admits one finite numeric series per chart, up to 200 labels, with optional source IDs; unsupported multi-series stores refuse observation instead of hiding data. |

Diagram uses the existing structured native engine command executor, not its sentence formalizer. Native placement/layout may apply collision/bounds behavior; actual coordinates are observed, not assumed equal to requested coordinates. Multi-target operations require every requested ID to exist and IDs to be unique. The adapter never silently edits only the resolvable subset.

Document's explicit write input admits paragraph, heading and quote blocks with text, optional heading level and source IDs. It writes content through the existing document model so the renderer sees the same structure. Composition requires an injected available source-backed composer; absent composition knowledge is an explicit refusal. Rewrite requires a provider that returns actual replacement blocks, not a tone label masquerading as rewritten text. Providers are trusted deterministic C2 knowledge services, never generative LLM calls. Tone, genre and length satisfaction are not certified by these adapters. Existing source IDs survive composition where the provider supplies them. Document removal and section operations update native history so undo remains available.

Charts consume explicit labels and finite values rather than guessing a dataset from a sentence. Numeric points are dimensionless values in the `chart.data` frame; no physical dimension is invented. The host retains supplied source IDs but does not certify them. All returned state remains compatible with the existing chart renderer.

## Native dependency closure and integration

The shared wrapper is `worlds/native-tool-host.mjs`. Diagram retains `diagram.sketch/tool.mjs`, `core.mjs`, `engine/logic.mjs`, `engine/auto-layout.mjs` and `engine/templates.mjs`. The vendored engine currently contains additional unused formalizer code; this adapter invokes only structured commands. Document retains `docs.editor/document.mjs` and `model.mjs`, with an explicit composer injection point. Charts has no dependency on its legacy sentence-reading module. These dependencies must be retained during old-route removal until equivalent native tools are extracted.

Shared worker/app registration and UI effect application belong to the coordinator lane. The adapters do not register themselves, import a request reader, add a legacy fallback, or vendor a library release. Tests exercise native families, detached observations, source incarnation changes, stale/replayed invocations, missing providers and invalid-data rollback. Native test success alone is not browser or real-English acceptance.
