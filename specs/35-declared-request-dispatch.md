# Declared request dispatch across native areas

## Boundary and evidence

The application binds published request graphs to declared native tools. Native parameter names are not semantic declarations. An operation becomes eligible only when its area declaration maps the request act, target role and each consumed constraint to a native argument. The generic coordinator must not know English phrases, colour names, object examples, scheduling rules or document prose templates.

The complete request graph is validated before any effect. A request with no root may contain flat result constraints: all owned constraints outside selector closures form an implicit conjunction. A genuinely empty result is valid for an act such as creation or removal. Target selectors describe the object being selected; result constraints describe the required result. They cannot be exchanged or silently discarded. Relation goals remain separate target identities.

An admitted projection retains the declaration identity, original semantic nodes, observed instance/version and all value mappings. Every request attribute and semantic node must be consumed by a declared capability or cause an explicit no-effect refusal. Unknown kinds, values, units, time frames, quantifiers and logical structures never become guessed native arguments. Missing required native arguments remain missing rather than receiving application-invented defaults. Defaults explicitly present in a native declaration remain native defaults, not interpreted user intent.

## Shared execution

Published `prepareRequestBatch` validates every graph and explicit dependency edge before dispatch. Each entry keeps its detached namespace. `requestBatchFrontier` controls readiness: a native receipt marked unverified never unlocks a dependent entry; independent entries may proceed. Neither wire order nor array order implies a dependency or conversational reference.

Area registration supplies the native host constructor, state location and semantic argument projections. Drawing, Diagram/Charts, Document and Calendar register through the same boundary. The host supplies observed identity, stale-version protection, atomic staging, policy checks and replay-safe receipts. Replayed historical receipts must not be reassessed as new effects. The coordinator retains actual unsupported projections and partial understanding without reporting success for unexecuted parts.

Native mutations are reported as unverified until their exact semantic claim is supported by a published assessment over retained observations. Existing Drawing native-property assessments remain available. Lifecycle assessments require complete lifecycle populations and incarnation identities; viewport absence cannot prove removal. Calendar policy acceptance is not proof that a requested natural-language time or participant was interpreted correctly.

## Acceptance

Validation must exercise independent declared native families, varied kinds and values, ambiguity, missing arguments, selectors distinct from results, rootless flat conjunction, unsupported semantic nodes, historical replay, stale state and blocked dependent entries. Browser packaging must include every registered host dependency. Owner English replay remains a separately reported development measure; host API coverage does not imply phrase coverage.

## Current implementation boundary

The published integration adds batch orchestration and a conservative flat-graph admission view, plus the general frame reader as a parallel declared proposal provider. The original property profile remains a parallel provider; provider failures do not cause a call into a retired reader. Distinct surviving graphs remain alternatives rather than being deduplicated by act/target shorthand. The existing assessed Drawing path accepts a sole flat result without inventing a root. Other native family argument projections and coordinator registration are still being integrated by functional-class lanes. The batch boundary currently retains all successful native receipts as unverified; no dependent entry can execute until a correlated assessment hook is implemented. This is intentionally not a claim of completed cross-area dispatch.
