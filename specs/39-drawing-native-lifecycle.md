# Drawing native lifecycle adapter

The declared Drawing host operates on the actual `art.draw` board instance. Creation uses `board.makeObject`, the renderer's complete enumerable native kind family and the board's native ID allocator. This preserves object geometry, parts, fill, layer and renderer defaults; it does not substitute an ellipse for an arbitrary semantic kind. Canonical knowledge-kind identity to native kind remains a separate declaration/resolution responsibility. Composite knowledge drawings require explicit registration and are not silently admitted by this fixed native family.

Creation and change expose explicit native x/y/size, optional name metadata and an exact RGB override or null. Names are observable object metadata, not a promise to draw a text label. Numeric coordinates are canvas pixels; defaults are the actual board constructor's centre, kind size and absent colour override. Colour names are not parsed here. Native absence/null is not a claim about the effective rendered default. No habitat inference, automatic extra landscape object, language reader or model proposal is called.

Creation, changes and removals use the shared staged transaction boundary and actual board history. Removal requires every requested object to exist. A no-op property update does not add history. Undo/redo use the board's existing snapshots. The observation exposes visible board objects, their grouped members and rendered constituents. Hidden objects and view-independent board fields remain addressable through the semantic state. Each record retains the shared host's source incarnation and version; removed then restored objects receive a new incarnation. Replay receipts stay historical and unverified, stale snapshots refuse, and malformed native requests cannot partially mutate the board. Effects are never reported as assessed semantic success.

### Operational authority

The application owns one canonical Drawing carrier. Its `sop` contains the current board, objects, group membership, vector primitives, points, transforms, scenes and relations. The closed instance schema governs every field. A native tool decodes temporary working rows and commits changed content as validated SOP facts. Renderer data is reconstructed from the same facts. Edited vector parts have exact governed facts. Constituents derived from stock renderer shapes and the view controls retain independently observed evidence.

Selection, view preferences and native undo/redo records are carried as separate runtime data. Saving serializes the semantic instance separately from that runtime data. Old archives are admitted by comparing their exact declared observations before canonicalization. Reopening preserves the instance ID and continues revision tracking. Object fact identities are derived from stable object IDs and survive drawing order changes.
