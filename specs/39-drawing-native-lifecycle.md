# Drawing native lifecycle adapter

The declared Drawing host operates on the actual `art.draw` board store. Creation uses `board.makeObject`, the renderer's complete enumerable native kind family and the board's native ID allocator. This preserves object geometry, parts, fill, layer and renderer defaults; it does not substitute an ellipse for an arbitrary semantic kind. Canonical knowledge-kind identity to native kind remains a separate declaration/resolution responsibility. Composite knowledge drawings require explicit registration and are not silently admitted by this fixed native family.

Creation and change expose explicit native x/y/size, optional name metadata and an exact RGB override or null. Names are observable object metadata, not a promise to draw a text label. Numeric coordinates are canvas pixels; defaults are the actual board constructor's centre, kind size and absent colour override. Colour names are not parsed here. Native absence/null is not a claim about the effective rendered default. No habitat inference, automatic extra landscape object, language reader or model proposal is called.

Creation, changes and removals use the shared staged transaction boundary and actual board history. Removal requires every requested object to exist. A no-op property update does not add history. Undo/redo use the board's existing snapshots. The complete observation scope is the live `objects` collection, not hidden stashes, scene groups or the canvas background. Each record retains the shared host's source incarnation and version; removed then restored objects receive a new incarnation. Replay receipts stay historical and unverified, stale snapshots refuse, and malformed native requests cannot partially mutate the board. Effects are never reported as assessed semantic success.

This landing adds native capability only. Functional setup mapping and request-class resolution are separate integrations; the app still has no graph-producing SOP-BERT checkpoint.
