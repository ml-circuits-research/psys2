# Frozen structural prediction and development replay

The offline Python predictor loads an explicitly hashed structural checkpoint/config/run/trainer and the saved fast tokenizer. Model inputs contain only source text paired with actual area/context JSON, using the training format. Input records are closed to id/text/area/context: annotations, expected requests, gold counts and fixed field queries are rejected. All 59 model outputs are decoded from actual logits. Typed ABSENT omits a field, UNKNOWN retains an unresolved diagnostic, literal bank values remain unchanged. Count overflow and presence/count disagreement never clip or choose an alternative interpretation.

Span-state predictions and learned token endpoints use exact fast-tokenizer offsets from source sequence zero. Context/special/padding tokens, reversed/out-of-range endpoints and child spans outside the predicted request refuse. Source ranges are Unicode scalar coordinates, not UTF-16 indexes. Missing request spans cannot provide anchors for children. Logit ties remain unresolved. Selected logits are auxiliary evidence, not probabilities or whole-graph confidence. A shared generated tensor fixture checks Python/JavaScript normalization parity without representing a trained-model result.

Checkpoint/config/run/trainer/tokenizer/encoder-config/input/predictor files are hashed before and after inference; changed files prevent a complete manifest. The encoder path must match the frozen run. The original training manifest did not separately hash its upstream encoder configuration, so retrospective capture at that pinned local revision is recorded as a provenance limitation, not proof of historical bytes. Runtime uses the frozen checkpoint's strict state dictionary and saved tokenizer.

Development replay reads only the 1,648 functional development rows and 205 previously reviewed English owner rows. Preparation strips them to source/context-only model inputs. After predictions are frozen, the replay verifies input/output manifest hashes, applies the frozen source-backed binding table and typed decoder, and passes actual proposals through the sole-reader application boundary. No calibrated gate is installed and no effect may execute. Context setup calls are separately accounted for; owner native history is not reconstructed. Reports distinguish raw completeness, typed valid proposals, actual nonempty graph proposals and no-effect replies. None of these is semantic accuracy or an instruction to admit execution; no independent final holdout is read.

No-request proposal auditing joins the original annotated request-array length only after inference. Empty arrays, nonempty arrays and missing annotations are distinct. A valid empty batch that omits annotated requests is a semantic proposal error; pending owner annotations remain unscored. Closed-gate app no-effect counts are never substituted for this audit.

Model format `psys2.raw-structural-model/2` adds exactly the declared `valuePolicy`: mode head `c:valueMode`, copy pointer `c:copy_span`, auxiliary heads `['c:value']`. Its four typed mode entries are absent, unknown, source-span and declared-symbol. The original 59 outputs plus mode and three copy-pointer outputs total 63. The old value bank is auxiliary only, including tied maxima; it cannot supply execution values. Source-span mode copies exact source tokens inside the independently predicted wider value span and request, emitting only RAW `value` and its scalar range. Unknown modes, missing parents/copies and unsupported declared-symbol projection remain unresolved. Internal mode/copy names never leak into RAW fields. The existing v1 normalization behavior and fixture stay unchanged; v2 has a separate generated parity fixture. No new checkpoint is activated by this support.
