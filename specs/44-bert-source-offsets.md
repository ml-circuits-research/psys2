# Verified BERT source offsets

`createBertSourceOffsetAuthority({tokenizer, tokenizerJSON, tokenizerSha256, maxScalars, budget})` is an asynchronous browser-safe factory. Its returned callback accepts the structural provider's `{text, contextJson, tokenIds, attentionMask, fullTokenIds, fullAttentionMask, maxLength}` and returns Unicode-scalar source offsets, sequence identities, special-token mask and exact tokenizer/profile hashes. Context, special and padding offsets are null. Unsupported input throws a diagnostic; it never guesses a source pointer. It does not propose requests or authorize execution.

The initial supported runtime profile is the actual Transformers.js 3.8.1 BertNormalizer, BertPreTokenizer, WordPieceTokenizer and TemplateProcessing components. Exact tokenizer JSON bytes must match the supplied hash; component classes/configuration and added tokens must match that profile. The caller owns authenticated runtime loading; class/config checks cannot authenticate malicious replaced JavaScript functions. Factory validation compares the full vocabulary once and currently repeats component-profile validation per call, independently bounded by the four-megabyte JSON limit. Per-input work uses a conservative reservation budget, including WordPiece quadratic lookup allowance, plus a source scalar cap; third-party component calls are not interruptible instructions.

Each original scalar is normalized by the actual component, preserving the original interval for every output scalar. Concatenated results must equal whole-text normalization. Actual pretokens are consumed monotonically, permitting only whitespace gaps. Actual model wordpieces must reconstruct their pretoken: the continuation prefix is removed only after the first piece. A single actual unknown token covers its original pretoken. No guessed English tokenization, sentence patterns or semantic string matching occur. The declared processor template composes source/context/special tokens. An independent actual whole-tokenizer invocation, the provider's full input, and its padded model input must all match reconstructed IDs and masks exactly.

An omitted/undefined `contextJson` selects the declared single template `[CLS] A [SEP]`; a string selects the existing pair template `[CLS] A [SEP] B [SEP]`. Null and other types refuse. An empty string is still a real pair and is never used to simulate single input. Special IDs are read from the authenticated tokenizer's processor declarations, not invented. Both profiles use right padding. Saved right/longest-first settings are recognized, but an actual truncated pair is refused: no partial-pair source authority is claimed. Input containing an added special-token string is refused before interception. Context-sensitive normalization (for example Greek final sigma), unpaired surrogates, supplementary CJK, overlapping mappings, mismatched IDs/masks and unsupported profile changes refuse. Supplementary CJK is excluded because this JavaScript BERT implementation differs from Rust's character handling. Combining marks that normalize away do not invent source coverage beyond the exact contributing scalar intervals.

Certification is deliberately bounded: the actual JS tokenizer and Python fast tokenizer agree on all IDs, masks, sequence identities and scalar source ranges for 26 adversarial cases (13 source strings, including empty source, each in source-only and actual-context-pair mode), including composed/decomposed accents, emoji, repeated words, punctuation, unknown long tokens, BMP CJK, controls and WordPiece splits. This is not full-corpus certification. The optional real-artifact test requires explicit local tokenizer/runtime paths and a Python reference runtime only during offline validation; Python is never a browser dependency. Every actual browser input still passes independent token parity and all refusal guards. No model confidence or deployment readiness follows from valid offsets.
