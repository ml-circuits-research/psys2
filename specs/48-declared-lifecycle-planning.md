# Declared lifecycle candidate preparation

`planDeclaredCandidates(batch, {registry, capabilities, evaluateSelector, ...limits})` validates the entire standard-request batch before observing native hosts. It prepares lifecycle make/remove operations across any injected host exposing `bindings()` and `observe()`. It never invokes a host, executes a policy, installs a reader or changes the application admission gate. A failure returns zero admitted plans, retaining unresolved diagnostics.

Capabilities are source-backed data: canonical kind, native kind/type, host/scope, lifecycle act/mode, native operation and parameter projections. Source identity/version/snapshot hashes are retained. The deployment loader owns authentication and semantic correctness of those declarations; nonempty provenance alone is not proof that an arbitrary mapping is true. No names, area identifiers, sentence forms or fixture-default tables are built into the planner. Native bindings supply real argument schemas and declared defaults.

Argument descriptors select declared kind, explicit target name, resolved subject IDs, or positive equality result constraints. Result mappings retain exact SOP tokens and source-backed native values; no implicit number/time/reference coercion occurs. Document parent references can require exact live context/subject identity witnesses; stale/missing witnesses refuse. Calendar start/duration/participants/room and native identity must be explicitly mapped where required by the real operation. No synthetic participants, times, content or parent creation occurs. Native defaults such as an optional empty block text are reported separately from user-specified semantics.

Removal resolves complete native populations with the published `.200` target resolver. Declared name-slot bindings use shared native token equality. Logical selector groups/not are traversed by the public resolver, not a new Boolean evaluator. Injected pure leaf evaluators receive copied observations and must return complete consumed-field evidence; unknown/missing evaluators prevent selection. New-target selectors refuse explicitly in addition to standard-schema rejection. Multiple targets, quantifier populations, logical result graphs and non-equality result projections remain unsupported in this bounded profile. Every accepted source field is retained in the consumed-field ledger with the declaration/mapping/resolution evidence. Unmapped rootless constraints cannot disappear.

The exported pure `validateNativeArguments` reuses the native host's existing declaration/type/bounds/default checks; `invoke` calls that same helper. It returns normalized arguments and default witnesses without reading or writing state, invoking handlers or evaluating policy. The planner therefore guarantees only declared parameter admission. Native policy, reference/domain invariants and tool availability may still refuse execution. Plans carry expected version, instance/scope and historical subject incarnations; later execution must refresh/revalidate them, especially when earlier batch entries mutate the same host. Native receipts are not semantic confirmation.

Limits are independent: adapter traversal budget, per-library-call `subBudget`, and per-copy byte cap. The reported steps cover adapter traversal only, not a global neural/library/host cost. Injected host methods and selector callbacks are trusted pure interfaces with their own limits. Tests use all four real native host families for make/remove preparation, plus logical selectors, partial observations, explicit/stale parent references and unchanged-state validation failures. No production C1 mapping or model interpretation is invented by these tests.

## Audit: connecting prepared plans to the existing dispatcher

The planner is not yet called by `executeRequestCandidate`; `NEW_ENGINE_AREAS` still registers only the Drawing property host. `dispatchDeclaredBatch` expects a resolver returning a live host plus operation/args/consumption; planner output deliberately contains an inert hostId instead. Integration must retain one actual session host registry with stable instance epochs, correlate its observations with UI state/undo/restore, preflight every entry's semantic capability before any effect, and then revalidate expected version and identities immediately before each invocation. Blindly replaying prepared snapshots after an earlier mutation is invalid. No registry or capability table is generated from evaluation fixture mappings.

| Area | Existing native lifecycle operations | Missing production declaration or resolution |
|---|---|---|
| Drawing | Object make/remove with native kind enum and complete incarnation observations | Source-backed canonical kind→renderer-kind mappings, owning instance-name/property slots and typed values. C1 `nativeFamilyBinding` currently asserts family eligibility only, not kind/value conversion. |
| Diagram, including charts | Node/link make/remove; chart datasets/series in a separate native host | Node/shape and chart subtype mappings; explicit relation endpoints and dataset structure. Node creation lacks a name parameter, so a requested label requires a declared make→setter dependency with the created identity, not silently dropping the name. |
| Document | Whole-document write/remove and block/section make/remove | Canonical document/genre/block kind ownership, explicit parent instance identity and block/content schema. Whole-document write replaces the current document; it cannot be reused as child creation. Multiple document containers are not an existing native capability. |
| Calendar | Person/room/event add/remove with resource references and native policy | Calendar entity/property identities, explicit identity allocation, participant/room resolution, and source-backed date/time→native millisecond frame conversion with actual date/timezone context. No missing attendee, room, date or duration may be filled from evaluation defaults. |

The frozen C1 snapshot links16 raw descriptors to canonical properties and native parameter slots; their `valueBoundary` explicitly defers native values, units, date/time composition, regions and defaults. The frozen lookup predates later native-source revisions and must not be silently treated as authenticated current code. A new versioned C1 execution declaration snapshot must verify semantic source and native module/dependency hashes, preserve ambiguities, and separately expose reference/value-resolution witnesses. Matching display names is not an undeclared semantic join.

Current admission consumes one do/make-or-remove target, declared names/determiners, supported selector groups and positive-equality make results. Missing mechanisms remain explicit for several target roles, quantifier/binder scopes, logical desired-result graphs, relation goals, numeric relative operators/baselines/units, contextual references, questions and corrections. Each extension needs whole-field consumption through shared published graph mechanisms; never mark all fields consumed merely because the graph schema validates.

The existing dispatcher treats native changed/unchanged receipts as unverified. Dependent entries remain blocked until a correlated typed assessment proves the required prior effect; receipt status cannot unlock them. Existing lifecycle observations can support published existence assessments, but request/step/invocation/source/population correlation and retained reply evidence must be wired explicitly. No final holdout, model gate or unsupported semantic field is bypassed by this planning audit.
