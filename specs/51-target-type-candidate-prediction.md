# Learned target-type candidate prediction preparation

The isolated `training/sop-bert/candidates/target-type/predict-key-reader.py` targets exactly `sop.key-reader/2-target-type-candidate`, with the corresponding `/2` raw codec and final-run record. It preserves the baseline source-only request text plus trusted actual area/context input, exact preparation-manifest/config/trainer/encoder/checkpoint chain, predicted BIO mention metadata, typed banks, scalar source ranges and immutable pre/post hash verification. Baseline root prediction/training tools are unchanged.

Unlike the134-key baseline, this architecture has an explicit learned `request.target.type` class. Its value comes only from the actual predicted class-bank entry; the declared `targetFamilies` and class-only `familiesByArea` metadata must agree and the value must belong to the current area. Absent, unknown, tied, malformed, missing or cross-area type predictions remain unresolved and do not provide a type. Invalid profile metadata refuses rather than pretending the head exists. No type is inferred from kind text, a property prefix, a native operation or source catalog order. The class is structural metadata: no invented literal source span/BIO evidence is emitted for it.

A valid learned type removes only the former unconditional missing-type diagnostic. All other source/value proof, missing metadata, truncated input, unsupported normalization, canonical binding and context limitations remain. Static support diagnostics remain alongside the raw output; future runtime adapters must preserve and validate them while respecting the closed runtime provider envelope. Neither a complete packet nor a validated type is calibrated whole-graph confidence or application effect authorization.

The CLI requires positive final training steps and exact matching candidate flags/config raw-codec format in addition to the frozen hash chain. It reads no active model unless a caller supplies a completed frozen artifact matching that contract. No actual candidate model exists or is consumed by these fixtures. Five pure tests cover every declared area's type values, independent type/kind representation, absent/unknown/tied classes, cross-area refusal, no fake type anchor and explicit rejection of baseline/future neural model formats.

The separately prepared next training orchestration may use a `/3` supervision and final-run provenance contract while keeping the neural model/raw codec at `/2`. This predictor does **not** silently accept that new run record: it requires a deliberate additive validator after the exact warmstart/hash contract is reviewed. Its `/3` neural-config rejection remains intentional. No GPU/model read, checkpoint export, application installation or inference accuracy claim is part of this preparation.
