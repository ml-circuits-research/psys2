# Learned target-type candidate prediction preparation

The isolated `training/sop-bert/candidates/target-type/predict-key-reader.py` targets exactly `sop.key-reader/2-target-type-candidate`, with the corresponding `/2` raw codec. It accepts the original `/2` final-run profile or the explicitly validated `/3` training-source profile. It preserves the baseline source-only request text plus trusted actual area/context input, exact preparation-manifest/config/trainer/encoder/checkpoint chain, predicted BIO mention metadata, typed banks, scalar source ranges and immutable pre/post hash verification. Baseline root prediction/training tools are unchanged.

Unlike the134-key baseline, this architecture has an explicit learned `request.target.type` class. Its value comes only from the actual predicted class-bank entry; the declared `targetFamilies` and class-only `familiesByArea` metadata must agree and the value must belong to the current area. Absent, unknown, tied, malformed, missing or cross-area type predictions remain unresolved and do not provide a type. Invalid profile metadata refuses rather than pretending the head exists. No type is inferred from kind text, a property prefix, a native operation or source catalog order. The class is structural metadata: no invented literal source span/BIO evidence is emitted for it.

A valid learned type removes only the former unconditional missing-type diagnostic. All other source/value proof, missing metadata, truncated input, unsupported normalization, canonical binding and context limitations remain. Static support diagnostics remain alongside the raw output; future runtime adapters must preserve and validate them while respecting the closed runtime provider envelope. Neither a complete packet nor a validated type is calibrated whole-graph confidence or application effect authorization.

The CLI requires positive final training steps and exact matching candidate flags/config raw-codec format in addition to the frozen hash chain. It reads no active model unless a caller supplies a completed frozen artifact matching that contract. No actual candidate model exists or is consumed by these fixtures. Five pure tests cover every declared area's type values, independent type/kind representation, absent/unknown/tied classes, cross-area refusal, no fake type anchor and explicit rejection of baseline/future neural model formats.

The published `/3` supervision/final-run validator is `candidates/target-type/run-provenance.py`. It requires complete final training, exact tensor/model/raw-codec profiles, source/config/checkpoint/preparer and encoded-data hash chains, declared selection criterion/rank, exact compacted-checkpoint evaluation profile, and config/run warmstart agreement. Semantic migration requires all seven frozen parent hashes, helper identity, positive explicit work allowance, matching estimated/actual element work and fresh AdamW; pretrained initialization requires the explicit null/empty alternative. It never relabels a `/3` neural model as `/2`.

The predictor hashes this validator alongside itself before/after inference and includes that identity in its codec proof. It reconstructs the layout from the exact pinned trainer/manifest as before. This is metadata admission, not a new backend parity or whole-graph confidence claim. Pure malformed-profile tests cover incomplete runs, changed hashes, precision/selection tampering, data encoding changes and restored optimizers. No candidate model is read by these tests.

Backend boundary: candidate selection evaluates compacted weights reloaded as FP32 with autocast disabled. The optional CUDA predictor still labels its own BF16-autocast forward path as `cuda-bfloat16`; CPU inference is labeled FP32. Neither path inherits selection scores as measured backend parity. Graph confidence remains absent until the actual frozen inference path is evaluated.
