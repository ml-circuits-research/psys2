# Runtime key-reader packet boundary

`createKeyReaderPacketAdapter({configJSON,configSha256,model,...limits})` binds exact UTF-8 config bytes to an explicit model/checkpoint-tokenizer-codec tuple. It accepts the candidate's exact `/2` model/raw-codec profile and derives every support entry from the declared registry/banks. The `/2` frozen architecture profile requires135 keys,122 BIO streams,63 banks and15 unique type values across four declared area families. These profile counts prevent a coherently trimmed config from masquerading as the same architecture; individual semantic key/area/value names still come from the pinned config, not host word lists. Configuration/model identity is supplied by the trusted frozen-artifact loader: matching hashes here is not independent verification of weights or calibration.

`adapt(rawPacket)` returns `{ok,packet,diagnostics,provenance,steps}`. The raw predictor's `coverage.support` must contain exactly one matching `{key,presence,value}` entry per config key in config order. Missing, extra, duplicate, reordered or altered entries refuse. Derived/untrained, learned presence, unsupported metadata value decoders, declared classes and copy routes retain their distinct labels. Optional unsupported capability is not silently promoted to support or forced into a fabricated positive prediction.

On successful adaptation, `packet` is the runtime pipeline's existing closed envelope: source, request, ranges, coverage containing **only** complete/truncated, unresolved, and model. `diagnostics.support` and `diagnostics.rawPacket` retain all static support and the complete original predictor packet. Callers must retain this diagnostics/provenance record with the reading; passing the packet onward does not authorize discarding its diagnostic record. Unknown semantic request fields and unresolved issues survive unchanged for the bridge to accept or refuse. No unsupported field is converted into an inferred result.

All source evidence is Unicode-scalar indexed and must own a string leaf in the request that exactly matches the source slice. Duplicate, malformed, out-of-bounds or unowned paths refuse. Source/model mismatches and complete coverage combined with truncation or unresolved issues also refuse. Successful packet storage is independent from the retained raw diagnostic copy; neither input nor shared host state is mutated. A failure yields no partial runtime packet.

Byte-copy limits and adapter work limits are independent bounds, not total neural/decoder work. The browser-compatible module uses the existing host-data copier and Web Crypto only; it loads no model and imports no Node or third-party runtime package. Provenance always states calibration:null and executable:false. No app provider is installed and no gate is widened. Future model routing must preserve actual frozen artifact provenance and establish whole-reading calibration independently.

Tests generate a packet using the published candidate configuration and actual pure Python normalizer, covering all135 support entries without loading weights. They exercise support corruption, exact model/config identities, unknown fields, scalar emoji ranges, source ownership, isolation and budget refusal. These tests prove the transport boundary, not understanding or inference quality.

The configuration hash and model tuple are independently pinned by the caller. This factory does not reconstruct the checkpoint exporter's codec preimage or prove a model/config association from weights; that association must be verified by the frozen artifact loader and retained in deployment provenance. Profile cardinality checks are additional fail-closed compatibility checks, not that missing cryptographic proof.
