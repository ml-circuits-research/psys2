# Actual two-model rollout and measured execution admission

The current application has no installed trained request reader. `reader-routing.mjs` reads `session.engine.requestReader.propose(text)` and refuses otherwise. The two-model pipeline validates source ranges, RAW bindings and typed graphs but always marks execution unavailable. The new packet adapter fixes transport of static support diagnostics; it does not run neural inference. Native adapters and read-only planning also do not establish understanding. These are the concrete current boundaries, not a completed rollout.

## Smallest real path

1. Freeze a 135-key candidate checkpoint with its own completed-epoch or final-run proof and exact checkpoint-compacted evaluation identity. The completed 134-key checkpoint cannot supply the missing target.type head and must not be patched by guessing a family. Any early epoch artifact needs an explicit immutable proof; a changing checkpoint.pt path is insufficient.
2. Export the real source-only BIO cutter and the actual candidate key encoder/heads. The current `export-key-reader.py` is a source-only `/1` prototype without a checkpoint loader or complete deployment manifest. A real exporter must verify frozen weight/config/trainer/preparer/codec/tokenizer identities, record resource/precision preflight, emit exact file hashes, and measure Python-versus-ORT decoded packets before any browser deployment. No prototype status is treated as a completed export.
3. Install actual browser inference: source-only tokenizer/cutter; exact predicted source cuts; request-local tokenizer with current host context; encoder BIO/presence outputs; predicted mention pooling through the heads graph; typed bank decoding and declared raw field routes from the frozen preparer; verified scalar offsets; packet adaptation; canonical bridge and typed graph validation. There is no grammar provider, teacher span/count/field query or nearest-kind repair.
4. Initially run the real pipeline without effects and record all failures, proposals, ambiguity, margins, source ranges and model identities. The 134-key baseline may be measured in this mode, but its missing-type packets remain unresolved. A 135-key checkpoint may improve this only through actual class predictions. Existing pipeline executable:false is not lifted by a model self-assertion.
5. Admit effects only using empirical whole-reading/effect evidence bound to the exact deployed pipeline identity and a declared risk policy. The pipeline identity must include both model files, tokenizer, decoder/routes, bindings, adapter/orchestrator, native execution scope and app build. Mention F1, token softmax or a product of head probabilities is not whole-graph confidence. A raw decision-margin feature can be used as a selection feature only after calibration of the actual complete pipeline; it is not named a probability without that evidence.

## Gate and evaluation work still required

The current router accepts a host callback plus `approved/wrong/better/compared` fields. This is a trusted placeholder boundary, not a measured calibration loader. A production admission artifact must bind an actual report, frozen inference identities, reviewed capability scope, score/selection definition, calibration split, threshold-selection procedure and separate untouched risk evaluation. Support and zero observed wrong must be reported with their denominators and uncertainty; no minimum sample/risk allowance is silently invented. Thresholds cannot be selected on the final risk rows. Unsupported and ambiguous readings remain refusals; missing evidence cannot become an approved callback.

The current matrix/owner scripts install no reader and score unchanged unsupported responses as honest. Any effect is needs-review because no independent full-intent evaluator is installed. To measure real rollout they must inject the actual provider/gate, retain exact deployment/source/host-context snapshots, count the share admitted above gate, and score against separately supplied reviewed intent/effect checks. Expected annotations stay exclusively in the scorer and never enter provider inference. Right requires both the complete intended request and observed intended effect; native receipt status, a schema-valid graph or a partial condition is insufficient. Missing source context and defaulted setup retain existing exclusions/limitations. Owner sessions additionally need their historical external-state gaps reported, not recreated from desired answers.

## Parallel ownership and resource boundary

The worker's runtime lane owns browser inference/provider wiring and replay integration. Training-source changes and full source rebuilding remain separate owners. Export and actual inference require explicit measured storage/precision preflight; no new trained-file read/export/GPU work is implied by this specification. Source implementations and tiny synthetic-module tests can proceed now. A real deployment milestone is reported only after actual frozen outputs, the empirical gate, observed effects, and class-by-area/owner evidence exist together.

## Browser key computation contract

`createKeyReaderInference` now executes an injected tokenizer, encoder session and mention-head session. It is not an artifact downloader. Its `sop.key-reader-runtime/1` manifest binds the exact `/2` 135-key config JSON, checkpoint, encoder ONNX, heads ONNX, tokenizer, preparer, trainer and decoder hashes. `rawRoutes.globals` and `rawRoutes.metadata` must be exported from the exact hashed preparer; they are not inferred from key spelling. The loader remains responsible for verifying file bytes and associating those identities with the supplied runtime objects. The manifest requires `dtype:fp32` for output tensors and separately records `weightRepresentation:fp32|q8-dynamic` for stored weights; the representation participates in model identity. It admits only `executionEligible:false` and `graphConfidence:null`.

Encoder outputs are hidden `[1,L,H]`, BIO `[1,122,L,3]` and presence `[1,135]`. The runtime obtains actual source-token intervals from the verified BERT component-tracing authority. Each strict predicted domain BIO span becomes a head query; global fields use the declared CLS query. The heads graph receives actual hidden states, token start/end pairs and registry-key indices, and returns concatenated class-bank logits in config key order. Repeated same-key spans receive separate metadata decisions. Typed absence and unknown are distinct. Raw source-copy values, numeric-normalization limitations, cross-area mismatches and unsupported routes follow the Python candidate normalizer. The test suite compares complete RAW packets against that Python normalizer using synthetic logits; it does not claim trained checkpoint parity.

`infer(text,{area,context})` returns the full raw packet, adapted closed packet, inventory-wide support diagnostics, exact provenance and selected auxiliary logits. `read` first calls the mandatory diagnostic recorder and only then returns the pipeline packet. No selected logit is labelled a calibrated probability. The diagnostic recorder and actual context getter are trusted host boundaries, never annotation inputs. No application provider is installed by construction.

Context JSON reproduces Python's sorted keys and default separators for Unicode scalar strings, booleans, null, safe integers, arrays and objects. Noninteger numbers, negative zero and unpaired surrogates refuse because untyped JavaScript numbers cannot recover the original Python numeric spelling. Source/context truncation refuses before model execution. Invalid tensor shapes, nonfinite outputs, offset mismatch, excessive queries or local work exhaustion yield incomplete packets. The local work allowance covers tensor scanning and decoding, with separate copy, text, query and class-output caps; it is not a bound on neural execution, tokenizer internals, diagnostic storage or downstream bridge work.

Real artifact export/load and decoded backend parity remain required. A synthetic fixture can exercise the neural call interface without establishing any real model accuracy. The empirical admission gate and complete intent/effect scorer remain separate required integrations.
