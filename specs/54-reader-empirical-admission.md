# Reader selection and reversible action

Owner decision Review29 supersedes the earlier zero-error, refusal-first policy. A usable reading is acted on and the reply reports the actual effect and any assumption. The application does not ask clarification questions. If no usable action exists, it reports what could not be applied without inventing an effect.

## One declared policy

`worlds/app.project/reader-admission-policy.sop` owns action classification and accepted-row empirical error limits: 0.05 for ordinary commands and 0.01 for destructive acts (remove/delete/overwrite/clear). Retained calibration still uses source-disjoint CAL fit/evaluation rows, exact runtime/area identities, validation, resolution and native execution checks. Refusals are not coverage. Error among acted rows requires an independent intended-effect judgment; neither graph validity nor a native receipt supplies it.

The owner also authorizes reversible best effort while no calibrated cohort is configured. That mode is explicitly `uncalibrated-best-effort`, carries no measured error-rate claim, requires a valid source-anchored complete graph and actual neural score, and excludes destructive acts. The SOP rules derive a closed decision for a supplied but rejected calibration. This bootstrap mode is reported separately from calibrated admission. It exists to let the owner try the demo and correct it rather than wait for a complete annotation program.

The reader validates the proposed graph and independently verifies any retained report. It supplies these observations as `app.reader.evidence` to the SOP rules in a library World fork. The derived `app.reader.decision` controls dispatch and is retained in the trace. C1 takes its ordinary error-rate ceiling from the same authored policy. Worlds shows the governing SOP file and its link to the evidence adapter.

The live reader context uses authored observation roles, hierarchy paths and focus evidence in `worlds/app.project/reader-context-policy.sop`. SOP rules retain roots, exact mentions and focused items. The library ranks the finite evidence classes once, then the reader projects observed records in the declared tie order. Offline replay uses the same display bindings and keeps the full source-order inventory.

## Score and alternatives

`psys2.model-minimum/1` uses the minimum selected softmax probability from actual cutter token decisions and request-class decisions, and the selected sigmoid probability of learned key-presence decisions. Untrained derived presence keys do not enter it. Every component is read from real inference outputs. No canonical-binding probability is fabricated: the declared binding/graph validation remains a structural eligibility condition. The scalar ranks interpretations and supports future threshold fitting; it is not a calibrated individual probability of success. Missing scores do not receive a synthetic confidence of one.

Complete alternative readings are retained in the trace. The current decoder ordinarily emits one argmax reading; when the model supplies ordered alternatives the first complete reading is used and the uncertainty is disclosed. This does not choose a reading from test annotations. Incomplete graphs, missing source evidence, model failures and unsupported semantics remain visible. No grammar fallback is added.

## Execution, defaults, correction and undo

`declared-execution.mjs` joins canonical target identities to declared native capability families and enum kinds. It uses actual host argument validation and transaction receipts across Drawing, Diagram, Document and Calendar. Existing property observations remain available through the earlier executor. Native argument mappings come from published bindings and the explicit Drawing property declaration. Colour values use the existing knowledge colour/RGB mapping. Numeric strings are converted only for declared numeric native parameters; qualitative size is not invented as a number.

Native interfaces declare catalog label seeds and chart ordinal labels as `std.capability.seed` facts. The app execution policy uses the same type for document and calendar defaults and supplies notices only when the compiler applies a missing argument. Catalog rows and raw observed fields enter the compiler with their original values. SOP rules normalize RGB values and retain the source evidence used for property selection.

A new object can be created even when a separate property cannot be applied; the reply names both the observed creation and the unapplied property. A changed action needs at least one applicable property. Known creation defaults are explicit application assumptions: an empty document, or a meeting starting now with a 30-minute duration and no participants/room. Temporal assumptions are reported. A populated document is not silently overwritten. Missing composition/rewriting providers stay unsupported.

For non-destructive actions, multiple matching objects prefer the current focus or the most recent matching object and name that assumption. Each applied turn records before/after data for the worlds it changed. A model-read `undo` restores those worlds only, preserving subsequent unrelated-area changes; a stale undo does not overwrite a later manual edit. Existing UI undo remains available. The per-session history World stores entry identity, position, view, direction, and native snapshot references in SOP. Its rules derive each live head and its guarded move action updates the selected entry. A portable snapshot carries these facts and the linked editor payloads. Reload preserves journal and entry identities, while a fresh dispatch lease prevents a command compiled for an earlier session or snapshot from mutating the restored state. The trace preserves alternatives for subsequent correction. Model-declared literal context corrections bind through observed native objects and published kind/property identities. A target correction can restore the previous mistaken property effect and apply the inherited intent to the other live object. Source values retain exact model ranges; inherited intent is retained separately. This does not claim that every fragment is understood.

## Measurement

`scripts/calibrate-reader.mjs READER_SPEC CAL_CORPUS OUTPUT_PREFIX [COMPARISON_LIBRARY]` measures full CAL messages using the installed model/bindings and actual native setup. Teacher annotations enter only after inference returns. Setup exclusions stay in the denominator. Strict graph comparisons are diagnostic; unknown eligible intent/effect labels remain unknown and cannot be relabelled abstentions to approve a cohort.

Functional and owner replay commands extract stage counts from the same inference calls. Actual actions without reviewed intended-effect labels remain `needs-review`, rather than automatically becoming right or wrong. The owner feedback is the next semantic judgment. Historical measurements made before Review29 are explicitly dated in `training/results/epoch7-reader-measurement.md` and do not validate this policy.

Constructor eligibility uses `worlds/app.project/constructor-policy.sop` to join canonical bindings with observed native interfaces. It retains the direct constructor and any compatible knowledge-backed constructors for the same source type. Family-level bindings retain their own constructor. Precondition and kind-enum restrictions are applied before candidate ranking.

Creation completion also consumes model-declared constructor-kind roles (such as a shape value) and exact owning identities. Conflicting target-class heads can yield to an anchored lexical identity within the active area; near lexical guesses use the published library edit cost over declared native-compatible identities and disclose the guess. No source phrase is matched. Unsupported condition metadata remains unapplied, not reinterpreted as an absolute value. Calendar creation does not silently discard unresolved scheduling details.

The parameter-free journal-act profile consumes a learned act/mood and source evidence, retaining discarded object-head diagnostics as uncertainty. Undo, focus and prior applied intent are included in session memory and snapshots so lazy world loading does not lose them.

The interface translates non-English input to English through the existing browser translation backend before calling SOP-BERT, and translates its effect reply back afterwards. A confidently browser-detected input language may differ from the selected reply language. No grammar reader or rules translator is restored. Missing input translation yields an explicit translation-unavailable reply with no effect. Failed output translation keeps the actual English effect reply without executing again. The original input remains source metadata; model offsets address the translated English.

Ordinary creation can supply omitted coordinates from the live scene. The compiler joins observed frame and object bounds with catalog layout slots and support anchors. It tries declared points in those regions, checking the rendered extent and ranking sampled positions by overlap with other observed objects. An explicit coordinate keeps its value. A water placement uses an observed support, and a missing region leaves ordinary creation available with its tool defaults. If each sampled point overlaps another object, the compiler prefers the least overlapping point.
