# Loading a completed candidate epoch without claiming a completed run

The candidate's `artifact-provenance.py` validates two explicit roles: a completed version4 plateau run, or the immutable first-epoch proof `sop.key-reader-completed-epoch/1`. Both retain model/raw codec version2 and supervision version3. The loader does not relabel an epoch as a final run, inherit calibration, or infer permission to execute a graph.

Metadata validation requires the known135-key/122-BIO/63-bank/15-family profile; exact config/trainer/preparer/data-manifest identities; schema-sourced type bank; warmstart work and fresh-optimizer contract; full encoded/decoded gzip identities and sample counts; selection, checkpoint compaction, plateau and writer contracts. Epoch validation recomputes the canonical metric hash and selection rank, checks the first plateau state against those same metrics, and requires the permanent content-addressed pin, byte count and reserve policy. Final-run validation requires actual stopping state and the actual selected checkpoint epoch. Neither validation proves correctness labels or empirical model quality.

`load-artifact.py` exports `load_verified_artifact(paths,hashes,max_checkpoint_bytes=...)`. The caller supplies exact paths and expected SHA256 values for checkpoint, config, trainer, preparer, data manifest and artifact proof; an encoder directory is independently authenticated by every config.encoderFiles hash. No training-row annotations are read. Source and proof roles are validated before Torch reads weights. Only a content-addressed first-epoch pin below the proof directory is eligible for the epoch role; a mutable checkpoint path, symlinked pin or pin-parent path escape refuses.

The frozen trainer's configuration function must reconstruct the recorded static model layout. A trusted, hash-verified trainer module constructs the CPU FP32 model, then weights_only loading requires the exact checkpoint config, selected epoch, state keys/shapes and BF16 floating storage. Nonfinite, complex or mismatched tensor dtypes refuse. Exact saved values are loaded into FP32 with strict state matching; the model returns in evaluation mode without trainable gradients. Files, encoder identities and loader/validator dependencies are rehashed after construction/loading, and mutation prevents returning the model. The caller must treat hash-pinned Python source as trusted authored code; a hash is not a sandbox for arbitrary third-party code.

The returned provenance records CPU FP32 loading from BF16 storage and null graph confidence. It does not run a forward pass, export files, use a GPU, calibrate or activate a provider. Backend parity and graph admission remain separate. Existing historical predictor CLI roles remain strict; callers consuming this new proof use this loader explicitly rather than fabricating a version3 completed-run record.

Eight fixture groups cover actual producer metadata, valid final plateau state, role/metric/rank/path/storage/source refusal, exact tiny CPU loading, size/hash/encoder/type refusal, source mutation during load and symlink-parent escape. Tiny model fixtures contain no trained data. The separately authorized actual first-epoch CPU load is recorded in reports/review23-epoch1-cpu-load.json: all67,296,311 parameters loaded on CPU as FP32 from the exact immutable pin, with no forward inference or inherited quality/calibration claim.
