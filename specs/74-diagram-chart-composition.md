# Diagram contains charts — 2026-11-17

The Diagram tab owns one live `diagram.sketch` instance. Its native host explicitly composes the vector-node/link primitives with the numeric chart primitives from `data.charts`. The latter remains an implementation module, not an application tab or a second active-area instance. Chart state is stored at `diagram.sketch.chartTools`; old standalone chart data is migrated once, with namespaced chart ids and unchanged values/source references.

The host publishes both sets of native operations and observations under one instance/version boundary. A chart is a selectable SVG group with canvas coordinates, title, up to twelve named series, category labels and finite numeric values. Bar, line, pie, doughnut, polar-area, radar and categorical scatter render as vector marks in the same SVG as diagram nodes and links. SVG/PNG export includes both. The UI exposes explicit chart creation/data editing, type/title changes, selection, drag, deletion, editable series names/data/colours, horizontal bars, value/legend visibility, stacking, shared palettes and ordering. Data entry is a label/number pair per line, not a natural-language parser.

Chart identity, data and display state remain separate: editing a point changes its numeric value, while moving a chart changes only placement. Negative values are accepted for Cartesian/radar charts and refused for radial part-of-whole charts. No numeric values are fabricated. If no category labels were supplied, numeric ordinal labels may be used, with that assumption disclosed. An empty chart is a visible empty chart, not an automatically populated example. At most 20 charts and 200 categories per chart are created through the native tools. The composite host's bounded undo/redo covers mixed chart/node edits.

`CHART_KIND_PARAMETERS` and `CHART_PROPERTY_ALIGNMENTS` are the owning C1 declarations for semantic-to-native chart binding. The exporter joins supported published `k.charts.kind`/`w.chart` identities to chart primitives, retaining the same evidence/provenance rules. The existing request projection and execution path consumes those mappings; no second sentence reader is added. Declared list codecs convert already extracted values into typed string/number arrays. Unextracted labels, mismatched lists, unsupported forms, unknown relations and missing value bindings remain explicit failures. UI tool availability is not a claim that the installed neural model correctly extracts every chart command.

The former standalone chart plugin is marked `standalone:false`. The application integrator must omit it from tab registration, migrate persisted standalone data, route active Diagram observations through the composite host, and regenerate the reader bindings when publishing the changed declarations. The Calendar tab replaces the former Charts navigation slot.

Validation: native mixed transactions/undo, migration, all SVG forms with escaped labels, and shared declared-request execution with exact numeric values are covered by `tests/diagram-charts-composition.test.mjs`. Actual installed-reader/browser measurements are reported separately by the integration run.

Diagram nodes can be created through the primitive toolbar, selected, dragged and labelled with a double click. Drag previews change SVG transforms only; pointer release emits `diagram.node.place` or `chart.place` through the normal typed operation door. Label edits emit `diagram.node.change`. The shared host can therefore capture each UI gesture as text plus its expected SOP intent for future reader training.
