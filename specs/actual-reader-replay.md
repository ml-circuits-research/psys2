# Actual reader replay host

The optional `--reader-spec FILE --output-prefix PREFIX` on both new-engine replay scripts installs the verified neural provider for measurement only. Without the option, the existing no-provider baseline is unchanged. Separate output is mandatory to preserve that baseline. No selective admission report is installed; every proposal and diagnostic is retained separately from application effects and semantic correctness remains null. Complete graphs are not counted as correct intent. Native fixture exclusions remain exclusions, not model abstentions.

`psys2.actual-reader-replay/1` supplies artifactRoot, manifestSha256, tokenizerArtifact and bindingsArtifact descriptors, tokenizerConfig {path,sha256}, runtimeRoot, runtimeTreeSha256, ortModule, transformersModule, and runtimeIdentity. Artifact paths are relative to artifactRoot and must resolve inside it. Runtime modules must resolve inside the exact recursively hashed dependency tree; symlink targets outside it refuse. The runtime identity is a reviewed host assertion for the complete implementation; hashing installed dependencies alone does not authenticate its other fields. Backend identity includes the dependency tree, Node/platform/architecture, module entry paths and explicit CPU/one-thread options. Its JSON SHA must equal runtimeIdentity.backendSha256. Original tokenizer configuration bytes are separately checked and passed to the actual BertTokenizer. No Python runtime or package installation occurs.

The factory verifies graph/config/tokenizer/bindings bytes before constructing actual sessions. The host invokes only actual ONNX sessions through the tokenizer and provider. A configured report is temporarily removed during measurement and restored afterward: this harness does not authorize effects. There is no fallback reader. Context failure is captured and becomes a provider refusal.

`psys2.native-reader-context/1` supplies only `{area,context:{existing:[{kind,name?}],previous}}`, derived from the actual complete native observation and explicit native display-label bindings. The previous value is the actual preceding sent message, never an annotated gloss or expected request. Native identities, versions and full observed properties remain in a separate diagnostic observation, not in the 192-token neural input. No target.type, name, rendered default or selected referent is inferred. Unknown native kinds remain their actual native representation. Owner replay has only its actual reconstructed Drawing store; other historical area state is unavailable rather than invented empty. Matrix model context is observed after native setup, never copied from expected annotations.

Bounds are independent: context copy1MB/1000objects, runtime inventory2GB/100000files, per-turn diagnostics16MB, and the factory/pipeline's own caps. The source fixtures verify real native context, rejection, and runtime file hashing; they are not trained-model quality evidence. Actual inference requires a frozen verified artifact bundle and records the backend anew. Node ORT1.21.0 and Python ORT1.31.1 results are not interchangeable calibration.

The read-only `probe(text,{area,context})` entry accepts explicitly trusted factual source context for backend parity probes, without constructing an application session or evaluating effects. Its input shape rejects extra top-level annotations. This is separate from replay `run`, whose model context must come from actual host observations. Both return unknown semantic correctness and never install admission. Exact tokenizer configuration may omit tokenizer_class (as the pinned DistilBERT artifact does); this host explicitly constructs BertTokenizer and the factory checks its actual tokenizer profile/component trace. A conflicting declared tokenizer class refuses.

The pinned original HF tokenizer serialisation predates the explicit WordPiece `model.type` discriminator. Offset profile version2 accepts its absence only with exactly the four WordPiece fields and still verifies the actual WordPiece component/configuration and all token IDs. Explicit other types or extra ambiguous legacy fields refuse. The original small tokenizer_config also omits special-role names. `explicit-bert-special-roles/1` supplies the BERT class roles only after checking unique special added-token records, exact vocabulary IDs, unknown token and CLS/SEP processor declarations; conflicts refuse. Original hashes are unchanged, while the derived constructor configuration hash and host source identity are recorded. Actual JS/Python fast-tokenizer certification covers 26 single/pair cases including empty input, Unicode, repeated substrings and UNK, plus unsupported-input guards.

## Predeclared source-version diagnostics

`select-reader-probes.mjs SOURCE haiku-v2 PREFIX` freezes the first two calibration rows per area in source order whose source_path belongs to that version. It inspects no annotation value, model prediction or correctness label to choose rows. Inputs contain only id/text/area/context; the separate selection declaration retains exact source hashes and line identities. Wrong split, missing area support or duplicate selected IDs refuses.

`probe-actual-reader.mjs SPEC INPUT_JSONL OUTPUT` runs at most64 predeclared inputs through the actual verified provider without application effects. Input1MB and output8MB caps apply; all packet fields/ranges/coverage/support/unknowns remain, while auxiliary numerical logits are deliberately omitted. Source/spec hashes are checked before and after. `compare-reader-probes.mjs NODE PYTHON OUTPUT` requires identical input/bundle identities and complete matching row populations. It compares all semantic fields and array order, excluding only per-packet model identity (retained separately); it reports every difference path. Source version groups remain separate. Canonical proposal counts describe only the chosen small diagnostic group, not accuracy, corpus coverage or admission precision.
