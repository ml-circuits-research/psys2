# Sole browser reader installation

The normal browser worker installs the verified q8 cutter and key reader at startup, then uses the existing decoder, retained empirical admission assessment and request engine. No engine query switch or alternate reader exists. `models/sop-bert/deployment.json` points to the immutable manifest-addressed bundle and exact tokenizer/bindings/config descriptors; the build binds the generated worker, reader, pipeline, adapter, decoder, executor, context and WASM/tokenizer implementation bytes. The original model manifest/checkpoint proof stays unchanged. The single vendored ONNX Runtime Web1.31.1 WASM backend uses one thread and no proxy; the small tokenizer bundle retains verified component names.

The provider receives actual current native state through the shared observed-context profile (native labels/kinds and previous sent message). Native object identities/versions remain sidecar observations. State restoration and world loading preserve the engine's provider; replacing a native store creates a new observation host. Missing/invalid native state refuses rather than inventing objects. Startup load failures install a diagnostic-only unavailable provider, never a fallback. Existing worker startup/turn cancellation limits remain active.

The shipped model uses the completed run's selected epoch 7 (last epoch 10), with separate proof for the unchanged cutter. No empirical admission report ships with this bundle. Actual model computation and proposal diagnostics therefore run, while unapproved requests have no effects. Readiness and diagnostic counts appear in trace data; user replies remain clear no-effect statements, without asking the user to repair deployment metadata. Model completeness is not execution authority and cohort precision is not assigned to model confidence.

`--browser-route --output-prefix PREFIX` on the functional matrix and English owner replay uses the normal page/client/worker and the same installed provider. Fixture creation remains before model invocation; setup exclusions remain separate. Worker state before/after supplies the effect check. Reports cannot call a schema-valid or refused proposal semantically correct without an independent intent/effect check. C1 probe commands and historical Node parity evidence are not substitutes for these browser-route results.

No live training checkpoint is copied, no report authorises effects, and Pages is served from the ordinary published app build.

The C1 Chromium transport retains the external observed pre-state and the normal client's `loadedBefore()` record from the just-completed send. The worker captures that record after lazy host loading but before command processing. Only previously absent world keys are filled from this record; an existing baseline value is never replaced. This prevents host initialization from being mislabeled as a model effect while still detecting mutations of either existing worlds or newly loaded worlds after their recorded initial state. The normal application, provider and admission behavior are unchanged by this measurement correction.

The C1 Chromium transport removes only its owned temporary profile. Removal retries transient filesystem busy/nonempty errors with bounded backoff after browser shutdown; a cleanup failure remains a failed run even when earlier model checks passed.
