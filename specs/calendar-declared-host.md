# Calendar declared native host

`worlds/time.calendar/declared-host.mjs` exposes the full local people, rooms and meetings lifecycle store through the shared native transaction boundary. It declares add/change/remove for all three kinds, meeting move, and observation. Arguments are already resolved native values; the adapter never reads English, chooses participants, supplies a room, searches for a slot, or interprets relative dates.

A meeting's start is integer Unix milliseconds; duration is positive integer milliseconds. Their observations carry distinct `unix` and `duration` frames. Explicit null room means no room; omission on creation is invalid. Native validation checks all foreign references and rejects resource removal while referenced. Complete snapshots cover the entire store, never a selected day/week. Source identities are incarnated by the shared host, so deletion and recreation cannot reuse historical evidence identity.

Mutation is staged and atomic. Optional caller-supplied `validate(candidateState)` is the declared-world policy boundary; it must return the generic host's bounded validation envelope. No overlap/scheduling policy is implemented in host JavaScript. Without such a validator this adapter exposes native effects only, including overlapping intervals permitted by the underlying tool. No scheduling-validity claim is licensed. Receipts remain `verification:unverified`; changed/acknowledged is not evidence of request satisfaction. Shared request resolution, policy loading, assessment and reply composition are separate integration obligations. Undo is deliberately undeclared because this ephemeral native-tool bridge does not preserve its private undo history.

## Declared scheduling policy and proposal

`scheduling-policy.sop` declares a deny over distinct meetings sharing a resource and intersecting half-open intervals (`a.start < b.end` and `b.start < a.end`). Resource keys retain person/room identity classes. `createCalendarPolicy({source})` projects resolved state into these facts and returns the actual library deny outcome. It is passed as the host's staged validator; the loader must supply the declared source. No JavaScript overlap predicate substitutes for it.

`proposeCalendarSlot` accepts a complete native meeting and explicit Unix-millisecond `[notBefore,notAfter]` window. It tests the lower bound and sorted existing meeting-end boundaries through that same policy. For the declared non-overlap policy these are sufficient earliest feasible boundaries: a blocked interval cannot become free before an existing interval ends. It retains duration, participants, room and title; it performs no search for unspecified people or rooms. Candidate count and projected resources are bounded. Proposal is read-only and remains unverified. A day/time/timezone parser must resolve the window before calling it; textual dates are refused, never treated as local or UTC by default. More policy kinds may require a different declared candidate generator; this boundary enumerator makes no completeness claim for arbitrary replacement policies.
