# Detached C1 candidate execution evidence

`measureCandidateExecution` in `scripts/lib/candidate-execution-measurement.mjs` consumes plain JSON native state, a detached candidate, source text, explicit native view, caller identity and an optional opaque expectation. It validates/copies input with the existing native host data boundary before invoking the actual imported `executeRequestCandidate` on a fresh minimal session and a new invocation. It is not imported by the application or model router and supplies no public admission bypass.

The record retains copied before/after state, native reply, receipt, typed journal, exceptions and an original-state-unchanged check. The after snapshot is attempted even when the executor throws. Invalid input refuses before invocation; capture failure or original-state inequality invalidates the record. Supported, unsupported, no-op and changed outcomes do not become correctness labels: `intent.correct` is always null and C1 admission is always false. The expectation is data only, never an execution callback. A future independent evaluator can consume this record together with reviewed teacher evidence without changing the normal application route.

Isolation means the known executor receives only a fresh plain native-state clone and empty journal. It does not prove arbitrary JavaScript side effects are sandboxed; no arbitrary executor/plugin callback is accepted. Repeated measurements start fresh, not from prior measured effects. This current executor implements its actual narrow property path; other valid classes/areas may refuse. No effect or coverage is simulated for them.

`measureCandidateExecutionNode` observes the static local import source closure rooted at `src/dialog/new-engine.mjs`, hashes file bytes and records Node/platform/architecture before and after execution. Source changes invalidate the record. This is observed filesystem evidence, not attestation of an already loaded module's bytes, dynamic imports, browser backend equivalence or a complete deployment identity. Caller-declared model identity stays separate. A future actual browser C1 host can use the dependency-free collector with a separately verified browser executor identity; this Node wrapper is never packaged into C2.

Input/after copies each have independent maxBytes/maxNodes limits (defaults4MB/100k nodes, existing depth48); these are not a total execution or heap budget. Source observation separately caps256 files/16MB. The actual executor retains its own guards. Native reply snapshots preserve structured-clone values including optional undefined fields; a later JSON report may omit those optional fields and must not treat absence as a resolved semantic value. This is a synchronous fixture/evidence API, not a full calibration runner.

Probes use synthetic structured graph fixtures with the actual imported native executor: changed state/typed claim in the clone, independent repeated invocations, unsupported area/graph, ambiguous target, unsafe descriptor and byte-limit refusal, and stable observed source identity. These tests do not invoke a trained reader, calibrate confidence or label any real utterance correct.
