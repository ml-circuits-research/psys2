# Demo application controls

Owner scope, 2026-11-17: the visible areas are Drawing, Diagram, Calendar, Documents and Avatar (permanent last tab). Charts are vector objects in the Diagram instance, not a separate tab. Its owning chart declarations remain reusable tools. Existing chart state migrates into diagram.sketch.chartTools.

Calendar exposes one event agenda, day/week navigation and docked event properties (title, start/end and notes). The UI has no room or calendar administration. The first event atomically initializes the single default calendar when necessary. Editing an existing event preserves its existing resource associations without exposing legacy resource management. Times use browser-local display and explicit Unix milliseconds. Native scheduling policy still rejects overlapping resource reservations and accepts adjacent events.

UI gestures call declared native operations through the engine worker. They do not turn button labels into sentences for the neural reader to rediscover. The same declared native host and policy serve recognized text requests. Changes enter the shared conditional undo journal. Local demo work is persisted in browser storage and restored before rendering. A stale tab or undeclared operation does not mutate another world's state.

The earlier resource UI was validated by scripts/smoke-demo-areas.mjs; the active single-calendar/chapter interface is validated by scripts/smoke-single-calendar-chapters.mjs. The earlier browser run covered: legacy resource creation, personal event, overlap refusal, adjacent room-only booking, edit/undo, chart creation as SVG in Diagram, shared node/chart state and persistence across reload. This validation does not claim arbitrary text interpretation works; reader accuracy is measured separately.

Desktop editors fill their available pane. Auxiliary controls occupy docked sidebars: Drawing catalog and object/part properties, Diagram groups and chart data, Calendar agenda/event forms, Document block properties, and Avatar slots/variants/colour/size. Routine edits do not open modal dialogs. Scene selection, dragging, keyboard movement and direct text editing call declared typed controls. Avatar work is persisted alongside the other four instances.

Each declared UI control emits readable text and visible `app.control.intent` SOP wires into chat. The exact typed interpreter decodes those wires before invoking the tool. Browser-local training pairs retain expected arguments, actual before/after observations, receipt and effect verification; the header export downloads JSONL. This expected UI intent is distinct from the neural reader output, whose request wires are also shown for text turns.

The desktop conversation pane defaults to a wider 35% column (380–600 px). Its visible separator grip supports pointer dragging and keyboard arrows (Shift for larger steps, Home/End for bounds), persists the chosen width, and resets on double-click. Tool space keeps at least 300 px. SOP intent/reading code wraps and expands to its full height; only the outer conversation scrolls vertically.

A single dice button lives beside chat input and acts only on the current tab, including when the phone shows chat. It samples declared typed control candidates from actual capabilities and observations, validates a changing result on a cloned native host, and executes the candidate through the same SOP intent/capture door as editor controls. It does not claim neural interpretation accuracy. There are no per-editor dice buttons, cross-tab jumps, clears or random document overwrites.

Calendar event selection and Avatar part selection are declared native controls (`calendar.event.select`, `avatar.part.select`), including pointer and keyboard activation. They emit the same visible typed intent pairs as edits and retain focus in instance state. Optional selected observation fields appear only when the stored projection owns its selection key, so earlier SOP archives still restore exactly without loosening semantic comparison.

Concrete UI control commands use one ordinary SOP wire whose type is the declared native operation; primitive arguments are attributes and primitive lists use repeated keys. The interpreter receives the exact operation declaration to preserve scalar/list types. Nested structures and explicit empty arrays retain the typed graph representation where a single repeated-key wire cannot express them. Source ranges, observed identity/version and effect evidence remain separate diagnostics. Chat offers separate text/SOP copies and collapsed SOP by default.

Each world has Active and Code views. Code displays the current validated full SOP archive verbatim, including the typed native projection/history, with instance ID, revision and schema metadata. The selected-object inspector exposes exact owned fact/descriptor/value wires and actual observation binding metadata. Observation versions are local to a native host; the persisted world revision is separately identified. This readonly view reveals the existing dual representation; it does not claim the native projection has already been eliminated.

Owner editor contract (2026-11-17): click/touch selects by default, Ctrl/Meta-click toggles multiple targets, and dragging empty canvas makes a marquee. Drawing Add and empty-canvas double-click open the same small basic-shape/knowledge-word chooser; Diagram Add Node opens its node chooser. Selection actions, including delete/group/ungroup, live in the right inspector. ObjectID is the readonly native identity; optional Label is painted on Drawing/Diagram content. Avatar exposes native IDs without a Label field. Temporary identification and persistent ID overlays are view controls. Exact geometric resize handles invoke declared native operations, retain relative geometry for multiselections and preserve undo.

Diagram connections have native select/change controls for labels, colour, width, line style, arrow direction and endpoints. Contextual group Layout replaces the top-level Fit command. Newly created numeric charts are primary groups of actual nodes (bar rectangles, line points/links, pie/doughnut sectors), with stable member IDs and layout properties; ungroup retains editable members and links. Legacy chart projections remain compatible and have an explicit data conversion action, with a single-series admission guard rather than silent data loss. Drawing groups expose explicit SOP member/in relations and preserve original child IDs; legacy grouped archives keep their prior observation contract until edited through new grouping.

The conditional undo comparison ignores only host-declared focus paths; selecting another object therefore does not invalidate content undo/redo. Actual undeclared content changes still block restoration. Training is deferred until owner validation of these editor contracts; annotation coverage is not neural accuracy or complete capability execution.
