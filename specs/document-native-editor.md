# Native Documents editor

The Documents tab edits the real `docs.editor` block model through declared typed tools. Keyboard, mouse, toolbar and inspector actions call the same native host as interpreted requests; the UI does not turn an action back into prose for a legacy parser. The application records the human command, expected typed intent and actual tool result separately.

The page fills its pane and includes a block inspector. Users can enter a title, add paragraphs/headings/quotes, double-click literal text to edit it, label blocks, set alignment, change plain block types and heading levels, drag blocks or reorder with Alt+Up/Down. Changes commit on blur or Ctrl+Enter; Escape discards an uncommitted text edit. List items and table cells are editable directly; whole lists and rectangular TSV tables use a docked inspector form. Content comes from the supplied literal fields, with no generated prose.

`document.title.change`, `document.block.change`, `document.section.change`, the selection/mark/alignment operations, full `document.block.reorder`, list/table creation and changes, and `document.container.change` declare their exact native arguments. Sections remain heading levels 1–2; ordinary headings use levels 3–6. Reorder requires a complete permutation of current block IDs and preserves identities. Invalid ranges, foreign IDs and nonrectangular tables refuse atomically.

Each real text container is observed as `docs.editor.text`, identified by `JSON.stringify([blockId, at])`. A paragraph has location `0`; list items use decimal indices; table cells use `row:column`. A literal cell edit targets that exact identity and can be compared with its exact observed text. Block observations also expose labels, kind, index, alignment, list/table content, marks and selection ranges. Section observations preserve their distinct source type.

Formatting uses the actual model's `addMark` and `cutMark`; text edits use `spliceText` so unchanged ranges retain existing marks. Ranges use UTF-16 offsets, matching browser textarea selection and the document model. Links accept HTTP(S), mailto or fragment destinations; highlights require six-digit hex colours. The toolbar applies bold, italic, underline, strike, code and highlight to a selected range. Aggregate formatting verification must remain unverified where parameter-to-observation correspondence is not explicitly declared; a changed receipt alone is not proof of every intended semantic effect.

Targeted validation: `node --test tests/document-declared-host.test.mjs tests/document-editing-declared-host.test.mjs`. The tests exercise literal edits, mark preservation, range validation, exact ordering, sections, list/task/table primitives, atomic refusals, undo and exact table-cell intent/effect verification. Browser layout and interaction validation belongs to the integrated application run.

The toolbar also adds chapters and subchapters through `document.section.make` at heading levels 1 and 2. The right inspector contains a real outline; navigation selects the existing section with its native tool. When a chapter is selected, a new subchapter inserts at the end of that chapter before the next level-1 heading. Optional `after` names an exact observed block identity; missing insertion references refuse atomically. Literal content and block identities remain unchanged during insertion. Browser smoke: `scripts/smoke-single-calendar-chapters.mjs`.
