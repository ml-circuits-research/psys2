# Native Documents editor

The Documents tab is a SOP area (`worlds/docs.editor/area.sop`, read by the generic `worlds/sop-area.mjs`). Its state is a `w.document` instance in its editor form (catalog `w.document`: a document with a `code`, `w.document.block` in order by `n`, `w.document.item` of list blocks, `w.document.cell` of table blocks, `w.document.mark` over characters of a block's, an item's or a cell's text), carried as `{sop, runtime:{view}}`; the view keys are the selected block and a selected character range (`selected`, `from`, `to`, `at`). The tab module only mounts the generic view (`docs/webchat/ui/sop-area-view.mjs`) as a scrolling page; there is no JavaScript branch per operation or block kind. Keyboard, inspector and interpreted requests call the same declared native operations, and the application records the human command, expected typed intent and actual tool result separately.

All 27 operations of `worlds/docs.editor/native-interface.sop` are compiled by `worlds/docs.editor/act-rules.sop` into `std.acts` calls (make, change, remove) on the instance, view changes or an explicit `app.act.refuse`; `worlds/sop-world-host.mjs` only runs them. A command changes the instance in place: a title, text, kind, level, alignment, list or table change updates or removes the existing things and never adds a second copy; a list or table change keeps the item or cell at each place, makes the new places and removes the places beyond. Blocks are addressed by their code (`b1`), the document by its code (`text1`; a first state holds one empty document so a block can be added at once). Sections are headings of level 1 (chapters) and 2; ordinary headings use levels 3–6, and a block made a heading without a level becomes level 2. A section is removed with what follows it up to the next heading of its level or above, and reordered with the blocks of its group; blocks before the first section stay first. Reorders require a complete permutation of current identities. `document.write` replaces the document (the old one, with all it holds, goes; the new one gets the next `text<k>` code). `document.compose` and `document.rewrite` are refused (`missing-knowledge-composer`, `missing-knowledge-rewriter`): free text needs a composer or a rewriter the area does not have, and no language model runs here. `document.observe`, `document.undo` and `document.redo` compile to no call: observation is derived and history belongs to the application's journal.

Each text container is observed as `docs.editor.text`, identified by `JSON.stringify([blockId, at])`: a paragraph's, heading's or quote's own text has location `0`, list items use decimal indices (kind `item`), table cells use `row:column` (kind `cell`), each under its block (`in`, `role`). Blocks are observed under their section (a section of level 2 under its chapter), the rest under the document, with their kind (`section` for a heading of level 1 or 2), form, index, alignment, text, name, level, list style, table header, selection and range. Marks are observed under their block with their form, range, location, link or colour. The document is observed with its title, genre, topic and length in words (counted on the wrapped lines).

Formatting joins marks of the same form that touch the range and say the same (the same link, the same colour) into one; a highlight or link that says something else is cut back out of the range; turning a format off cuts the range out of the marks of that form, and what lies outside keeps its link or colour. A text change finds the common prefix and suffix of the old and new texts (digit by digit with regular expressions; sopworld has no text-length function): a mark before the change stays, after it moves by the change in length, over it grows or shrinks, overlapping it is cut at its edge, inside it goes. A list or table change keeps an item's or cell's marks within its new text. Ranges are character offsets checked against the text (`invalid-text-range`); links accept HTTP(S), mailto or fragment destinations; highlights require six-digit hex colours. A block selection (from = to = 0) is taken for any block, a table included.

`worlds/docs.editor/render-projection.sop` sets the page: the title, headings by level, paragraphs and quotes wrapped at spaces into lines of the 704-unit column (a cut word when longer than a line), list markers (bullet, number, task box), table cells by row and column with a shaded header, and each line cut where a mark starts or ends so a mark is drawn as a style (bold, italic, a link's colour and underline, strike, code and highlight backgrounds). The face is monospaced and each segment is set to its exact width, so a mark's place is exact. The page grows with what is on it (`app.observe.frame`). The inspector's controls are declared in `area.sop` (`app.area.control`, `app.area.field`, and `app.area.arg` for the arguments a control always sends: a fixed value, an observed option such as the document code, a view key such as the selected range, or an empty list).

Validation: `node --test tests/document-sop-area-declared-host.test.mjs tests/document-persistence-declared-host.test.mjs` (every operation, the page, the inspector's declared arguments, work-file restore and journal undo). Browser check: the built webchat on the Documents tab, through the chat input and the inspector.
