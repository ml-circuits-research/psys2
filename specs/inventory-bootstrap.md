# Inventory-conditioned encoder bootstrap

The bootstrap trains one pretrained DistilBERT encoder with shared candidate-score and source-span heads against all generated Haiku v1/v2 input files and the reviewed key/concept inventory. It retains source IDs, request index, constraint path and selector/result phase. It does not infer those identities: they are provided as conditioning. Scalar field instances emit a positive candidate and at most two deterministic negatives. Labels preserve unknown/non-scalar diagnostics; no generated source file is changed or deleted.

Preparation records source/inventory/mapping/output hashes and counts. A deterministic source-row calibration partition is not the final unseen evaluation. The shared model is not a graph decoder or executable reader. Its accuracy must be described as oracle-instance-conditioned candidate classification, never request or graph accuracy. Unique literal source spans provide auxiliary supervision; unmatched/ambiguous spans are counted and unsupervised, not guessed. Per-key calibration reports support, confusion counts, positive precision/recall and aligned span exactness from a frozen model/data hash. No threshold is tuned against final unseen data.

Checkpoints contain model weights only, not optimizer continuation state. Saves use an atomic replacement and check disk reserve; interrupted runs stay recorded. A small smoke or interrupted prefix is never reported as a full corpus run. Exact graph roundtrip, independently authored heldout evaluation and real execution remain separate deployment requirements.

The exact local package versions are pinned in `training/sop-bert/requirements-bootstrap.txt`; CUDA/platform details and the pretrained encoder's immutable revision and file hashes are recorded in each run. The repository's runtime dependency set is unchanged. Generated training pairs and model checkpoints stay local; the small provenance/summary files are published without presenting an unfinished checkpoint as a released reader.

## Owner-designated functional development split

The exact IDs in `training/eval/functional-matrix/exclude-from-training.json` must be excluded before field emission and candidate-bank construction. Preparation records the exclusion file hash, requested/found/missing IDs and source counts. Training refuses a prepared manifest without an exclusion hash. Published evaluation IDs are distinct from fresh final unseen evaluation. A changed exclusion set requires regenerated data and a restart from the clean pretrained encoder; previously exposed weights stay preserved but explicitly ineligible. Compressed deterministic JSONL output can be loaded into host memory for training to preserve disk space without dropping rows.
