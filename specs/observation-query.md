# Historical observation queries

`src/dialog/observation-query.mjs` aggregates internal jobs compiled from validated published request-query declarations. It does not parse English, mutate hosts or choose a target. Each job supplies its operation and a selected set of historical source identities, correlated to one exact instance/scope/version. The common target resolver is the trusted boundary for selector/name/reference meaning. This consumer checks identity correlation; it does not independently prove that the resolver interpreted a selector correctly.

`members` returns the selected object identities, not a traversal of an arbitrary membership property. `count` returns that population's cardinality. `exists` can return true with a witnessed selected member from a partial view; false requires a complete population and no unknown selector candidates. Complete member/count/value answers also require completeness and no unknown candidates. Unknown candidates never become mismatches or absent objects.

`values` reads one unambiguous declared concept/source-type binding per selected object, and one compatible historical input. Missing or empty inputs remain unknown. It returns exact native SOP tokens together with the full input descriptor (including dimension/unit/frame), selected identity, binding and frozen observation evidence. Declared dimension/unit/frame constraints must agree; no date, unit, colour or rendered-default conversion is inferred. This reports observed native input, not perceptual appearance or arbitrary domain truth.

Jobs and results are bounded, detached JSON; one traversal budget covers the batch. An invalid/unsupported job fails the batch without partial claims. There are no effects, receipt-based success declarations or generic action-target multiplicity defaults. Graph compilation, trusted target resolution and retained typed reply assessment are separate integration obligations. The initial aggregation core alone does not claim end-to-end question/check support; the shared query schema and reader must be published and integrated first. Check predicates remain separate from query projection.
