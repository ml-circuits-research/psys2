# Haiku v2 reader rows in the general request form (reviewer-generated, 2026-11-16)

17,995 validated English messages (drawing 5,198; diagram 5,200; document 3,799; calendar 3,799), written by 90 Claude Haiku batches from `INSTRUCTIONS-v2.md` against `inventory.json` (the per-(wire type, key) inventory, same as `../../heads/inventory.json`). Batches 01-08 per area targeted groups of keys (faces, parts, scenes, editing, selector vs result with every operator, logic, conversation turns and cross-area, questions and checks); later batches were generated from the measured coverage gaps. Every row passes `validate_v2.py` (exact spans, keys and closed values from the inventory, operator/phase/polarity/character on every constraint, relation needs an anchor, delta needs a step or measure, fragment needs a previous message). 3 duplicates dropped.

Each request is annotated in the general form: `mood`, `act`, `target` (type, mode new/existing/bound, fill, determiner, kind, name/description spans, ordinal, count, quantifier), `constraints` (one condition on one `<type>.<key>`, with value and value span, operator, phase selector/result, polarity, character, step, measure/unit, anchor span and fill, variety, scope, group and/or), `question` (ask and asked key), `turn` (fragment, objection, repeat count, target area). It maps directly to `std.request` and to the inventory heads.

Coverage, v1 and v2 together (`../../heads/gate.py`, `GATE-v1-v2.txt`, `COVERAGE-v1-v2.txt`): every one of the 134 keys has at least 100 examples; 64 of 72 concept heads pass the head gate (at least 300 examples per concept, every closed value at least 40, every key at least 100). The 8 that do not are listed in GATE-v1-v2.txt; each is short only by a few rare values or a total just under 300.

Known quality notes, from the batch reports: a few batches reuse one sentence frame too often; some calendar rows encode the relation anchor as a separate constraint; `day`/`time` open values mix normalised forms (`15:30`, `next friday`) and must be normalised by the resolver, not learned as classes; three batches were overwritten by a neighbour that read the wrong task line (the files on disk are complete and valid, but those three themes are mixed). Training and calibration only: the final unseen evaluation is an independently written set (Q112).
