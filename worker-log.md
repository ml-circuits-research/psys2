### Library improvements (for the library session, from docs.editor and docs.reader)
1. **Opaque values.** The engine's big immutable analysis (28 kB for a 685-word text, megabytes for a book) must sit in a wire so it is part of marks/rewind, but it is parsed, escaped twice and compared as a string. Idea: a slot `kind=blob` (value kept as given, compared by length+hash, never tokenized, excluded from rule matching). Minimal: `@doc.k core.slot of=docs.reader.open key=json kind=blob`.
2. **Bound variables in the refusal.** `check()` returns `why` with variables already replaced as text, so we post-process the string to turn "has 2" into "has two" and `?n` into "third". Idea: `violations[i].vars = { n: 3, c: 2, o: 'third' }` and filters in the template (`?c:words`, `?n:ordinal`).
3. **Aggregates without an anchor.** `core.calc fn=count over=$p` in a rule needs a separate `when=` wire or it fires once per match; and a count of an empty set has no wire unless an anchor exists. Idea: `core.aggregate over=$p count=?c default=0 then=...` that always yields one result. Minimal: five copies of the same rule today (one per block kind in docs.editor).
4. **Rank of an item.** "The 2nd chapter" is the position of a wire among the wires that match a pattern, ordered by a key. We compute it in JS (`sec`) and write it as an attribute. Idea: `core.rank of=$p by=n out=?r`.
5. **Transient wires.** The selection, the cursor and the focus are state the user looks at, not edits; "undo" must skip a step that changed only them. We do it in the host by comparing states (`isView`). Idea: a type flag `transient=true` (or `core.transient`) so `mark`/`rewind` groups are skipped by `undo` natively and a redo is a first-class operation (`world.redo()`; today `rewind` returns the function).
6. **Upsert.** `applyPatch.sets` changes a single value in place, but adding or removing a key means retract + tell under a new id (`x.r1`), and the host has to map ids back. Idea: `applyPatch({ replace: { id, attrs } })` keeping the id.
7. **String checks.** `core.check` has no `matches` / `startsWith` / `lower`; "a heading that says Chapter 3 is chapter 3" and "the section called Plans" had to stay in the guard's JS.
8. **A dry run with hypothetical facts.** `guard` asks `check({ wires })` with the question as a wire; for an instance that has no wires yet (the sample open at the start) we prepend the state's own wires to the text. Idea: `check({ wires, overlay })` or `world.ask(question)` that evaluates denies on the world plus the question without telling anything.
9. **Change cost.** About 0.2-0.7 ms per patch for a few hundred wires (the copy on the first write after a mark, then the rules' pass). Idea: a patch that only changes values no rule reads (the JSON of the focus) should skip the pass: per-slot `index=false` / `rules=false`.

### Library improvements (from games.chess and media.music; for the library session)
1. **Expression calcs and geometry builtins.** The test "is this piece strictly between those two squares" is 17 `core.calc` and 9 `core.check` wires per rule (a cross product, two min / max boxes, an `abs` distance). 2. **`replace` in a patch.** `applyPatch({ retract: ['chess.g'], wires: '@chess.g chess.game ...' })` is refused as `duplicate-id` (the wires are ingested before the retract), so a world that keeps a record in a wire invents revisions (`chess.g_1`, `music.p_2`). 6. **Undo by unit.** `undo=` rewinds a whole turn; the world's own undo took back one note. `rewind(mark, { only: 'music.note' })` or `core.undo unit=music.note` (the last wire of that type told in the turn).

9. **Enumerating candidates.** Legal move generation would be the rules over the 4096 pairs of squares (62 000 `chess.try` checks of 0.5 ms each, about 30 s: far too slow to generate on every turn, fine to verify). A generator (`core.each ?a in $square ?b in $square then $try`) or backward chaining at query time would let the engine ask the library "which moves are legal here" and a rule-built move list would carry its own reasons ("pinned", "blocked").

The effect events of a `music.play` are cloned twice (the action's result, then the host's queue): an `effects` field the library passes through untouched.
